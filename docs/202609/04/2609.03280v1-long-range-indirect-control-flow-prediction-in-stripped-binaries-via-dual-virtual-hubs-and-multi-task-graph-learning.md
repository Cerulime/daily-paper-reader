## 摘要
恢复间接控制流（ICF）边是二进制安全分析的基础，但现有方法难以处理长距离依赖，隔离了不同的ICF类型，并且常在易受标签噪声和数据泄漏影响的协议下进行评估。我们提出了ICFlowNet，一个用于剥离二进制中长距离ICF预测的统一框架。ICFlowNet引入了候选感知的双虚拟枢纽——全局代码枢纽和全局数据枢纽——以在远距离代码与数据证据之间创建短路由路径，并将其与多任务图学习相结合，以联合建模间接调用、间接尾部调用、跳转表和返回。为了实现可信的评估，我们进一步开发了一个泄漏感知、噪声受控的流水线，包括包级切分、函数级助记符哈希去重，以及由动态正例和绝对负例构建的干净测试协议。使用该流水线，我们构建了一个包含15,901个唯一剥离x86-64二进制的数据集，其中1,351个具有动态地面真值。实验表明，仅扩展静态监督仅带来边际收益，而我们的结构和多任务设计至关重要：双虚拟枢纽将长距离F1提升多达9.13个百分点，多任务学习额外增加多达5.81个百分点，最终模型在长距离间接调用上比先前基线高出超过13个F1点，同时仅增加11.44%的拓扑开销。

## Abstract
Recovering indirect control-flow (ICF) edges is fundamental to binary security analysis, yet existing methods struggle with long-range dependencies, isolate different ICF types, and are often evaluated under protocols vulnerable to label noise and data leakage. We present ICFlowNet, a unified framework for long-range ICF prediction in stripped binaries. ICFlowNet introduces candidate-aware Dual Virtual Hubs, a Global Code Hub and a Global Data Hub, to create short routing paths between distant code and data evidence, and combines them with multi-task graph learning to jointly model indirect calls, indirect tail calls, jump tables, and returns. To enable credible evaluation, we further develop a leakage-aware, noise-controlled pipeline with package-level splits, function-level mnemonic-hash deduplication, and a clean test protocol built from dynamic positives and absolute negatives. Using this pipeline, we construct a dataset of 15,901 unique stripped x86-64 binaries, including 1,351 with dynamic ground truth. Experiments show that simply scaling static supervision yields only marginal gains, whereas our structural and multi-task designs are essential: Dual Virtual Hubs improve long-range F1 by up to 9.13 points, multi-task learning adds up to 5.81 points, and the final model outperforms prior baselines by more than 13 F1 points on long-range indirect calls while adding only 11.44 percent topological overhead.

## 论文核心问题与整体含义（研究动机与背景）

剥离二进制（stripped binaries）中，恢复间接控制流（Indirect Control-Flow, ICF）边是二进制安全分析（如二进制重写、重编译、软件加固、差异分析等）的基础。ICF 转移包括：

- **间接调用（indirect calls）**
- **间接尾调用（indirect tail calls）**
- **跳转表（jump tables）**
- **返回（returns）**

现有方法存在三大核心痛点：

1. **长距离依赖问题**：决定 ICF 转移的关键证据（如代码—数据交叉引用 xRef）往往距真正执行转移的节点相距多个跳数，而标准消息传递 GNN 的有效感受野有限，存在过挤压（over-squashing）和瓶颈现象，导致远距离信息难以传播。
2. **任务割裂问题**：当前方案将不同类型 ICF 分别处理（Callee、AttnCall 只做间接调用；SJA 只做跳转表），忽略了跨类型结构关联（如返回依赖既有调用、尾调用兼具调用与跳转特征），导致监督信息利用不充分。
3. **评测协议缺陷**：现有数据集（如 Callee、CupidCall）依赖单一来源标签，存在过拟合或欠拟合偏差；训练与测试集之间存在严重的代码重叠与数据泄漏（如库里重复代码、静态链接等），导致性能被高估。

总结而言，论文试图回答的核心问题是：**如何在剥离二进制中统一、准确且可信地预测长距离依赖的所有 ICF 转移类型。**

## 论文提出的方法论

### 核心思想
论文提出 **ICFlowNet**，一个统一的多任务图学习框架，核心思路有两个关键洞察：

1. **候选感知的双虚拟枢纽（Candidate-Aware Dual Virtual Hubs）**
   - **Global Code Hub (GCH)**：作为代码侧候选节点的稀疏回退路由，连接与任务相关的代码候选（源候选与目标候选），提供短路径。
   - **Global Data Hub (GDH)**：仅聚合候选代码节点附近 2 跳内的数据节点证据（非整程序），过滤无关数据节点。
   - GCH 与 GDH 之间双向连接，实现代码侧与数据侧摘要的常量深度交互，从而缓解长距离依赖与代码—数据 xRef 缺失造成的断链问题。

2. **多任务图学习（Multi-Task Graph Learning）**
   - 用共享的异构图注意力网络（HGAT）作为编码器，配合任务特定的图头（task-specific GAT）与二元分类器，联合预测四种 ICF 类型（icall/itcall/jt/ret）。
   - 任务间通过共享表示相互促进，例如高频的 return 任务可以正则化低频的 tail-call 任务。
   - 额外加入辅助**边类型分类**头（只在正边上训练），强迫共享编码器区分语义相似但行为不同的控制流类型，提高表征的判别性。

### 关键技术细节

**（1）图构建与节点嵌入**

- 用 angr + symbolization 恢复基准 ACFG；保留直接跳转边作为显式边类型（供跳转表和返回推理）。
- 所有目标 ICF 边都排除在图外，仅作为监督信号，确保特征/标签分离。
- 代码节点用 PalmTree 嵌入初始化；数据节点用归一化地址+轻量结构特征；两个 hub 节点用可学习类型嵌入。

**（2）HGAT 编码与门控融合**

对每种关系类型 r、目标节点 v、层 l，多头注意力系数和关系特定聚合消息为：

```
α_u v^{(r,k)} = softmax(LeakyReLU(a_r^{(k)})^T [W_r^{(k)} h_u^{(l)} ∥ W_r^{(k)} h_v^{(l)}])
m_v^{(r,l)} = (1/K) Σ_{k=1..K} Σ_{u∈N_v^r} α_u v^{(r,k)} W_r^{(k)} h_u^{(l)}
```

普通节点的邻域被划分为本地关系（local）与枢纽关系（hub），分别聚合，通过可学习门控：

```
g_v^{(l)} = σ( w_{φ(v)}^T [ m_{v,loc}^{(l)} ∥ h_v^{(l)} ] + b_{φ(v)} )
h_v^{(l+1)} = f( LN_{φ(v)}( m_{v,loc}^{(l)} + α_{φ(v)} g_v^{(l)} m_{v,hub}^{(l)} + W_res_{φ(v)} h_v^{(l)} ) )
```

从而防止全局路由信号淹没强局部证据。

**（3）任务特定边打分**

对每个任务 τ 的候选对 (u,v)，拼接源与目标编码后送任务特定 MLP（GELU→线性→sigmoid），得到边存在概率，优化加权二元交叉熵。

**（4）多任务整体损失**

```
L_total = Σ_τ λ_τ L_BCE^τ + λ_type L_CE^type
```

其中 L_CE^type 是仅在正样本对上计算的辅助边类型分类损失。

### 评测管线（离线）

- **静态监督**：定制 LLVM 工具链（修改 Clang 与 LLVM 后端），利用 LLVM-CFI/Modular CFI 策略、X86 DAG 指令选择拦截、返回重建等方式收集编译器级 ICF pairs。
- **动态监督**：Intel Pin 工具追踪程序真实执行过程（含原生测试套件和 LLM 生成的增强测试），提供动态 ICF pairs。
- **Clean Test Protocol**：动态观察到的目标为正样本，负样本仅从绝对负例区域（静态候选集之外，占据 98.7% 的跨过程控制流空间）采样，避免对动态未观察到但静态合理的边进行误罚。

## 论文的主要结论与发现

1. **单纯扩大静态监督规模收益有限**：静态训练集扩大 10 倍，平均 F1 仅 +0.27%，表明监督质量比数据量更关键。
2. **双虚拟枢纽显著提升长距离 ICF F1**：对 Indirect Call +6.04、Indirect Tail Call +9.13、Return +5.04；跳转表任务（局部性极强）因全局路由注入噪声而轻微下降（−2.14），故最终采用任务感知结构——跨过程任务保留 hub 路由，跳转表目标保持本地。
3. **多任务学习进一步增益**：在长距离子集上，MTL 带来的提升为 ic +4.16、itc +5.81、ret +5.43 F1；跳转表接近饱和，但 MTL 不损害其表现。
4. **整体性能大幅超越 SOTA**：长距离间接调用上较 Callee 和 CupidCall 各提升超 13 个 F1 点（Callee 82.26、CupidCall 82.48 vs Ours 95.51）；长距离跳转表在 LLVM 19 新式编译产物上较 SJA 提升 3.67 F1。
5. **MTL 不仅有精度收益，还有 2.25× 训练与 2.41× 推理加速**；双虚拟枢纽的拓扑开销在统一 MTL 图上仅 +11.44%，并未线性叠加。
6. **无枢纽条件下 MTL 平均仅 +1.33% F1**，证明长距离依赖问题必须靠图结构修复（而非仅靠任务共享）解决。

## 优点

- **方法层面**：
  - 首次以统一多任务框架联合预测四类 ICF 转移（icall/itcall/jt/ret），打破单任务割裂局面；

  - 提出完整、严格的评测管线：包级划分 + 函数级去重 + clean test（动态正例 + 绝对负例），显著降低了数据泄漏和标签噪声对结论的干扰；
  - 在先前数据集上再评估原有模型，用数据说明泄漏问题的真实影响（94.6% → 90.92%），提高了领域评测可信度；
  - 数据集规模大（15,901 unique binaries，1,351 带动态真值），远超其动态资源（如 Callee）。

## 不足与局限

- **安全关键场景的部署限制**：论文明确自认为 ICFlowNet 更适用于候选裁剪、分析提速或辅助保守分析，而非需要严格 100% 召回保证的控制流完整性（CFI）等安全关键管线；这类任务中少量漏报即不可接受。
- **评测完整性受限**：
  - 对 TypeArmor、TypeSqueezer、BPA、SchedExec、Disa 等传统程序分析工具，仅进行外部/参照性对比（附錄 M），未能在同一数据协议下做严格复现级对比；
  - Callee 和 SJA 数据集只覆盖单一 ICF 类型，无法对所有四类都做标准基准对比。
- **训练资源与超参数敏感性**：论文未披露具体训练时长和总 GPU 小时消耗；高优化级别（O2/O3）下对 icall 敏感性稍高，跨运行的不确定性未详细分析。
- **对前端恢复质量的依赖缺陷仍未完全消除**：虽然避开了 angr 的间接跳转解析，但基础图恢复的正确性/完整性（如函数边界识别失败时的连边缺失）仍影响模型闭环效果。
- **超大规模二进制仍存在内存瓶颈**：尽管 hub 是稀疏连接的，但仍是全图式 GAT 方法，对超大型真实二进制图的内存占用未有详细压力测试，作者留作未来工作——候选中心图压缩。
- **数据代表性**：只在 Arch Linux 生态的 x86-64 二进制上训练，未对不同指令集（ARM/MIPS 等）、不同编译器（GCC）、不同 OS 二进制做跨域验证，泛化边界有待探索。
