## 摘要
固件模糊测试是发现嵌入式系统漏洞的有效技术。然而，现有的覆盖率引导固件模糊测试器通常通过固件插桩、硬件调试接口或固件重宿主来获取反馈，这需要访问固件源代码或二进制镜像。对于现成嵌入式设备而言，这些要求往往不可行，因为其固件二进制不可访问、无法重宿主、不可修改或无法调试，因此需要在黑盒条件下进行模糊测试。本文提出 POZZER，一种面向黑盒嵌入式系统的功耗侧信道引导模糊测试器。POZZER 使用功耗迹作为反馈，通过增量构建的基于图的已观测执行表示来识别此前未见的行为，引导模糊测试器走向未探索的执行路径。其非画像设计既不需要先验固件知识，也不需要克隆设备，每次执行仅从单条功耗迹中提取有意义的反馈，同时对测量噪声保持鲁棒。我们在两个平台和两个真实商用嵌入式设备上的 15 个固件目标上评估了 POZZER。在所得的目标-平台组合中，在相同时间预算下，POZZER 在 30 个目标-平台组合中的 26 个上优于盲模糊测试器。此外，POZZER 在其中一个商用设备中发现了两个此前未知的漏洞，且均得到厂商确认，展示了其在识别黑盒嵌入式系统漏洞方面的潜力。

## Abstract
Firmware fuzzing is an effective technique for discovering vulnerabilities in embedded systems. However, existing coverage-guided firmware fuzzers typically obtain feedback through firmware instrumentation, hardware debug interfaces, or firmware rehosting, which requires access to the firmware source code or binary image. Such requirements are often infeasible for off-the-shelf embedded devices, where firmware binaries are inaccessible, unrehostable, immodifiable, or undebuggable, necessitating fuzzing under black-box conditions.   In this paper, we present POZZER, a power side-channel-guided fuzzer for black-box embedded systems. POZZER uses power traces as feedback to identify previously unseen behavior via an incrementally constructed graph-based representation of observed executions, guiding the fuzzer toward unexplored execution paths. Its non-profiling design requires neither prior firmware knowledge nor a clone device, extracting meaningful feedback from a single power trace per execution while remaining robust to measurement noise. We evaluate POZZER on 15 firmware targets across two platforms and two real-world commercial embedded devices. Across the resulting target-platform combinations, POZZER outperforms a blind fuzzer under the same time budget in 26 out of 30 target-platform combinations. Furthermore, POZZER discovers two previously unknown vulnerabilities in one of the commercial devices, both confirmed by the vendor, demonstrating its potential for identifying vulnerabilities in black-box embedded systems.

## 1. 核心问题与研究动机

- **背景**：嵌入式系统广泛用于 IoT、工业自动化、汽车、医疗等安全关键场景，其固件漏洞后果严重；模糊测试是发现此类漏洞的有效手段，其中覆盖率引导模糊测试因能持续利用执行反馈引导输入生成而最为有效。
- **核心矛盾**：现有固件模糊测试器通过**固件插桩**、**硬件调试接口**或**固件重宿主（rehosting）**获取反馈，均需访问固件源码或二进制镜像。而现实中，现代嵌入式系统大量集成第三方模块（无线通信芯片、GNSS 接收机、安全元件、传感器控制器），其固件对系统集成商与终端用户不可见，调试接口常被禁用；许多设备只能在严格黑盒条件下通过暴露的通信接口测试。
- **后果**：黑盒条件下传统覆盖率引导模糊测试器无法获得执行反馈，只能退化为**盲模糊测试器（blind fuzzer）**，输入空间探索效率显著下降。因此，"如何获取执行反馈"成为黑盒固件模糊测试的根本挑战。
- **可能的出路**：物理侧信道无需插桩、无需固件二进制或源码即可泄露执行信息；功耗侧信道（PSC）可泄露已执行指令与处理数据的信息，是有前景的反馈来源。
- **难点**：将原始 PSC 迹转化为实用的在线模糊测试反馈非常困难——测量噪声、时间对齐、执行相关信号变化使"执行差异"与"测量伪影"难以区分。此前侧信道引导模糊测试器依赖真值数据训练模型（画像/Profiling）、重复执行（如 DuskFuzz 每个测试用例需 5 次执行）或不现实的威胁模型。
- **整体含义**：POZZER 是**首个在相同时间预算下持续优于盲模糊测试的 PSC 引导黑盒模糊测试器**，在严格黑盒威胁模型下实现了可用的执行反馈。

## 2. 方法论

### 2.1 威胁模型（软硬件两层面）
- **软件**：严格黑盒。无源码、无二进制；仅能通过暴露的通信接口交互并观察响应；无法获得代码覆盖率反馈。
- **硬件**：调试接口不可访问，无法获得指令迹或调试信息；但攻击者拥有物理接触，可在目标供电回路上加装**分流电阻**被动监测 PSC 迹，并知道暴露接口引脚以发送测试输入。
- **非画像约束**：不需要克隆设备、训练数据或泄露模型，仅从模糊测试过程中采集的目标自身功耗迹提取反馈。

### 2.2 核心思想
- **直觉**：PSC 迹之间的差异（discrepancy）暗示固件控制流的差异。
- **机制**：增量构建**伪执行流图（pseudo execution-flow graph）**，作为全局参照，判断新采集的迹是否包含此前未见的行为；若有，则将对应测试用例加入语料库。
- 沿用并大幅改进 EDG（Execution Divergence Graph）概念：节点表示执行迹、边表示转移，从初始节点起存储已观测执行前缀；新执行若不匹配任何已有路径前缀，则分裂节点或加边。

### 2.3 相似性度量
- 使用 **L1 距离**逐点比较 PSC 迹；距离超过阈值即判定为**差异点（discrepancy point）**。L1 计算廉价，适合在线高频比较。

### 2.4 硬件噪声处理（三类关键技术）
- **分块差异检测（Chunk-based）**：以固定大小块（连续样本序列）而非单样本比较，归一化 L1 距离为 `D_L1(X,Y) = (1/|CS|) Σ|xi − yi|`，超阈值则判定该块差异。降低对局部幅度偏移的敏感性，并把比较降到"指令序列"粒度。
- **一阶导数比较**：定位差异块后，在块内做逐点比较以确定精确差异点；比较在**一阶导数域**进行。数学上 `x[n]=s[n]+o[n]`，`Δx[n]=Δs[n]+Δo[n]`，对常数 DC 偏移 `Δo=0`，对缓变偏移 `Δo≈0`，故导数可抑制局部幅度偏移而保留信号变化（附录 A 给出证明，图 3 示意）。
- **时间偏移感知的邻居搜索**：逐点比较时，将样本与另一条迹中的对齐样本及**预定义窗口内的邻居样本**比较（图 4 示例用两侧各 2 个样本的邻域），容忍小的时间错位，减少伪差异点。

### 2.5 图的构建与维护（三阶段）
- **签名搜索（Signature-based search）**：签名是取自每个图分支起始处的固定长度片段，代表该分支入口。由于执行路径会汇聚、同一代码段可在不同时间位置出现，新迹可能偏离当前路径后重新汇入已观测路径。POZZER 从根开始比较至首个差异点，随后**在整个图的全局签名池中搜索**，而非只查当前差异点的后代；匹配后从对应图位置恢复比较。此举既避免不必要的图扩张，又因签名远小于完整迹而提升比较效率（图 6a）。
- **迹插入（Trace insertion）**：四类情形
  - **新差异点**：匹配已有节点签名但在无边处出现差异 → 创建节点与边，测试用例判为 interesting。
  - **新分支**：从差异点起不匹配任何已有签名 → 从该差异点新建分支，判为 interesting。
  - **新路径**：迹由图中已有片段以未见顺序连接而成 → 添加新边，保留测试输入。
  - **完全匹配**：迹是已有路径的前缀 → 丢弃该输入，不改图。
- **图裁剪（Graph trimming）**：当汇聚段起点不是已有差异点时，插入会产生冗余图结构；插入后识别并合并冗余执行段，减小图规模并保留路径；仅在图被修改时执行，避免额外开销。

### 2.6 实现与标定
- 原型构建于 **LibAFL** 之上；架构含模糊测试引擎、目标接口、采集设备、观察者（Observer）与反馈模块（图 5）。每轮：变异生成测试用例 → 经目标 API 下发并同步采集 PSC 迹 → 反馈模块做签名搜索、必要时插入与裁剪 → 报告是否发现新行为。
- **一次性标定（不违反黑盒模型，无需真值）**：需确定 chunk size、chunk threshold、signature size、signature threshold、time-shift window size、point-wise discrepancy threshold、minimum node size 等参数。
  - 尺寸类参数由采样率与目标 MCU 时钟决定；阈值类参数依赖目标与测量装置电气特性。
  - 标定流程：生成 M=100 个随机测试用例，每个重复执行并采集 N=100 条迹；假设噪声逐样本服从高斯分布，计算样本协方差矩阵 `Σm`，取每用例最大方差 `σ²m = max(diag(Σm))`，再对全部用例求平均得 `σ̄²`；阈值取约 **4σ̄**（对应噪声低于阈值的概率上界 0.9999）。
  - **minimum node size** 规定相邻差异点最小时间间隔，抑制分块比较中由微小错位引入的伪差异点与冗余节点。
  - 标定完成后参数在整个测试活动中固定。
