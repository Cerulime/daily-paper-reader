## 摘要
自动化内核漏洞复现对于缺陷分诊、补丁验证和回归测试至关重要，但仍缺乏有效且高效的解决方案。核心挑战有两点：复现器必须首先恢复到达易受攻击状态所需的触发骨架，并确定真正触发缺陷的精确具体值。现有的定向模糊测试方法在恢复必要触发骨架方面效果不佳，而仅依赖 LLM 的生成则较为脆弱，因为其难以处理具体值发现和运行时非确定性。我们设计了 SyzHarness，一个结合 LLM 推理与覆盖率引导模糊测试的框架，用于基于补丁的 Linux 内核漏洞复现。给定一个补丁，SyzHarness 使用由代码导航工具支撑的 LLM 智能体来合成参数化模糊测试驱动，该驱动固定先决条件设置逻辑，同时仅暴露不确定且对缺陷关键的输入参数，供 Syzkaller 变异。随后，SyzHarness 将该驱动转换为与 Syzkaller 兼容的接口，并利用分层可达性反馈对其进行迭代优化。我们在多个可触发真实世界 Linux 内核漏洞数据集上评估 SyzHarness。在 100 个 KernelCTF 案例上，SyzHarness 达到 78% 的缺陷复现成功率。在 SyzDirect 基准上，SyzHarness 达到 73% 的缺陷复现成功率，显著优于先前的定向灰盒模糊测试。在 50 个近期（2026 年 3 月之后修复）已知可触发的 syzbot 缺陷上，SyzHarness 仅以修复提交作为输入，复现了 40/50（80%）。

## Abstract
Automated kernel vulnerability reproduction is essential for bug triage, patch validation, and regression testing, but   still lacks an effective and efficient solution. The core challenge is twofold: a reproducer must first recover the   trigger scaffold needed to reach the vulnerable state and determine the precise concrete values that actually trigger   the bug. Existing directed fuzzing approaches are ineffective at recovering the necessary trigger scaffold, while LLM-   only generation is brittle because it struggles with concrete-value discovery and runtime nondeterminism. We design   SyzHarness, a framework that combines LLM reasoning with coverage-guided fuzzing for patch-based Linux kernel   vulnerability reproduction. Given a patch, SyzHarness uses an LLM agent grounded by code navigation tools to   synthesize a parameterized fuzzing harness that fixes the prerequisite setup logic while exposing only uncertain, bug-   critical input parameters to be mutated by Syzkaller. SyzHarness then translates this harness into a Syzkaller-   compatible interface and iteratively refines it using hierarchical reachability feedback. We evaluate SyzHarness on   multiple datasets of triggerable real-world Linux kernel vulnerabilities. On 100 KernelCTF cases, SyzHarness achieves   a 78% bug reproduction success rate. On the SyzDirect benchmark, SyzHarness achieves a 73% bug reproduction success   rate, substantially outperforming prior directed greybox fuzzing. On 50 recent, known-triggerable syzbot bugs fixed   after March 2026, SyzHarness reproduces 40/50 (80%) using only the fix commits as input.

## 一、核心问题与研究动机

- **研究背景**：Linux 内核是现代计算基础设施的核心，漏洞复现（reproduction）是缺陷分诊、影响评估和补丁验证的基础能力。然而现实中复现工作往往**从安全补丁出发而非从崩溃报告或 PoC 出发**——Linux 内核补丁并不强制附带公开 PoC（如 kernelCTF 允许延迟至 90 天内公开），上游维护者与下游厂商常在无可用复现器时就需要验证修复或回移植。
- **核心挑战（二元问题）**：
  - **触发脚手架（trigger scaffold）恢复**：需要确定到达脆弱状态所需的系统调用序列、协议步骤、对象关系与状态转换。
  - **精确具体值（concrete values）发现**：需要找到真正触发缺陷的参数值、边界条件、时序敏感交错等运行时效应。
  - 补丁通常只暴露脆弱区域，却几乎不揭示上述隐藏前提与触发条件。
- **现有方法的两难**：
  - **定向灰盒模糊测试（DGF，如 SyzDirect）**：仅引导执行靠近补丁点，但“距离 ≠ 可达性 ≠ 可触发性”，遇到 `if(state == READY)` 这类状态机守卫时退化为无引导搜索（即内核模糊测试中著名的“依赖挑战”）。
  - **纯 LLM 生成**：擅长推断高层触发逻辑（如定位关键字段），但难以给出稀疏、极端的精确具体值（例：SCSI 案例中 LLM 选 `cmd_len=5`，实际触发需 `cmd_len=0`），且无法应对运行时非确定性。
- **核心洞察**：LLM 与模糊测试天然互补——LLM 恢复触发脚手架，模糊测试负责具体值与运行时不确定性搜索；关键在于**如何在不损失二者优势的前提下融合**。

## 二、方法论：SyzHarness 设计与实现

### 核心思想
将搜索从“无约束的系统调用程序探索”转化为“**约束化、语义有效的子空间探索**”：LLM 合成一个**参数化 fuzzing harness**，固定前置设置逻辑与系统调用序列，仅把不确定的、对缺陷关键的输入参数（大小、标志、缓冲区内容、字段选择等）暴露给 Syzkaller 变异。

### 三阶段流水线

- **阶段一：从原始补丁合成 harness（LLM 智能体）**
  - 智能体配备**代码导航工具**：符号定义查找、引用追踪、文本模式搜索、按文件/行范围定向源码检索。
  - 采用**“假设—验证—生成”（Hypothesize–Verify–Generate）**严格工作流：先从 commit message 与 diff 推导候选触发前提；再查询代码库确认/反驳；最后在源码上下文落地后才生成 harness 逻辑。
  - **外部知识检索**：对复杂/低频子系统设置（io_uring 初始化、文件系统挂载、非常规设备节点等），检索并复用 Syzkaller 现有伪系统调用（pseudo-syscall）作为范例，或直接复用其逻辑、或挖掘其顺序与参数约束。
  - **显式参数暴露**：harness 包含环境设置（namespace、模块加载、设备发现）、依赖构造（内核对象/资源初始化）、序列定义（系统调用顺序）；**仅将不确定的 bug 关键旋钮暴露为 entry() 参数**。
  - **编译验证**：在目标（或忠实重建的）内核构建环境中自动编译，提前捕获头文件缺失、类型错误、API 误用等幻觉问题。

- **阶段二：桥接到 Syzkaller**
  - **系统调用描述合成**：与 harness 生成在**同一智能体会话**中完成，保证参数语义与类型决策一致；接口刻意简化为纯标量参数（整数、标志、字节数组），嵌套结构在 harness 内部构造；优先复用 Syzkaller 已有类型定义。
  - **伪系统调用转换（确定性重写）**：函数签名适配为 `static long syz_<name>(volatile long a0, ...)`；插入显式类型转换；用 `#if SYZ_EXECUTOR || defined(__NR_syz_name)` 等预处理守卫包裹。
  - **编译修复智能体**：仅在集成构建失败时调用，输入编译器日志与注入代码的精确行范围；**权限严格受限**——只能编辑新注入的伪系统调用与描述块，禁止改动 Syzkaller 既有代码；最多 5 轮修复。

- **阶段三：分层可达性反馈迭代精炼**
  - **隔离模糊测试配置**：仅启用新造的伪系统调用，防止 fuzzer 漂移到无关子系统，使覆盖率变化可归因于 harness 本身。
  - **分层可达性信号**：
    - `T_file`：补丁源文件是否被执行（失败 → 修驱动/设备初始化）
    - `T_func`：补丁函数是否被执行（失败 → 精炼命令码/标志）
    - `T_line`：补丁修改/删除的具体行是否被执行（失败 → 调整细微状态约束）
  - **自适应时间预算与早停**：迭代超时单调递增（如 1h、2h、4h、6h、8h），总预算约 24 小时；若某 harness 在分配预算的前 30% 内仍无法达到 `T_file`，立即终止并触发 harness 修订（实证依据：可行 harness 通常 10 分钟内即可达成最大覆盖）。
  - 每次迭代保留前序上下文以支持单调改进，系统调用描述与接口变更同步更新。

### 实现细节
- 基于 **Model Context Protocol (MCP)** 实现两个智能体（生成智能体、修复智能体）；通过 Codex CLI 驱动，固定系统提示 `AGENTS.md` + 任务特定用户提示；纯语法/确定性编辑用脚本完成，需要语义感知的转换（尤其显式类型转换）由生成智能体负责。

## 六、主要结论与发现

- **有效性**：KernelCTF 上 **78%（78/100）**；SyzDirect 基准上 **73%**，显著优于 SyzDirect 的 **25%**（受控重跑）；近期 syzbot 上 **80%（40/50）**，仅以修复提交为输入。
- **效率**：KernelCTF 成功案例平均 TTR **2.9h**，中位 **1.2h**；首次迭代成功率 **47.5%**；83.34% 的成功案例在**前两轮迭代**内复现，存在明显的长尾（后三轮仅占 18.5%）。
- **缺陷类型差异**：UAF 与 OOB 成功率相近（79.0% vs 82.4%），但效率差异显著——OOB 首轮成功率 71.4%，UAF 仅 43.8%；UAF 平均 TTR 3.1h vs OOB 1.9h。
- **竞态缺陷**：24 个竞态案例复现 19 个（79.2%），与 76 个非竞态案例（77.6%）成功率相当，但时序敏感会增加复现延迟。
- **消融结论**：
  - LLM-only 达 65% vs SyzHarness 78.3%，证明“LLM 定位字段 + 模糊测试搜索具体值”的分工有效。
  - 分层反馈主要提升**效率**而非最终有效性：完整配置 47/60 vs 5 次无反馈 46/60，但前者在 1h/2h/4h 预算内复现更多目标（34 vs 30、41 vs 38、48 vs 42）。
- **稳定性**：5 次独立运行成功率 78.3%–86.7%，均值 82.0%；60 个目标中 43 个五次全中、48 个至少四次成功、54 个至少一次成功——随机性集中于少量边缘目标。
- **无标签补丁**：64 例中复现 29 例（45.3%）；抽样 10 个失败案例中 8 个因缺少必要内核配置（如 `CONFIG_MT7925E`、`CONFIG_DRM_AMDGPU`）而实际不可触发。
- **失败模式**（20 例中）：**脚手架错误 14 例**（最主要，到达正确文件/函数但未满足触发条件）、竞态/时序窗口未命中 4 例、脚手架细节问题 2 例（顺序或参数不一致）。
- **成本结论**：LLM 开销相对整体流水线适中，主导墙钟时间的是 Syzkaller 模糊测试（无额外 API 成本），使设计在大规模补丁复现中具备实用性。

## 七、优点

- **问题分解清晰**：将复现明确拆为“触发脚手架恢复”与“具体值发现”两个层次，并论证了模糊测试与 LLM 的互补性失败模式，为混合设计提供原则性依据。
- **表示鸿沟的巧妙桥接**：用“参数化 harness”而非直接生成 seed 程序，避免了覆盖率引导变异漂移到无关系统调用；同时以伪系统调用形式嵌入 Syzkaller 原生执行模型，兼顾结构约束与高吞吐变异。
- **工程落地完整**：从补丁解析、代码导航、外部知识检索、编译验证、确定性转换、受限编译修复到迭代精炼，形成端到端可自动化流水线；修复智能体的权限严格限制保护了 Syzkaller 本体完整性。
- **分层可达性反馈设计精巧**：file→function→line 三级信号与具体修复动作一一对应，且配合自适应预算与早停策略，将反馈定位为效率机制而非有效性机制，论断克制诚实
