## 摘要
大型语言模型（LLM）广泛部署在云托管的推理服务中，其中使用即时（JIT）编译来减少重复的框架和GPU启动开销。JIT服务引入了一个主机端控制平面，用于选择编译后的工件并协调其在GPU上的执行。同时，共享云环境推动了针对LLM/DNN推理的越来越多的位翻转攻击（BFA）。现有的大多数BFA针对模型参数或权重，并且需要特定于模型的知识。少量工作通过破坏可执行代码来降低这种依赖，但仍然破坏直接实现模型计算的代码，将其攻击效果限制为推理耗尽。我们提出了JITterFlip，这是第一个针对基于GPU的LLM推理的主机端JIT服务控制平面的BFA。通过破坏CPU驻留的服务决策而不是模型计算，JITterFlip能够实现乱码输出生成和正确输出的海绵攻击。为了在大型JIT编译器堆栈中识别可利用的目标，JITterFlip开发了一种决策引导的故障易受攻击代码分析。在四个文本和多模态LLM工作负载中，识别出的易受攻击代码故障表现出跨模型的可迁移性，产生PPL比率为$15.45\times$至$2.48{\times}10^{6}\times$的乱码输出，并展示了延迟放大为$2.03\times$至$181.90\times$的正确输出海绵攻击。JITterFlip还绕过了最近的LLM BFA防御，同时保持两种攻击效果。最后，我们展示了跨越四个LLM的端到端Rowhammer攻击：CPU驻留分支代码中的单个位翻转跨CPU-GPU边界传播，破坏GPU执行的推理，而无需直接访问GPU内存，达到高达$7.23{\times}10^{6}\times$的PPL放大或$124.97\times$的延迟放大，同时保持精确生成的输出。

## Abstract
LLMs are widely deployed through cloud-hosted inference services, where Just-in-Time (JIT) compilation is used to reduce recurring framework and GPU-launch overhead. JIT serving introduces a host-side control plane that selects compiled artifacts and orchestrates their execution on the GPU. Meanwhile, the shared cloud setting has motivated a growing body of bit-flip attacks (BFAs) against LLM/DNN inference. Most existing BFAs target model parameters or weights and require model-specific knowledge. A smaller body of work reduces this dependency by faulting executable code, yet still corrupts code that directly implements model computation, limiting their attack effect to inference depletion.   We present JITterFlip, the first BFA targeting the host-side JIT serving control plane of GPU-based LLM inference. By faulting CPU-resident serving decisions rather than model computation, JITterFlip enables both gibberish output generation and a correct-output sponge attack. To identify exploitable targets in a large JIT compiler stack, JITterFlip develops a decision-guided fault-vulnerable code analysis.   Across four text and multimodal LLM workloads, the identified vulnerable code faults exhibit cross-model transferability, produce gibberish outputs with PPL ratios of $15.45\times$ to $2.48{\times}10^{6}\times$, and demonstrate correct-output sponge attacks with latency amplification of $2.03\times$ to $181.90\times$. JITterFlip also bypasses recent BFA defenses for LLMs while retaining both attack effects. Last, we demonstrate end-to-end Rowhammer attacks across four LLMs: a single bit flip in CPU-resident branch code propagates across the CPU-GPU boundary to disrupt GPU-executed inference without direct access to GPU memory, reaching up to $7.23{\times}10^{6}\times$ PPL amplification or $124.97\times$ latency amplification while preserving the exact generated output.

## 1. 论文的核心问题与整体含义

**研究动机：**
- 大型语言模型（LLM）广泛以云服务形式部署，推理过程中为减少重复框架与 GPU 启动开销，普遍采用即时编译（JIT），例如 PyTorch `torch.compile`、vLLM V1 的组合（Dynamo/Inductor/Triton/CUDA Graph）。
- JIT 编译为 LLM 推理引入了 **host-side 控制平面**：由 CPU 侧代码决定选择哪个已编译工件、是否复用缓存、如何向 GPU 提交计算等。
- 现有位翻转攻击（BFA）主要分两类：
  - 针对模型参数/权重（需模型结构知识，攻击效果大多为“推理耗尽”，可被输出级防御检测）；
  - 针对可执行代码（如 FrameFlip 攻击 OpenBLAS、Compiled Models 攻击 DL 编译器生成的模型代码），但仍属于 **模型计算平面**，只能破坏计算本身，无法实现“保持正确输出的拖慢攻击”。
- 本文首次将 BFA 目标移到 **JIT 服务控制平面**，通过翻转 CPU 驻留的分支代码来改变服务决策，既能产生乱码输出，也能实现 **正确输出海绵攻击（sponge attack）**，即输出完全不变但延迟大幅上升。

**整体含义：**
JITterFlip 揭示了现代 JIT 编译 LLM 服务中一个全新的攻击面——服务控制逻辑而非模型计算。单比特翻转可从 CPU DRAM 跨 CPU–GPU 边界影响 GPU 上的推理执行，且无需任何受害者模型知识，能绕过现有主要针对权重或输出语义的防御。

## 2. 论文提出的方法论

**核心思想：**
- 将攻击目标从“模型计算”转移为“JIT 服务决策”；
- 利用单比特翻转修改 CPU 侧条件分支（如 `jle` ↔ `jg`），使执行流向语义合法但代价更高的路径，或抑制 GPU 计算提交，从而产生乱码或延迟放大。

**关键技术与流程：**

1. **执行关键决策定位（Decision-Relevant Source Localization）**
   - 通过差分源码分析，对比 eager execution 与 JIT 编译路径，识别 JIT 特有的 host 侧控制阶段。
   - 两个决策族：
     - **编译工件选择**：包括 Dynamo 帧分发、守卫评估、编译缓存查找；
     - **GPU 工作提交**：包括生成的 wrapper/launcher（Inductor static launcher、Triton launcher）及 CUDA Graph 重放。
   - 源范围从 181 个文件、139.1K SLoC 缩小到 34 个文件、34.7K SLoC 的决策相关控制逻辑。

2. **决策相关分支原型（Branch Archetypes）**
   - 抽象出 5 类条件分支模式：
     1. Compiled-reuse gating（编译复用门控）
     2. Guard-result gating（守卫结果门控）
     3. Cache-match gating（缓存匹配门控）
     4. Launch-grid gating（发射网格门控）
     5. Launch-path resolution（发射路径解析）

3. **自动 LLVM IR 分析（Archetype-guided search）**
   - 枚举局部代码中的 36,861 条条件分支；
   - **后向谓词溯源**：追踪分支条件产生来源，标注 JIT 阶段语义；
   - **前向后继行为分析**：分别概括两个后继路径的终止行为、JIT 阶段调用、循环重复证据；
   - 匹配原型签名（谓词来源、后继对比、JIT 上下文）并应用“持续执行检查”排除会崩溃的分支；
   - 对候选分支分别按“乱码输出”和“延迟放大”目标排序，取各自 Top-20；
   - 将源码级分支映射到二进制层的翻转记录（代码页、页内偏移、翻转方向）。

4. **内存 Profiling 与物理位对齐**
   - 使用 DRAM 地址反推与 hammer pattern fuzzing 获取可翻转物理页及其位偏移和翻转方向；
   - 将二进制翻转记录与 profiling 结果匹配（页内偏移和方向一致）；
   - 通过 memory waylaying 将目标代码页放置到对应物理页，触发 Rowhammer 实现端到端攻击。

## 6. 论文的主要结论与发现

- **攻击面有效**：JITterFlip 在 4 个模型上可实现 PPL ratio 15.45× 至 2.48×10⁶×，延迟放大 2.03× 至 181.90×。
- **跨模型迁移**：5 个乱码分支中有 2 个在 ≥3 个设置中有效；10 个延迟分支中有 6 个在 ≥3 个设置中有效。
- **绕过现有防御**：FaR 和 LM-Fix 对权重 BFA 有效，但对 JITterFlip 无缓解（PPL 35,831× / latency 188× 仍保持），因为攻击不涉及权重而是 JIT 控制流。
- **端到端 Rowhammer 可行**：单比特翻转 CPU 驻留分支代码即可跨 CPU–GPU 边界影响 GPU 推理。乱码 PPL 287.3× 至 7.23×10⁶×；海绵攻击延迟放大 97.38× 至 124.97×，且输出保持完全相同。
- **方法可扩展**：决策引导分析比随机/顺序搜索效率高得多（25%/50% vs 0%），有实用价值。

## 7. 优点

- **新攻击面**：首次系统研究 JIT 服务控制平面，而不是模型计算/参数，具有首创性；
- **模型无关**：不需要受害者模型结构、权重、训练数据甚至输入提示，攻击者只需分析公开的 PyTorch 源码；
- **攻击效果更丰富**：不仅乱码，还能实现正确输出的海绵攻击，更难被输出级防御检测；
- **跨 CPU–GPU 边界**：无需 GPU 内存访问即可干扰 GPU 推理，更贴近真实云 LLM 服务；
- **系统化分析框架**：决策语义定位 + 原型抽象 + LLVM IR 自动分析 + 二进制映射组成的流水线，具有可扩展性；
- **实验基线扎实**：与随机/顺序搜索、权重型 BFA 防御进行了对比验证。

## 8. 不足与局限

- **平台覆盖窄**：端到端 Rowhammer 仅在单套非 ECC DDR4 平台验证，未覆盖 ECC、DDR5；虽然论文引用近期绕过工作，但未实测；
- **框架单一**：只分析了 PyTorch 2.9.1 的 torch.compile 栈，其他 JIT 框架（JAX/XLA、TensorRT 等）需重新进行源码定位和 IR 分析；
- **源码版本依赖**：JIT 栈更新可能改变分支位置，攻击需要随版本重跑分析；
- **防御评估有限**：FaR/LM-Fix 只在 Qwen3-0.6B 上测试，未在更大模型上使用完整 FaR 流程；对其他防御（如 BitShield、运行时监控）未做对抗；
- **实际攻击约束**：需要 DRAM 物理可翻转位与代码页对齐，依赖 memory waylaying 成功，实际云环境成功率可能存在波动；
- **潜在偏差**：固定 prompts、固定 32-token 生成的评估限制了在不同输入分布下的推广性；论文没有讨论在多用户并发请求下的攻击影响。
