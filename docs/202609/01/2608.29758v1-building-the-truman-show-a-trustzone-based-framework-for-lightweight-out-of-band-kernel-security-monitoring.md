## 摘要
操作系统漏洞的日益增多，加上复杂的内核级威胁（如rootkit），削弱了传统内核内保护机制的有效性。由于这些防御机制与内核运行在同一特权级别，它们共享相同的攻击面，一旦内核被攻破，这些防御就可能被绕过。基于隔离的安全方法通过将安全逻辑与内核分离提供更强的保护，但严格的隔离常常引入语义鸿沟，限制系统可见性并阻碍及时威胁检测。在本文中，我们提出LOOM，一种基于ARM TrustZone的轻量级带外操作系统监控架构。通过利用TrustZone的硬件强制隔离，LOOM建立了一个独立于内核的防篡改监控环境。为了弥合语义鸿沟，我们在安全世界设计了一种轻量级语义重建机制，它选择性地捕获关键内核对象（如进程控制块和内核模块）的状态和行为模式。此外，LOOM引入了一种双阶段危害预防机制，结合了原子内存保护与中断驱动的自适应代理，以检测和缓解内核rootkit活动。进一步地，集成了地址转换缓存以优化重复地址访问并减少监控开销。总体上，我们开发了一个具有平台层、功能层和辅助层的多层协作架构，用于安全高效的内核监控。LOOM原型已在飞腾D2000平台上实现。实验结果表明，LOOM在保持强大监控能力的同时，引入的开销可忽略不计。此外，基于CVE案例的安全能力分析表明，LOOM能够检测和缓解各种内核攻击。

## Abstract
The increasing number of vulnerabilities in operating systems, together with sophisticated kernel-level threats (e.g., rootkits), has weakened the effectiveness of traditional in-kernel protection mechanisms. Since these defenses operate at the same privilege level as the kernel, they share the same attack surface and can be bypassed once the kernel is compromised. Isolation-based security approaches provide stronger protection by separating security logic from the kernel, but strict isolation often introduces semantic gaps that limit system visibility and hinder timely threat detection. In this paper, we present LOOM, a lightweight out-of-band operating system monitoring architecture built on ARM TrustZone. By leveraging TrustZone's hardware-enforced isolation, LOOM establishes a tamper-resistant monitoring environment independent of the kernel. To bridge the semantic gap, we design a lightweight semantic reconstruction mechanism in the Secure World. It selectively captures the states and behavioral patterns of critical kernel objects, such as process control blocks and kernel modules. Additionally, LOOM introduces a dual-stage hazard prevention mechanism that combines atomic memory protection with an interrupt-driven adaptive agent to detect and mitigate kernel rootkit activities. An address translation cache is further incorporated to optimize repeated address access and reduce monitoring overhead. Overall, we develop a multi-layered collaborative architecture with platform, functional, and auxiliary layers for secure and efficient kernel monitoring. A prototype of LOOM has been implemented on the Phytium D2000 platform. Experimental results indicate that LOOM incurs negligible overhead while maintaining a strong monitoring capability. Furthermore, a security capability analysis based on CVE cases demonstrates that LOOM can detect and mitigate various kernel attacks.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想

- 采用“带外（out-of-band）”监控模型：监控逻辑运行在 ARM TrustZone 提供的 Secure World 中，被监控内核运行在 Normal World，两者由硬件强制隔离。
- 设计原则：
  - 在硬件约束下权衡隔离性与感知能力；
  - 只重建最小化且必要的内核语义子集，降低复杂度和攻击面；
  - 保证异常行为的及时检测与响应；
  - 优化开销但不牺牲安全性、不引入新的信任假设。

### 2.2 整体架构

- 采用三层协作架构：
  - **平台层**：基于 TrustZone 硬件隔离，在 Normal World 内核中静态编译一个被动驱动代理（driver agent），通过 System.map 获取安全关键内核对象位置，以只读方式访问并转发到静态共享内存；共享内存被映射为单向通道，在 Secure World 中仅作为数据缓冲区，不含可执行代码或控制逻辑。
  - **功能层**：核心监控能力，包括轻量级语义重建引擎（映射物理内存到进程列表、模块列表、文件系统对象、系统调用上下文等）和双阶段危害预防机制。
  - **辅助层**：地址转换缓存（Address Translation Cache）用于降低语义重建的地址翻译开销。

### 2.3 关键技术细节

#### S1：物理地址翻译

- LOOM 从 TTBR1_EL1 寄存器获取内核页表基地址，通过遍历三级页表（PGD→PMD→PTE，4KB 页，39 位虚拟地址空间，每级 512 项）解析虚拟地址到物理地址。
- 然后使用 `phys_to_virt()` 在 Secure World 中安全访问物理地址。
- 直接解析物理地址可防止 REE 内核页表被恶意篡改导致的地址映射欺骗。

#### S2：轻量级语义重建

- 提出“内核无关、属性导向”的语义解析模型，用四元组 `<逻辑结构, 类型, 基地址, 偏移>` 描述每个被监控元素，避免重建完整数据结构。
- 逻辑结构用于抽象链表、层次包含、数组索引等访问模式；类型指定原始数据类型和大小（如整数、指针、函数地址）；基地址和偏移定位目标字段。
- 语义描述符在启动时初始化，可由内核构建工具自动生成，不依赖硬编码偏移；虽然无法完全消除内核布局差异，但在通用性与低开销之间做了取舍。
- 运行时，根据预加载描述符计算属性物理地址，映射为 Secure World 可访问虚拟地址，再安全解引用获取语义值。

#### 双阶段危害预防机制

- **原子操作（Atomic Operations）**：针对指针劫持攻击（如篡改 sys_call_table、file_operations 等），Secure Monitor 在 EL3 配置 TTBR0_EL3、TCR_EL3、MAIR_EL3 和 secure page table，将目标物理页标记为只读（AP 字段）和非执行（PXN/UXN 位），通过 SCR_EL3.NS 控制安全状态，并执行 TLB 失效保证立即生效；Normal World 无法覆盖这些属性。
- **自适应代理（Adaptive Agents）**：针对灵活足迹攻击（如隐藏模块、隐藏进程），LOOM 配置 GICv3 将软件生成中断（SGI）设为最高优先级 Secure Group；检测到 rootkit 时写 ICC_SGI0R_EL1 触发 FIQ，Secure Monitor 保存 EL1 上下文、更新 SCR_EL3、掩蔽非安全中断、冻结所有 REE 核，最后通过 ELR_EL3 和 ERET 执行受控非安全 warm reset，重启 Normal World 内核。

#### 地址翻译缓存

- 利用内核内存访问的时空局部性，缓存虚拟地址到物理地址的映射，避免重复页表遍历。
- 缓存大小为 256 项（2^8），采用数组+哈希索引（位与运算，单周期完成），直接映射替换策略，最小化查找开销。
- 平均访问时间公式：`T_avg = H·T_hit + (1-H)·T_miss`，代入实验值得到 `T_avg = 1.7×10^8 − H·1.43×10^8`。当命中率超过 0.21 时缓存即收益；命中率 80% 时平均访问延迟降低约 60%。

## 6. 论文的主要结论与发现

- 相比基线，UnixBench 性能开销在单核模式为 0.6%、多核模式为 0.8%，均在 ±2% 误差范围内，说明 LOOM 对 Normal World 性能影响可忽略不计。
- 共享内存通道获取内核数据约需 3.5×10^4 周期，而 SMC 往返上下文切换约 7.6×10^8 周期，共享内存方式比 SMC 快超过 10000 倍，大幅降低了 REE-TEE 通信开销。
- 地址转换缓存将语义解析加速约 6.3 倍（缓存命中 2.7×10^7 周期 vs 未命中 1.7×10^8 周期），平均开销随命中率显著下降。
- LOOM 结合硬件隔离、语义感知和主动防御，相对现有工作（如 Hypernel、NFM、KIMS）在“隔离性 + 语义可见性 + 低开销 + 主动防御”组合上更全面。
- 基于 CVE 分析，LOOM 可检测和缓解进程隐藏、Netfilter 漏洞、权限提升、use-after-free、syscall 表篡改等多种内核攻击。

## 7. 优点

- **架构清晰**：平台层、功能层、辅助层分层设计，职责明确，有助于安全性和可维护性。
- **硬件级隔离**：基于 TrustZone 的 Secure World 监控，消除与内核的“同命运”依赖，防篡改能力强。
- **轻量语义重建**：仅重建最小关键属性，避免完整内核镜像，降低复杂度和攻击面。
- **低通信开销**：共享内存单向通道避免频繁世界切换，比 SMC 快四个数量级以上。
- **主动防御能力**：双阶段危害预防（原子内存保护 + 自适应中断代理）既能防护指针劫持，又能处理灵活足迹攻击，提供了现有同类工作（如 KIMS）不具备的主动响应能力。
- **性能优化合理**：地址转换缓存利用局部性且用位运算索引，实现简单高效。
- **实验测量有针对性**：对开销、通信、缓存效果分别给出量化数据，并用 CVE 案例说明安全能力。

## 8. 不足与局限

- **实验覆盖不足**：缺少对真实 rootkit 实际攻击的动态检测与响应实验，CVE 分析仅为理论推演，未在实机上复现攻击。
