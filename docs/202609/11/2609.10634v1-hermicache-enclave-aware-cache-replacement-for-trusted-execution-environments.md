## 摘要
可信执行环境（TEE）保护飞地内存免受不可信软件的攻击，但由于共享的微架构资源，仍易受基于缓存的侧信道攻击。现有对策采用缓存分区或随机化等技术：如果设计者希望获得细粒度配置和确定性保护，这些方案并不理想。在本文中，我们提出 HermiCache，它满足了这些需求。HermiCache 面向 RISC-V 核设计，并已在 OpenHwGroup CVA6 核中实现，软件层采用 Keystone TEE。该方案在处理器核上的面积开销为 6%。

## Abstract
Trusted Execution Environments (TEEs) protect enclave memory from untrusted software but remain vulnerable to cache-based side-channel attacks due to shared microarchitectural resources. Existing countermeasures use techniques such as cache partitioning or randomization: these solutions are not ideal if a designer wants fine-grained configurations and a deterministic protection. In this paper, we introduce HermiCache which is an answer to these requirements. HermiCache is designed for RISC-V cores and has been implemented in the OpenHwGroup CVA6 core with a Keystone TEE for the software layer. The solution has an area overhead of 6% on the processor core.

# HermiCache 论文中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：可信执行环境（TEE，如 Intel SGX、ARM TrustZone、AMD SEV，以及 RISC-V 上的 Keystone、Penglai）通过 enclave 将敏感代码与数据同不可信软件隔离。
- **核心问题**：TEE 的保护并不完整——处理器、缓存层次等**共享微架构资源**仍会泄漏信息。攻击者可利用共享缓存实施 Evict+Time、Prime+Probe、Flush+Reload 等时序侧信道攻击，从受害者 enclave 中窃取信息。
- **现有对策的缺陷**：
  - 软件方案（如常数时间编程）难以应用于复杂程序；
  - 硬件方案（缓存分区、随机化）会导致容量利用率下降，且需要额外逻辑管理替换策略。
  - 关键在于：当设计者需要**细粒度配置**与**确定性（deterministic）保护**时，上述方案都不理想。
- **论文含义**：提出 HermiCache，一种面向 RISC-V 核、基于硬件强制的 TEE 缓存隔离机制，兼顾低开销、可配置性与确定性防护。

## 2. 方法论：核心思想与关键技术细节

- **核心思想：基于所有权（Ownership-based）的缓存替换机制**
  - 在组相联缓存中为**每条缓存行**扩展所有权元数据：
    - **1 位安全标志**：该行是否受 HermiCache 保护；
    - **Enclave IDentifier（EID）**：该行归属哪个 enclave。
  - 通过元数据区分"谁拥有这条缓存行"，从而在替换决策时避免跨 enclave 的相互驱逐。

- **安全缓存缺失（secure cache miss）时的替换优先级**（文中图 1 的灰块流程）：
  1. 优先选择**无效（invalid）条目**；
  2. 其次选择**当前 enclave 自己的行**；
  3. 再次选择**未被保护的行**；
  4. 若不存在符合条件的受害者，则**在该缓存层级旁路分配（bypass allocation）**，即不进行替换。
  - 该流程同时包含普通缓存查询与带 enclave ID 的扩展查询分支，依据"是否 enclave 请求""安全模式是否激活""标签匹配的组相联路"等条件判定命中/缺失。

- **与 Keystone TEE 的集成**：
  - 扩展 Keystone API，允许 enclave 显式请求缓存保护（`create_enclave(eid)`、`activate_countermeasure()`、`destroy_enclave(eid)`）。
  - Keystone 安全监视器（SM）负责分配 EID 并配置安全标志，二者写入 CVA6 核中新增的**可信 CSR 寄存器**（CSR1 为 4 位 EID、CSR2/CSR3 各 1 位标志、另有 32 位寄存器）。
  - 默认 EID 宽度为 **4 位**，支持最多 **15 个受保护标识符**（另 1 个专门用于非安全执行）。

- **威胁模型**：
  - 处理器、缓存层次与 Keystone SM 可信；操作系统与 REE 应用等软件不可信。
  - 攻击者被允许执行不可信代码并发起缓存攻击（Prime+Probe、Evict+Time、Flush+Reload）。
  - **不防护** TLB、分支预测器等其他微架构侧信道，也不考虑物理攻击。
