## 摘要
在云计算中，不同用户共享同一物理硬件，这带来了严重的安全风险。为了保护数据，云系统依赖虚拟机和容器来隔离用户。本文综述了 2008 年至 2025 年的 120 多篇安全出版物，重点关注这些隔离边界如何被突破。我们考察了虚拟机逃逸、虚拟机跳转、CPU 缓存侧信道、容器逃逸、存在漏洞的容器镜像以及分布式拒绝服务（DDoS）攻击等威胁。我们使用三个关键研究问题来评估这些安全威胁及其防御措施。为了比较不同的防御系统，我们引入了一个名为 ADPO 的量化评分框架，它根据防御措施的准确性（Accuracy）、部署便捷性（Deployment ease）、性能影响（Performance impact）和运维开销（Operational overhead）将其评为 0 到 3 分。我们还将这些攻击的影响映射到针对机密性、完整性和可用性的 1 到 5 级严重性量表上。最后，我们强调了安全与系统性能之间的权衡，并概述了构建低开销入侵检测和创建真实测试数据集等开放挑战。

## Abstract
In cloud computing, different users share the same physical hardware, which creates serious security risks. To protect data, cloud systems rely on virtual machines and containers to keep users isolated. This paper reviews over 120 security publications from 2008 to 2025, focusing on how these isolation boundaries can be breached. We examine threats like virtual machine escape, virtual machine hopping, CPU cache side-channels, container breakouts, vulnerable container images, and distributed denial of service (DDoS) attacks. We evaluate these security threats and their defenses using three key research questions. To compare different defense systems, we introduce a quantitative scoring framework called ADPO, which rates defenses from 0 to 3 based on their Accuracy, Deployment ease, Performance impact, and Operational overhead. We also map the impact of these attacks onto a 1-to-5 severity scale for Confidentiality, Integrity, and Availability. Finally, we highlight the trade-offs between security and system performance, and we outline open challenges like building low-overhead intrusion detection and creating realistic test datasets.

## 6. 主要结论与发现

- **安全—性能权衡是核心张力**：
  - 硬件级防御（SMM、CATalyst、HTM）隔离保证最强，但需处理器厂商采纳或特定硬件特性，部署受限；
  - 软件/hypervisor 层检测（CacheShield、CloudRadar、NIGHTsWATCH）可现网部署、准确率可达 **99.51%**，但只能"泄漏后检测"、无法阻止，且带来持续监控开销。
- **CIA 严重性排序**（原文表 7）：
  - VM 逃逸 **5/5/5**（最严重，VMM 完全失守）；
  - VM 跳转 **4/4/3**；
  - 缓存侧信道 **5/1/1**（机密性极高，可用性几乎无影响）；
  - 容器逃逸 **4/4/4**；
  - 容器镜像漏洞 **3/3/3**；
  - EDoS/流量型 DDoS **1/2/5**（主要打击可用性，并通过自动扩缩容造成"Yo-Yo"式财务损耗）。
- **容器镜像 = 供应链熵传播源**：92% 公共镜像含平均 10 个漏洞包，99% 存在合规违规，8.5% 镜像泄漏凭证。
- **范式整合建议**：单一防御不足，需"运行时异常检测 + 主动漏洞评估 + 结构性隔离"的纵深组合；VM 跳转往往只是 APT 多阶段链条中的一环，点状方案无效。
- **开放挑战（三大控制论议题）**：
  1. **闭环控制与动态硬件隔离**：现有 hypervisor 为开环设计，需用运行时遥测反馈驱动调度器动态调整；
  2. **熵传播与软件层检测极限**：容器共享内核使上游镜像漏洞放大为宿主机错误，ML 检测受数据集瓶颈制约，需自监督异常闭环；
  3. **弹性饱和缓解**：DDoS/EDoS 利用自动扩缩容形成正反馈，需 eBPF/XDP 边端线速清洗的分布式闭环过滤器。
- **共性缺口**：缺乏高保真、标准化的云/容器安全数据集，导致检测结果难以泛化。

## 9. 对后续研究的启示与可操作建议

- **对防御设计者**：
  - 单一机制难以覆盖完整攻击链，宜按"结构隔离（硬件/namespace）+ 运行时检测（VMI/eBPF/系统调用建模）+ 主动评估（模糊测试、镜像扫描）"三层组合，并明确各层负责的 CIA 维度；
  - 选择机制时应先明确自身约束：若为公有云多租户且无法改动客户机，D 维度权重应提高，优先考虑无 agent 的 VMI/宿主层方案；若为私有云且可定制硬件，A 维度可优先。
- **对评测与基准建设**：
  - 当务之急是构建**标准化、高保真、跨平台**的云安全数据集与统一测试床（含真实攻击载荷、真实多租户负载、可复现的扩缩容策略），以消除"不同数据集比准确率"的可比性障碍；
  - 建议在报告检测效果时强制披露：数据集来源与规模、攻击类型分布、误报率（FPR）、以及性能开销的测量方法与基线。
- **对评分方法论的改进方向**：
  - 将 ADPO 从"作者主观打分"升级为**多评审独立打分 + 一致性检验（Cohen's Kappa / Krippendorff's α）**；
  - 引入**权重敏感性分析**（如 AHP 或熵权法）说明四维如何聚合为单一结论，或直接放弃单一分数、改用帕累托前沿（Pareto frontier）呈现"准确率—开销"权衡曲线；
  - 可考虑以**每类攻击的 CIA 损失 × 防御成本**构建期望效用函数，使跨族比较具备统一量纲。
- **对攻击面演进的跟踪**：应把机密计算（SGX/TDX/SEV-SNP）、WebAssembly 沙箱、Serverless 冷启动侧信道、eBPF 自身作为新攻击面（如 eBPF 验证器漏洞）纳入下一代威胁模型。

## 10. 总体评价

- **定位与贡献**：本文是一篇**覆盖面广、组织清晰、带量化比较工具**的系统性综述。其最大增量不在于发现新漏洞，而在于（i）用统一的 ADPO/CIA 双评分把散落文献转化为可比数据；（ii）用控制论框架把"性能—安全"权衡上升为可讨论的系统问题；（iii）按威胁族给出防御范式谱系与组合建议，具备较强的"路线图"实用价值。
- **适用读者**：云安全研究者（快速定位某威胁族的代表工作与开放问题）、云平台架构师（选型时参考 ADPO 与 CIA 排序）、以及刚进入该领域的博士生（PRISMA 流程与表格可直接作为文献入口）。
