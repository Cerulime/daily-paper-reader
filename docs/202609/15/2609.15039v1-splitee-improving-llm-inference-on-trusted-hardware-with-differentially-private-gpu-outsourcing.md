## 摘要
提供给大语言模型（LLM）的用户提示可能包含敏感或隐私信息，这些信息可能被远程部署的模型滥用，例如在重新训练期间被无意记忆。保护用户提示的一种方式是在可信执行环境（TEE）内执行 LLM，并保证服务提供商无法访问 TEE 内执行的计算或与 TEE 交换的信息。然而，当前 TEE 主要基于 CPU，且比针对 LLM 推理优化的 GPU 慢得多。为规避这一问题，Tramer 和 Boneh（2019）提出了 Slalom，它在 TEE 与不可信 GPU 之间拆分神经网络推理，并加密发送至 GPU 的中间输入。我们将这种拆分推理架构扩展到 LLM 推理，并转而使用差分隐私来保护中间输入。我们证明了对中间表示进行掩蔽的必要性：提示重建攻击能够以近 80% 的准确率从这些表示中恢复提示。我们的主要贡献是对关键 LLM 函数进行全局敏感性分析，从而界定了所需差分隐私噪声的规模。与加密不同，差分隐私避免了量化，使 LLM 能够保持在浮点域中。我们还推导了 TEE 中掩蔽与噪声消除所导致的浮点误差上界，该上界是隐私参数 ε 的函数。我们使用 Intel TDX 实现该架构，并用两个 LLM（Llama-3.2-3B 和 Qwen3-4B）对其进行评估。我们的拆分执行比 TDX 内完全基于 CPU 的推理快近两倍，比基于加密的 Slalom 快 5–15 秒，同时实现了更高的准确率。最后，我们证明，即使已知差分隐私机制，提示重建也无法恢复出比一个无关提示所包含的更多信息。

## Abstract
User prompts provided to large language models (LLMs) may contain sensitive or private information that can be misused by remotely deployed models, such as through inadvertent memorization during retraining. One way to protect user prompts is to execute the LLM inside a trusted execution environment (TEE), with the guarantee that the service provider has no access to computations performed within or information exchanged with the TEE. However, current TEEs are primarily CPU-based and significantly slower than GPUs optimized for LLM inference. To circumvent this, Tramer and Boneh (2019) proposed Slalom, which splits neural network inference between a TEE and an untrusted GPU and encrypts intermediate inputs sent to the GPU. We extend this split-inference architecture to LLM inference and instead protect intermediate inputs using differential privacy. We show that masking intermediate representations is necessary by showing that a prompt-reconstruction attack can recover prompts from these representations with nearly 80% accuracy. Our main contribution is a global sensitivity analysis of key LLM functions, which bounds the required scale of differentially private noise. Unlike encryption, differential privacy avoids quantization, allowing the LLM to remain in the floating-point domain. We also derive an upper bound on floating-point error from masking and noise cancellation in the TEE as a function of the privacy parameter epsilon. We implement our architecture using Intel TDX and evaluate it with two LLMs: Llama-3.2-3B and Qwen3-4B. Our split execution is nearly twice as fast as fully CPU-based inference inside TDX and 5-15 seconds faster than encryption-based Slalom while achieving higher accuracy. Finally, we demonstrate that prompt reconstruction, even with knowledge of the differential privacy mechanism, cannot recover more information than is contained in an unrelated prompt.

## 1. 核心问题与整体含义

- **研究动机**：用户提交给远程 LLM 的提示可能包含敏感或隐私信息，服务提供商可能在重训练中无意记忆这些内容。将 LLM 部署在可信执行环境（TEE）内可防止服务提供商窥探计算与数据，但当前 TEE 主要基于 CPU，其推理速度远慢于 GPU。
- **背景与挑战**：
  - TEE（如 Intel TDX）虽能提供机密性与完整性保证，但 LLM 推理中的矩阵乘法在 CPU 上效率极低。论文实测显示，TDX 内全 CPU 推理在 800 token 生成时耗时 53–83 秒，而 GPU 仅需 3–5 秒。
  - Slalom（Tramer & Boneh, 2019）提出将 DNN 推理拆分至 TEE 与不可信 GPU，通过流密码加密中间输入，但需量化到有限域，导致精度损失。
  - TwinShield 等后续工作将拆分推理扩展至 Transformer，但仍依赖量化，且部分掩蔽机制（如置换）缺乏形式化安全证明。
- **整体含义**：SpliTEE 首次将拆分推理架构扩展至 LLM，并改用**差分隐私**（而非加密）保护外包至 GPU 的中间表示。差分隐私使 LLM 保持在原生浮点域，避免了量化带来的精度损失，同时通过调节隐私参数 ε 实现隐私与效用之间的可控平衡。

## 2. 方法论

### 2.1 核心思想

- **拆分推理架构**：TEE（Intel TDX 虚拟机）保留所有机密数据（中间激活、掩码张量、修正值），仅将昂贵的线性操作（Q、K、V、O、Gate、Up、LM Head 投影）外包给不可信但更快的 GPU。
- **线性掩蔽与消除**：对输入 \(x\) 添加噪声 \(\eta\) 得 \(\tilde{x} = x + \eta\)，GPU 计算 \(W\tilde{x} = Wx + W\eta\)，TEE 收到结果后减去预计算的修正量 \(W\eta\)，恢复 \(Wx\)。该过程依赖矩阵乘法的线性性质。
- **差分隐私替代加密**：不同于 Slalom 使用有限域上的流密码掩蔽，SpliTEE 使用高斯机制添加差分隐私噪声，避免量化，保持浮点运算域。

### 2.2 关键技术细节

- **全局敏感度分析**（核心贡献）：
  - 对 LLM 中前置函数（层归一化 LN、注意力机制 att、SiLU 激活函数 act）进行全局 \(\ell_2\)-敏感度上界推导：
    - **LN**：\(\Delta_{LN} \leq 2\sqrt{d} \cdot \|\alpha\|_4\)
    - **注意力**：\(\Delta_{att} \leq 2\sqrt{d} \cdot \|W_{val}\|_2 \cdot \|\alpha\|_4\)
    - **激活函数**：\(\Delta_{act} \leq 2\sqrt{d} \cdot (\sqrt{d}\|\alpha\|_4 + \|\beta\|_2)^2 \cdot \|W_{up}\|_2 \cdot \|W_{gate}\|_2\)
  - 基于 f-差分隐私框架，采用 \(\epsilon\)-GDP（高斯差分隐私），噪声机制为 \(\eta \sim \mathcal{N}(0, (\Delta_f/\epsilon)^2 I_d)\)。
  - 对 n 个 token 的提示，单次外包操作满足 \(\sqrt{n}\epsilon\)-GDP；顺序组合下总隐私预算为 \(\sqrt{n}\epsilon\)。

- **浮点误差上界分析**（定理 4）：
  - 推导了噪声消除后浮点误差的上界：
    \[
    |fl(\langle w,x\rangle) - fl(fl(\langle w,x+\eta\rangle) - fl(\langle w,\eta\rangle))| \leq \gamma_d \langle |w|, |x| + |x+\eta| + |\eta| \rangle + u\langle |w|, |x| \rangle + O(du^2)
    \]
  - 实际使用中采用 Higham 的成对求和估计：\(\gamma_{\lceil \log_2 d \rceil + 1}\)。
  - 该上界可用于通过蒙特卡洛模拟选择适当的 ε，确保浮点误差不损害 LLM 输出质量。

- **实现流程**：
  1. TEE 预生成噪声掩码 η 和修正量 \(W\eta\)，存入噪声库（按输入形状索引，一次性使用）。
  2. 推理时，TEE 对输入加噪后通过 IVSHMEM 共享内存发送至 GPU，TCP socket 用于控制信令。
  3. GPU 执行矩阵乘法，返回结果。
  4. TEE 从噪声库取出对应修正量，执行减法恢复原始线性输出，继续后续 Transformer 计算。

- **不外包 Down 投影**：因该组件输入维度（\(d_{ff}=8192\)）远大于隐藏维度（\(d=3072\)），敏感度上界极高，导致噪声尺度与浮点误差过大，存储成本高昂，故保留在 TEE 内。

## 6. 主要结论与发现

- **性能提升**：
  - SpliTEE 拆分推理比 TDX 内全 CPU 推理快近 **2 倍**（800 token 时 23.9 秒 vs. 53.3 秒，Llama-3B）。
  - 比加密方案 Slalom 快 **5–15 秒**（Llama-3B 约快 5 秒，Qwen-4B 约快 15 秒）。
  - 噪声添加与修正仅引入 modest 开销（EP1 vs. T3 差距很小）。

- **生成质量**：
  - ε ≥ 10 时，100% 精确匹配原始输出。
  - ε = 5 时 98% 精确匹配；ε = 1 时 84%；ε = 0.5 时 67%。
  - 语义相似度在所有 ε 下均保持高位（99.36%–100%）。
  - Slalom 精确匹配率 0%，Token 匹配率仅 20.22%，BLEU 43.82%，显著低于 SpliTEE。

- **浮点误差**：
  - 理论上界约为真实误差的 **4.3 倍**，偏保守但能有效指示误差趋势。
  - 平均真实误差随 ε 增大而减小（ε = 0.5 时 \(2.26 \times 10^{-4}\)，ε = 15 时 \(7.48 \times 10^{-6}\)）。
  - 受控误差实验表明：平均绝对误差超过 \(10^{-4}\) 时生成质量开始下降；\(2 \times 10^{-2}\) 时语义相似度降至 9.91%。

- **隐私保护**：
  - 无掩蔽时，提示重建攻击可从 QKV 输入恢复提示，Token F1 ≈ 70.30%，语义相似度 ≈ 79.87%。
  - 加噪后（ε = 1），Token F1 降至约 15.91%，语义相似度仅约 5.29%，与随机提示对基线相当。
  - 即使攻击者知道 DP 机制并用相同噪声训练（噪声感知攻击者），提升也极为有限。
  - GPT-5.4 后处理修复对噪声感知重建无显著提升（Token F1 15.91% → 15.76%）。
  - ε = 2500 时重建重新变得可能（语义相似度 78.41%），说明噪声尺度是关键。

## 7. 优点

- **方法创新**：
  - 首次将差分隐私引入 LLM 拆分推理，替代传统加密掩蔽，避免量化，保持浮点域。
  - 提出完整的全局敏感度分析框架，可复用于任何需要外包 LLM 中间计算的系统。
  - 推导了浮点误差上界，并证明可通过调节 ε 控制误差在可接受范围内。

- **实验设计亮点**：
  - 攻击评估采用最强威胁模型（攻击者知道模型权重、架构、DP 机制及 ε），结果具有说服力。
  - 引入随机提示对基线（平均 Token F1 ≈ 20.71%）区分“真实重建”与“偶然重叠”。
  - 受控误差实验系统性地量化了数值误差与生成质量的关系，为 ε 选择提供实用指南。
  - 消融实验清晰（T3 vs. EP1 vs. EPN；单组件 vs. 复合攻击者；Down 投影排除分析）。

- **工程实现**：
  - 使用 Intel TDX + IVSHMEM 共享内存 + TCP 控制通道，实现高效 TEE-GPU 通信。
  - 噪声库预计算与一次性使用设计，兼顾安全性与运行时效率。
  - 代码开源（GitHub: DPVault/SpliTEE）。

- **隐私与效用平衡**：
  - ε 可调，用户可根据任务需求在隐私与精度之间灵活取舍，这是 Slalom 不具备的特性
