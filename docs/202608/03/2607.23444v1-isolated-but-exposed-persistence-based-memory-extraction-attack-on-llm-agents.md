## 摘要
基于LLM的智能体通过长期记忆（LTM）扩展大型语言模型，跨会话持久化保存隐私敏感的用户数据。生产系统通过记忆隔离来缓解提取风险，将每个用户的LTM绑定到唯一标识符。这种防御已阻止了已知的针对共享存储的攻击，从而形成了隔离的LTM是安全的假设。我们识别出工具接口是一个被忽视的攻击面。智能体经常将LTM检索到的数据嵌入工具调用参数中，使得恶意工具能够在违反用户级隔离的情况下泄露私有记忆。用户侧提取技术的简单改造会失败，因为对抗性命令的语义干扰了检索精度，而平台强加的工具调用限制约束了每次触发的提取预算。我们提出了SPORE，这是首个针对该威胁模型的提取攻击。SPORE通过将命令持久化在短期记忆中将对抗性命令与检索锚点解耦，并在工具响应中发出语义纯锚点。恢复的检索精度使得嵌入空间上的几何覆盖优化能够系统地引导锚点朝向未探索的记忆区域。为了在工具调用限制之外持续提取，SPORE在记忆中持久化重新激活负载，这些负载可在会话内及跨会话自动恢复攻击，无需额外用户触发。SPORE在无限触发下实现了80.0%的记录提取率，在仅20次触发下实现了47.0%。在多用户部署中，攻击者可以将提取的记录链接到用户身份，从而支持定向监控。这些结果表明，仅靠记忆隔离是不够的，并呼吁重新审视智能体架构中的工具侧信任边界。

## Abstract
LLM-based agents extend large language models with long-term memory (LTM) that persists privacy-sensitive user data across sessions. Production systems mitigate extraction risks through memory isolation, binding each user's LTM to a unique identifier. This defense has blocked known attacks on shared storage, fostering the assumption that isolated LTM is secure. We identify the tool interface as an overlooked attack surface. Agents routinely embed LTM-retrieved data in tool invocation parameters, enabling a malicious tool to exfiltrate private memory without violating user-level isolation. Naive adaptations of user-side extraction techniques fail because the adversarial command's semantics interfere with retrieval precision, and platform-imposed tool-call limits constrain the extraction budget per trigger. We present SPORE, the first extraction attack designed for this threat model. SPORE decouples the adversarial command from retrieval anchors by persisting the command in short-term memory and emitting semantically pure anchors in tool responses. The restored retrieval precision enables a geometric coverage optimization over the embedding space that systematically steers anchors toward unexplored memory regions. To sustain extraction beyond tool-call limits, SPORE persists reactivation payloads in memory that automatically resume the attack within and across sessions without additional user triggers. SPORE achieves an 80.0% record extraction rate with unlimited triggers and 47.0% with only 20 triggers. In multi-user deployments, attackers can link extracted records to user identities, enabling targeted surveillance. These results demonstrate that memory isolation alone is insufficient and call for reexamining tool-side trust boundaries in agent architectures.

## 2. 方法论：SPORE 攻击

### 核心思想

SPORE 的关键洞察在于**智能体记忆是有状态的（stateful）**——注入的内容可以跨迭代和跨会话持续存在并影响智能体行为。SPORE 利用这一特性解决工具侧攻击面临的两大瓶颈：**语义干扰（L1）** 与**有限的工具调用预算（L2）**。

### 关键技术细节

SPORE 的攻击流程分为三个阶段：

| 阶段 | 名称 | 功能 |
|------|------|------|
| Step ❶ | 对抗上下文建立 | 在首个迭代中注入对抗指令 C_adv 到短期记忆（STM），实现持久劫持控制，且后续查询不再受指令干扰 |
| Step ❷ | 迭代记忆提取 | 每个迭代中工具响应仅包含纯语义锚点（anchor），引导检索未探索的记忆区域，并将检索记录通过工具参数外泄 |
| Step ❸ | 重新激活负载注入 | 在提取循环结束前注入 dormant payload，自动恢复攻击（STM 或 LTM 持久化），无需用户再次触发 |

### 核心创新点

- **指令-锚点解耦**：传统攻击范式是 `锚点 ⊕ 对抗指令` 拼接；SPORE 将指令一次性注入 STM 持久生效，工具响应中只保留纯语义锚点，消除了指令对查询嵌入的语义干扰，恢复了对检索方向的精确控制。
- **几何覆盖优化**：首次将记忆提取形式化为嵌入空间中的几何覆盖问题——每个检索操作视为"探索球"（explored ball），目标为最大化未探索区域的覆盖，避免重复检索。
  - **细粒度扩展**：基于 intra-component/inter-component 距离评分，向已知语义区域的边界扩张；
  - **粗粒度发现**：使用 K-means 聚类已检索记录，从检索内容中提取关键词，寻找距离已有聚类中心最远的候选锚点；
  - **自适应模式切换**：默认 γ=4 个连续无新记录的迭代后切换模式，平衡全局探索与局部扩展。
- **持久化重新激活**：通过 LLM-Fuzzer 优化预激活负载，使其在 STM 或 LTM 中长期存留，未来会话中由相似度检索自动触发，恢复攻击循环；同时产生良性回复以保持隐蔽。

### 负载优化

- 对抗指令 C_adv 与重新激活负载 Preact 均通过 LLM-Fuzzer 模板级模糊测试优化；
- 评估时需在完整的多轮提取循环中验证，而非单次提示-响应对。

## 6. 主要结论与发现

- 记忆隔离不足以保证 LTM 隐私：**工具侧通道可以被恶意工具系统性地利用**，打破"隔离即安全"的普遍假设。
- SPORE 在无限触发下达到 **80.0%** 的记录提取率（GPT-5-mini、LTMemory、HealthCareMagic 数据集），仅 20 次触发时仍有 **47.0%**（RER@20），单次触发 + LTM 持久化可达到 76.5%–77.5%（RER@1）。
- 在稀疏触发及无会话连续条件下，SPORE 仍可保持较高提取率，说明预先注入的持久化负载可以长期潜伏并自动恢复攻击循环。
- 多用户部署中，攻击者可结合 **OAuth 2.1 授权** 将提取的记忆与用户身份关联，将匿名批量提取转化为定向监控。

## 7. 优点

- **问题定义新颖**：识别出工具接口作为用户隔离之外的独立攻击面，挑战了行业普遍接受的"用户隔离即安全"假设。
- **方法论系统化**：将提取问题形式化为嵌入空间的几何覆盖优化，给出了可量化的探索策略，而非启发式遍历，为后续攻击研究提供了新的理论视角。
- **消融实验归因清晰**：通过逐步移除组件（如纯 coarse / pure fine）验证各策略的独立贡献，结论可信度较高。
- **威胁模型贴近实际**：考虑了平台工具调用限制、用户触发稀疏性、无会话连续性等真实部署约束，且在 Dify 和 Coze 两个实际平台上验证了攻击。攻击者假设采用黑盒设定，不依赖任何内部信息，具有现实威胁性。

## 8. 不足与局限

- **实验规模有限**：LTM 仅 200 条记录，且未在真实生产系统或大规模用户数据上验证，实验结论的外推性受限。

- **多用户场景论证不足**：文中只用 OAuth 2.1 说明身份关联的可能性，没有给出多用户共享唯一工具下跨用户提取的具体实验数据。
