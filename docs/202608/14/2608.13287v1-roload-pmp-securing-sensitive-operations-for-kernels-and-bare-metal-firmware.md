## 摘要
攻击者破坏受害者系统的一种常见方式是使用攻击者控制的输入劫持敏感操作（例如控制流转移）。现有解决方案通常只保护这些目标的一部分，并且具有较高的性能开销，这使得它们在资源有限的系统（例如物联网设备）或内核和裸机固件等低级软件上不切实际且难以部署。在本文中，我们提出了一种轻量级软硬件协同设计方案 ROLoad-PMP，以保护低级软件中的敏感操作免受劫持。首先，我们提出了新的指令，这些指令仅从具有特定密钥的只读内存区域加载数据，以保证（可能被破坏的）数据指针所指向对象的完整性。然后，我们提供了一种程序加固机制来保护敏感操作，通过在编译时对其操作数进行分类并将其放入具有不同密钥的只读内存中，并在运行时使用 ROLoad-PMP 系列指令加载它们。我们基于 RISC-V 实现了 ROLoad-PMP 的 FPGA 原型，并展示了一个重要的防御应用，即前向边控制流完整性。结果表明，ROLoad-PMP 仅需少量额外硬件资源（< 1.40%）。此外，它实现了许多轻量级防御（例如开销可忽略不计，< 0.853%），并提供比现有硬件解决方案（如 ARM BTI 和 Intel CET）更广泛、更强的安全保证。

## Abstract
A common way for attackers to compromise victim systems is hijacking sensitive operations (e.g., control-flow transfers) with attacker-controlled inputs. Existing solutions in general only protect parts of these targets and have high performance overheads, which are impractical and hard to deploy on systems with limited resources (e.g., IoT devices) or for low-level software like kernels and bare-metal firmware. In this paper, we present a lightweight hardware-software co-design solution ROLoad-PMP to protect sensitive operations from being hijacked for low-level software. First, we propose new instructions, which only load data from read-only memory regions with specific keys, to guarantee the integrity of pointees pointed by (potentially corrupted) data pointers. Then, we provide a program hardening mechanism to protect sensitive operations, by classifying and placing their operands into read-only memory with different keys at compile-time and loading them with ROLoad-PMP-family instructions at runtime. We have implemented an FPGA-based prototype of ROLoad-PMP based on RISC-V, and demonstrated an important defense application, i.e., forward-edge control-flow integrity. Results showed that ROLoad-PMP only costs few extra hardware resources (< 1.40%). Moreover, it enables many lightweight (e.g., with negligible overheads < 0.853%) defenses, and provides broader and stronger security guarantees than existing hardware solutions, e.g., ARM BTI and Intel CET.

## 1. 核心问题与整体含义

- **研究动机**：内存破坏类漏洞十分常见，攻击者常利用漏洞将攻击者可控数据写入程序的**敏感操作数（sensitive sinks）**（如间接调用目标、敏感 API 参数、校验标志等），进而劫持控制流或绕过安全检查。
- **现有方案的不足**：
  - 软件方案（如 taint、CFI、CPI 等）要么只覆盖部分目标，要么运行时开销过高。
  - 硬件方案（如 Intel MPK、ARM MTE、ARM PA、Intel CET、ARM BTI）或实现复杂、或开销较大、或仅提供粗粒度保护，难以部署在资源受限的低端设备（IoT）、内核和裸机固件等场景。
- **论文目标**：设计一种**轻量、低开销、可移植、易部署**的软硬件协同方案，为低级软件（内核、裸机固件）中的敏感操作提供完整性和安全检查。

## 2. 方法论

- **核心思想**：提出一种轻量级数据流完整性变体——**pointee integrity（指针目标完整性）**。即不追踪指针本身是否被篡改，而是确保“指针最终指向的数据”是从**带有特定密钥（key）的只读内存区域**中加载的，从而保证该数据不可能被攻击者篡改。
- **威胁模型**：假设存在内存破坏漏洞；DEP（W⊕X）已部署；PMP CSR 初始化后不可篡改；硬件可信。
- **关键设计**：
  - 新增 **ROLoad-PMP 系列指令**（如 `ld.ro`、`lw.ro`、压缩的 `c.ld.ro`），它们只允许从**只读且带有指定密钥**的内存区域加载数据，否则触发访问异常。
  - 扩展 RISC-V PMP：为每个 PMP 区域增加 `pmpkey` 字段（新 CSR），并在处理器 TLB/PMP 检查逻辑中增加“只读检查”和“密钥匹配检查”，与原有权限检查并行，通过 AND 门合并结果。
  - 编译器支持：扩展 LLVM，提供 `ROLoad-PMP-md` 元数据接口，将普通 load 指令替换为 ROLoad-PMP 指令，并将不同类别的允许值（allowlist）放入不同密钥的只读 section。
  - SBI 支持：扩展 OpenSBI，提供 `set_pmp_ro()` 函数，供 S-mode 代码（如操作系统内核）设置只读区域及密钥。
- **应用示例：类型基前向边 CFI**：
  - 将地址被取函数（address-taken functions）按函数类型哈希分组，放入不同密钥的只读数组（GFPT）。
  - 将函数指针改为指向 GFPT 表项；使用函数指针时，用 `ld.ro`（带正确密钥）从 GFPT 加载真实函数地址，从而保证间接调用目标必须来自对应类型的只读表，实现类型匹配的 CFI。
- **实现规模**：修改 RISC-V BOOM 核心（94 行 Chisel）、OpenSBI（5268 行 C）、LLVM 后端（1234 行 C++/TableGen）；应用层（LLVM pass 和内核修改）共 796 行。

## 6. 主要结论与发现

- **硬件开销极低**：增加 `ld.ro` 指令后，FPGA 资源开销 LUT < 0.56%~0.37%、FF < 1.40%~0.74%，最大频率几乎不变。
- **性能开销可忽略**：
  - SPEC CINT2006 平均开销 < 0.030%（KCFI < 0.289%）；
  - Nginx 平均开销 < 0.305%（KCFI < 2.24%）；
  - Redis 平均开销 < 0.853%（KCFI < 2.48%）。
  - 部分负开销来自代码/数据布局变化导致的缓存/TLB 命中率变化。
- **安全强度**：提供的类型基 CFI 与 KCFI 等方案相当，但开销低一个数量级以上；相比 ARM BTI/Intel CET 的粗粒度 IBT，ROLoad-PMP 提供更强的类型匹配保证。
- **适用性**：可用于内核、裸机固件等低层软件，也适用于资源受限设备。

## 7. 优点

- **轻量简单**：硬件改动只有约百行 Chisel，逻辑简单，不增加关键路径；软件改动集中在编译器和 SBI，部署成本低。
- **通用性强**：思想不限于 RISC-V，可迁移到 ARM；对 x86 可设计指令前缀。
- **低开销且安全强度高**：相比软件 CFI 和硬件 ARM PA 等，实现更简单、开销更低，且提供类型基 CFI 的强保证。
- **设计理念清晰**：类比 DEP（代码不可执行），提出“敏感操作只能使用只读密钥数据”的“数据版 DEP”，直观且易理解。
- **应用场景扩展**：原始 ROLoad 依赖 MMU 页表，不能保护内核自身；ROLoad-PMP 改用 PMP，使得保护内核/裸机固件成为可能。

## 8. 不足与局限

- **安全局限**：
  - 面临 **pointee reuse 攻击**：攻击者可以重用只读区域中已有且密钥匹配的数据（如将指针指到合法 GFPT 中的其他目标），类似控制流弯曲。
  - 密钥位数有限（12 位立即数），可能被暴力猜测或碰撞，需通过增加间接层等方式增强。
- **应用范围受限**：只适用于**编译期可确定 allowlist 且运行时不改变**的敏感操作；无法保护会话密钥等动态生成的敏感值。
- **实验覆盖不足**：
  - 仅演示了前向边 CFI 一种应用，未展示其他敏感操作（如 `system()` 参数、返回地址保护等）。
  - 未进行真实攻击对抗测试，也缺少与其他硬件方案（BTI、CET）的直接基准对比。
  - 未报告对内存占用、功耗、编译时间的影响。
- **依赖系统信任**：依赖 PMP CSR 在初始化后不可篡改，以及硬件本身可信；侧信道、Rowhammer 等硬件攻击不在范围内。
- **S 模式依赖 SBI**：操作系统内核需要 SBI 协助配置 PMP，对未使用 SBI 的裸机/无 M-mode 场景可能不适用，需额外适配。
