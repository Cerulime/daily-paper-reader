## 摘要
跨处理器、内存和加速器的安全、私有多租户执行仍然是现代边缘计算系统中最重大的挑战之一。同时，内存内处理（PIM）作为一种通过将计算移至数据附近来减少冯·诺依曼瓶颈的有效方法而出现。现有的可信执行环境（TEE）仅在处理器内部建立信任，在数据穿越内存总线等不受信任的资源时保护数据。因此，无法直接在内存内执行可信计算。我们提出YAVIN，一种统一的可信计算基（TCB），将TEE扩展到处理器之外，涵盖处理器执行和一个支持可信内存内处理执行的专用内存区域，同时将内存总线视为不受信任的。利用传统TEE架构已经建立的专用受保护内存区域，YAVIN使数据能够由处理器或PIM执行解密、处理和重新加密，同时保持在TEE内。为了实现这一统一的TCB，YAVIN首次提出了LightSaber KEM后量子密码系统和ASCON-128认证加密的PIM实现，协同设计这两种算法以实现高效的DRAM执行，从而建立和维护共享的密码状态。最后，我们展示了针对张量工作负载的密码学-PIM协同设计如何重组计算，以满足认证加密施加的排序约束，同时将性能开销降至最低，并实现位切片排序以限制临时明文暴露。与最新的PIM AES实现相比，YAVIN实现了超过20倍的加速，而在执行INT8和INT32量化的边缘级LLM时，相对于明文执行仅分别产生34%和9.3%的开销。

## Abstract
Secure, private multi-tenant execution spanning processors, memory, and accelerators remains one of the most significant challenges in modern edge computing systems. Simultaneously, processing-in-memory (PIM) has emerged as an effective approach for reducing the Von Neumann bottleneck by moving computation closer to data. Existing trusted execution environments (TEEs) establish trust only within the processor, protecting data while it traverses untrusted resources such as the memory bus. Consequently, trusted computation cannot be performed directly within memory. We present YAVIN, a unified trusted computing base (TCB) that extends the TEE beyond the processor to encompass both processor execution and a dedicated memory region supporting trusted processing-in-memory execution while treating the memory bus as untrusted. Leveraging the dedicated protected memory regions already established by conventional TEE architectures, YAVIN enables data to be decrypted, processed, and re-encrypted by either processor or PIM execution while remaining within the TEE. To realize this unified TCB, YAVIN presents the first PIM implementations of the LightSaber KEM post-quantum cryptosystem and ASCON-128 authenticated encryption, co-designing both algorithms for efficient DRAM execution to establish and maintain shared cryptographic state. Finally, we demonstrate how cryptography-PIM co-design for tensor-based workloads reorganizes computation to satisfy the ordering constraints imposed by authenticated encryption with minimal performance overhead while simultaneously enabling bit-sliced ordering that limits temporary plaintext exposure. Compared to the latest PIM AES implementation, YAVIN achieves more than a 20x speedup while incurring only 34% and 9.3% overhead when executing INT8 and INT32 quantized edge-class LLMs, respectively, relative to plaintext execution.

## 1. 核心问题与整体含义（研究动机和背景）

- 现代边缘计算系统广泛采用多租户执行模式（多个用户共享处理器、内存和加速器），这带来了严峻的安全挑战。客户端数据和密钥可能暴露给不安全的操作系统、虚拟机监视器、物理攻击者或恶意租户。
- 现有安全方案存在明显两难：
  - **传统 TEE**（如 Intel SGX、AMD SEV、ARM CCA）仅信任处理器内部，数据离开 CPU 后在不可信的内存总线上以明文传输或仅由内存控制器加密，**无法在内存内部（PIM）执行可信计算**。
  - **全同态加密（FHE）** 虽然允许在密文上计算，但计算和存储开销巨大，在边缘设备上几乎不可行。
- **处理内存（PIM）** 通过将计算移至数据附近，可大幅降低数据搬运开销，但现有 PIM 缺乏与处理器 TEE 协调的统一信任机制。
- 因此，核心问题是如何在边缘多租户场景下，同时兼顾**安全可信执行**和**PIM 的高效计算能力**，使秘密数据能在内存内被解密、处理并重新加密，而不在内存总线上暴露明文。

## 2. 方法论：核心思想、关键技术细节

- **统一可信计算基（TCB）设计**：
  - YAVIN 将 TEE 从处理器扩展到 DRAM 内的专用可信内存区域，处理器和 PIM 均处于统一信任边界内，内存控制器和内存总线被视为不可信。
  - 每个租户拥有物理隔离的可信内存区域，数据可在此区域内解密、计算、重加密，明文永不经过内存总线。
- **密钥建立：LightSaber 后量子 KEM 的 PIM 实现**：
  - 采用 LightSaber（Saber 家族最轻量变体，基于模 LWR 问题），支持约 128 位后量子安全强度。
  - 关键设计：模数为 2 的幂（q=8192，p=1024），避免了复杂的模约减，适合电荷共享 DRAM 位级操作。
  - 利用 DRAM 物理不可克隆函数（PUF）产生硬件信任根，生成内存侧密钥对。
  - 通过四路并行 SHAKE-128、CBD₁₀ 采样、基于行内移位和 512 列工作区的 negacyclic 多项式乘法，实现 PIM 中的密钥生成、封装和解封装。
  - CPU 与内存侧通过 LightSaber 交换密钥，随后经 SHAKE-128 提取 128 位 ASCON 会话密钥。
- **数据保护：ASCON-128 认证加密的 PIM 实现**：
  - 选用 ASCON（NIST 轻量密码标准），其置换仅含 XOR、AND、NOT 和循环移位，非常适合位级 DRAM 计算，且天然提供认证能力（AEAD），无需额外完整性机制。
  - 320 位状态映射为 5 行 DRAM 行，每个状态字占 64 位，可在一行内并行 8 个实例，提升吞吐量。
  - 实现了完整的初始化、关联数据处理、加密、终结化流程，支持 ASCON-128 和更高速的 ASCON-128a 变体。
- **密码学与计算调度协同设计**：
  - 针对张量工作负载（如 LLM 推理），利用张量索引顺序和位级计算顺序的灵活性，将数据组织为连续的加密/解密流，满足 AEAD 的排序约束。
  - 采用位切片调度，使明文在任意时刻只暴露部分位切片，而非完整数据值，降低瞬态观测风险。
- **总体流程**：CPU 和 PIM 各持密钥对 → LightSaber 交换生成共享密钥 → ASCON 保护所有跨总线数据 → 计算可在 CPU 或 PIM 内安全进行。

## 6. 主要结论与发现

- **PRF 实现可行性**：首次在电荷共享 DRAM-PIM 中实现了 LightSaber 后量子 KEM 和 ASCON-AEAD，证明可信内存内执行在密码算法层面可行。
- **ASCON 显著优于 AES**：
  - 相比最新 PIM AES 实现，ASCON-128 在 1Mb 数据时获得约 20.4× 延迟加速和 19.2× 能量降低；ASCON-128a 更为突出（28.8× 能量降低）。
- **后量子密钥交换成本可接受**：
  - LightSaber 单次会话密钥建立（PIM 侧 KeyGen + Decaps）约 670 ms、93.9 mJ，属于一次性开销，可摊销。
- **相比 FHE 的压倒性优势**：
  - YAVIN 比 CPU-FHE 快约 4~5 个数量级，使原本不可行的安全推理变为现实。
- **LLM 推理开销可控**：
  - 在所选边缘模型中，YAVIN 加密开销在 INT8 下平均（几何均值）为 82%，INT32 下为 27.7%；对典型边缘级模型，INT8 开销 34.2%，INT32 开销仅 9.3%。
  - 开销主要来自 PIM 侧加解密，模型 GEMM 占比越高，开销被摊销得越好。

## 7. 优点

- **创新性突出**：
  - 首次构建统一跨度处理器和内存的 TEE（YAVIN），突破传统 TEE 只能信任处理器的限制。
  - 首次在 DRAM-PIM 中实现后量子 KEM（LightSaber）和认证加密（ASCON）的完整流程。
- **密码算法选择精妙**：
  - LightSaber 的 2 的幂模数天然适配 PIM 的位操作，ASCON 的纯逻辑置换适合位级并行。
  - ASCON 自带认证，省去单独的完整性硬件。
- **硬件机制利用充分**：
  - 利用 DRAM PUF 提供硬件信任根，QUAC-TRNG 提供随机性。
  - 利用 512 列宽行内并行、行内移位、一次激活三行实现多数逻辑等 PIM 原语，高度定制化优化。
- **协同设计理念先进**：
  - 将张量计算调度与 AEAD 排序约束统一规划，同时通过位切片减少明文暴露。
- **实验能展示清晰的端到端优势**：
  - 对比 FHE 和 AES，从多个维度证明了 YAVIN 在性能与安全间的平衡。
