## 摘要
模型上下文协议（MCP）自2024年11月推出以来已被迅速采用，公共互联网上可检测到超过21,000个服务器实例。我们首次对面向互联网的MCP服务器进行了动态行为安全评估，结合了跨十一个数据源（crt.sh、HuggingFace、GitHub、npm、Smithery、PyPI、Censys、FOFA、Shodan、glama.ai和pulsemcp.com）的被动发现，以及使用Corvus（一个专门构建的框架，实现了涵盖10类MCP特定漏洞的34个测试模块）进行的主动动态测试。在跨越2026年7月的四次测量中，我们确认了640个生产MCP服务器并动态审计了414个，发现了68个可报告的漏洞，包括SQL注入、针对云元数据服务的SSRF、提示模板注入以及通过游标操作的路径遍历。我们发现，91.8%的动态审计服务器缺乏OAuth认证，已确认服务器中的687个工具实例暴露了无访问控制的shell执行能力，并且41.6%的已确认服务器在连续测量运行之间的三天内消失——表明存在无安全审查的快速部署周期。我们报告了负责任披露流程，并发布了Corvus作为MCP安全评估的开源框架。

## Abstract
The Model Context Protocol (MCP) has seen rapid adoption since its November 2024 launch, with over 21,000 server instances detectable on the public internet. We present the first dynamic behavioral security assessment of internet-facing MCP servers, combining passive discovery across eleven data sources (crt.sh, HuggingFace, GitHub, npm, Smithery, PyPI, Censys, FOFA, Shodan, glama.ai, and pulsemcp.com) with active dynamic testing using Corvus, a purpose-built framework implementing 34 test modules covering 10 MCP-specific vulnerability classes. Across four measurement runs spanning July 2026, we confirm 640 production MCP servers and dynamically audit 414, uncovering 68 reportable vulnerabilities including SQL injection, SSRF targeting cloud metadata services, prompt template injection, and path traversal via cursor manipulation. We find that 91.8% of dynamically audited servers lack OAuth authentication, 687 tool instances across confirmed servers expose shell execution capabilities without access controls, and 41.6% of confirmed servers disappear within three days between consecutive measurement runs---indicating rapid deployment cycles without security review. We report on our responsible disclosure pipeline and release Corvus as an open-source framework for MCP security evaluation.

### 6. 论文的主要结论与发现（续）

- **认证缺失是结构性而非意外**：发现的380个存在认证缺陷的服务器并非零散个体，而是呈现出集群化特征——许多服务器由同一开发者、同一模板或同一部署工具链批量生成。典型模式包括：硬编码Bearer令牌（如`sk-`开头密钥直接暴露在客户端代码中）、无认证的`tools/call`端点、以及仅依赖网络层ACL（如Cloudflare WAF）但协议层完全开放。论文指出，MCP生态当前的“默认不安全”状态与早期REST API普及阶段的教训高度相似。
- **敏感能力暴露面惊人**：687个无认证shell执行工具实例意味着任意互联网用户可远程触发`exec`、`run_command`、`shell`等工具，等同于公开的RCE入口。这些工具常被包装在“开发辅助”、“运维自动化”等看似良性的MCP服务器中，但因缺少认证与授权层，实际暴露为匿名远程代码执行。
- **工具投毒/rug-pull不再是理论讨论**：47个工具投毒与rug-pull实例说明，MCP服务器的工具清单可在运行期被外部参数篡改或替换，使AI代理在毫不知情下执行被替换后的恶意工具逻辑。这直接验证了此前仅在实验室中形式化推演的“MCP供应链投毒”风险在现实生产服务器中真实存在。
- **高危漏洞分布极为集中**：68个可报告漏洞集中在少数服务器上——少数服务器同时命中多个MST-10类别。这暗示MCP生态中存在“高危供应商头部效应”：少数不成熟的开发者/项目贡献了不成比例的安全风险，而多数服务器相对“干净”，但这种长尾与头部的混合结构恰恰使得审计与治理难以规模化。
- **MCP生态处于“快速部署、缓慢治理”阶段**：纵向4轮扫描显示确认服务器数量在两周内从140增长到464再回落至296，波动剧烈，说明大量服务器是实验性、短期存活的“周末项目”；同时，已披露的19个漏洞中，部分在下一轮扫描中仍未修复，修补速度远低于部署速度。

### 7. 局限性与未解决的问题（作者承认与客观补充）

- **样本代表性偏差**：候选池依赖公共数据源（GitHub、npm、注册表聚合器等），意味着完全私有、未公开索引、或仅在内网运行的MCP服务器天然不可见。论文的结论只能代表“面向互联网、且可被公共搜索发现”的MCP子集。
- **动态探测的伦理边界**：为避免对生产服务器造成实际损害，MCP09 DoS类漏洞被整体排除。这意味着真实环境中可能的资源耗尽、无限递归、或大规模并行调用导致的故障风险未被量化。此外，测试载荷虽经设计尽量避免写入/删除，但SSRF探测中的云元数据访问仍可能产生超出预期的影响。
- **检测能力不对称**：Corvus依赖响应指纹（反射、时延、错误信息）判定漏洞，无法识别“静默失败”型漏洞——例如服务器内部成功解析了注入载荷但未回显，或SSRF实际发生了但响应被代理层吸收。因此所有计数均为确认下限而非上限。
- **纵向窗口短**：4轮扫描集中在两周内，无法刻画数月尺度的服务器生命周期、补丁节奏或攻击面演化趋势。
- **无第三方基准标签**：34个测试模块的精确率/召回率未与人工标注的黄金数据集对照，模块级误报率未知；置信度阈值（40/70）的选择缺少敏感性分析。

### 9. 对未来研究的启示与开放问题

- **MCP服务器存活率研究**：两周内服务器数量的大幅波动提示需要更长时段的纵向追踪，以识别“服务器漂移”现象（URL迁移）、生命周期分布及“死亡率”的驱动因素。
- **认证与授权方案的系统化设计**：380个认证缺陷服务器表明，简单地在协议层增加`Authorization`头不足以解决问题——需要针对MCP的工具级细粒度授权模型、OAuth 2.1/DPoP在MCP中的适配、以及无认证场景下的默认拒绝策略。
- **AI代理侧防御**：既然工具投毒和rug-pull已大规模存在，未来研究应聚焦于如何在AI代理端（而非服务器端）对`tools/list`返回结果做一致性校验、签名验证与行为基准比对，以抵御恶意或受损服务器。
- **自动化判定与人工复核的协同**：Corvus的单研究者手动验证存在瓶颈，需要引入LLM辅助漏洞确认、多观察者交叉验证以及置信度阈值的贝叶斯校准方法。
- **协议演进的安保影响**：SSE与Streamable HTTP两种传输变体在认证缺陷率上是否存在系统性差异？MCP规范未来若强制要求认证/授权层，是否会引起服务器退出互联网或转向隐蔽信道？这些均是值得跟踪的政策性研究问题。
- **跨协议迁移性**：本方法是否可直接迁移至Anthropic新发布的A2A（Agent-to-Agent）协议、OpenAI的Function Calling远程网关或其他AI代理互操作协议？协议间共享的JSON-RPC/工具描述攻击面暗示方法具有普适性，但具体指纹与测试模块需重新适配。

### 10. 总体评价与综合结论（结合理论、方法、实验与意义）

- **理论层面**：论文证明MCP不仅是一个“协议规范”问题，更是一个“生态工程实践”问题。理论研究中提出的各类攻击面（工具投毒、模式注入、SSRF、游标遍历等）在真实生产环境中全部得到实证确认——理论威胁模型不再是虚构，而是触手可及的现实风险。
- **方法层面**：被动发现+主动动态测试的设计合理避开静态分析的两大缺陷（不可见运行时状态、难以验证真实可达性），并首次将负责任披露纳入大规模测量伦理框架，是对安全测量方法论的重要完善。34个测试模块的设计深度远超同类工作的“探测存活/协议版本”式浅层扫描。
- **实验层面**：虽然有选择偏差与短窗口局限，但640个确认服务器、414个动态审计对象、68个漏洞披露的规模，在MCP安全实证领域具有开创性。其纵向设计虽然窗口短，仍初步揭示了生态的剧烈更替性。
- **实践层面**：研究发现的最重要信息不是“存在漏洞”，而是“漏洞以结构性、生产化方式存在”——例如687个无认证shell工具实例意味着互联网上存在大量实际可被匿名利用的RCE入口。这一结论对部署MCP的企业、平台运营商与协议标准化组织均构成明确警示：MCP生态目前尚不具备作为生产级AI接入基础设施的安全成熟度。
- **总体结论**：本研究以严谨的方法论、清晰的披露流程和大规模实证数据，完成了对公共互联网MCP服务器安全态势的首次“全身CT扫描”。其核心判断——**MCP生态正处于“功能先行、安全缺位”的早期阶段，结构性认证缺失与高密度的远程代码执行暴露使其成为当前互联网上最具风险的新兴攻击面之一**——具有较高的可信度，并为后续研究建立了可复用的量化基线与评估范式。
