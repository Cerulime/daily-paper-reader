## 摘要
提高系统对网络攻击抵御能力的方法变得越来越重要。控制流监控为在运行时确保完整性并检测潜在异常提供了原则性基础。一旦检测到异常，就可以使用所谓的攻击树来识别可能的攻击类型。然而，这种方法容易受到伪装的影响，攻击者通过故意操纵系统的可观察控制流，试图规避检测（以及正确识别）。在本文中，我们概述了一种基于模型的方法，通过结合软件与硬件监控的架构，提供更稳健的入侵检测和攻击识别。在该方法中，软件层面的观察用于指示可疑活动，而硬件层面的监控则对其进行更详细的独立核查，使得攻击更难伪装自身并逃脱检测。我们通过一个认证服务示例说明了该方法，该示例捕捉了一种真实故障模式：软件级观察者看到一个异常但看似无害的控制流偏差，将其映射到攻击树中的良性根因，却漏掉了真正的入侵。第二个独立的硬件控制流监控器观察到实际的转移序列，从而将攻击树的诊断从低严重性的配置或维护问题转变为高置信度的代码注入或控制流劫持。在此场景中，所提出的控制流异常检测、基于攻击树的入侵识别与基于硬件的监控相结合，不仅能提升异常检测能力，还能提高基于攻击树的网络攻击识别的诊断精度。

## Abstract
Methods to increase the resilience of systems to cyber-attacks become increasingly important. Control-flow monitoring provides a principled basis to ensure integrity and detect possible anomalies at run-time. Once anomalies have been detected, so-called attack trees can be used to identify possible types of attacks. However, this approach is vulnerable to camouflage, by which attackers try to evade detection (and correct identification) by deliberately manipulating also the system's observed control flow. In this paper, we outline a model-based approach that provides more robust intrusion detection and attack identification through an architecture that combines software- with hardware-based monitoring. In this approach, software-level observation indicates suspicious activities, while hardware-level monitoring checks them separately in more detail, making it much harder for attacks to camouflage themselves and go undetected. We illustrate the approach with an authentication-service example that captures a realistic failure mode: a software-level observer sees an anomalous but apparently harmless control-flow deviation, maps it to a benign root cause in an attack tree, but misses the true intrusion. A second, independent hardware control-flow monitor observes the actual transition sequence and thereby changes the attack-tree diagnosis from a low-severity configuration or maintenance issue to a high-confidence code-injection or control-flow hijack. In this scenario, the proposed combination of control-flow anomaly detection, attack-tree based intrusion identification, and hardware-based monitoring can improve not only anomaly detection, but also the diagnostic precision of attack-tree-based cyber-attack identification.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：现代计算系统面临的网络攻击不仅威胁数据机密性和可用性，还威胁软件执行的完整性。攻击者可能已深入系统内部试图影响执行过程，因此仅仅保护外部接口是不够的，需要在运行时提供韧性。控制流监控被认为是一种有原则基础的运行时技术，通过观察程序执行路径并对照期望模型来检测背离（异常）。
- **核心问题**：现有组合方案（控制流异常检测 + 攻击树诊断）容易受到“伪装（camouflage）”攻击。攻击者既可以操纵实际控制流使其看似合法（如隐藏在调试/维护路径中），也可以篡改软件级观测通道（如日志、追踪、插桩），使重建的控制流缺失关键恶意转移，导致攻击树将高严重性入侵误判为低严重性配置或维护问题。
- **论文含义**：提出一种结合软件级监控与硬件级监控的架构，用独立于被监控软件的硬件追踪通道提供更真实、更难篡改的控制流证据，从而提升入侵检测的鲁棒性和攻击识别的诊断精度。论文强调这是“迈向基于模型的运行时网络安全”的一步，属于初步探索性工作。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：双层监控架构——软件层观察作为“可疑活动指示器”，硬件层监控作为“独立详细核查器”。攻击者即使攻破软件环境，也很难同时、一致地篡改硬件追踪证据。
- **关键技术细节**：
  - **控制流图（CFG）**：定义合法执行模型 \( G = (V, E, v_e, V_f) \)，节点为基本块，边为允许的转移；运行时轨迹 \( \tau = v_0 v_1 \ldots v_n \) 与之比较，检测缺失或意外的块/转移。
  - **攻击树（Attack Trees）**：将攻击目标分解为子目标和具体步骤，用 AND/OR（以及顺序 AND，SAND）组合。观测到的异常作为根节点，通过树逻辑激活内部节点，形成对可能根因的诊断。诊断函数形式化为 \( D_T(F_G(\hat\tau)) \subseteq H \)，其中 \( F_G(\hat\tau) \) 是从观测轨迹提取的异常特征向量（如缺失块、意外块），\( H \) 为攻击树内部节点集合。
  - **观察通道模型**：区分软件观察函数 \( O_S(\tau) = \hat\tau_S \) 和硬件观察函数 \( O_H(\tau) = \hat\tau_H \)。正常时两者都忠实；攻击者可破坏软件通道（\( O_S(\tau) \neq \tau \)），但硬件通道被假设为基本忠实（\( O_H(\tau) \approx \tau \)）。
  - **硬件监控架构**（基于先前工作[22,23]）：包含被监控处理器（PUO）、跟踪单元（如 Arm CoreSight / Intel Processor Trace）、独立的网络安全监控引擎（含控制流重构单元、预期模型存储、执行监控单元）以及可控延迟输出缓冲器。监控引擎依据多项异常准则检查，包括：非法间接分支目标、缺失/意外的源-目标分支对、地址超出许可范围、顺序违规、循环/重复次数超限、调用/返回不匹配等。
  - **算法流程**（以示例说明）：
    1. 软件观察器生成 \(\hat\tau_S\)，提取异常特征并输入攻击树；
    2. 攻击树基于低质量证据给出误导性诊断；
    3. 硬件监控器独立生成真实轨迹 \(\hat\tau_H\)，识别非法转移（如 \(E \nrightarrow K\)）、缺失块（如 \(H\)）等特征；
    4. 使用同一攻击树重新推理，得出高置信度入侵诊断。

## 6. 论文的主要结论与发现

- **结论1**：将控制流异常检测与攻击树诊断结合时，诊断质量严重依赖于观察通道的保真度；如果软件观察被伪装/篡改，攻击树会给出低严重性的错误诊断。
- **结论2**：独立硬件监控提供更接近真实执行的控制流证据（如非法转移 \(E \to K\)、缺失 MFA 块、会话前存在遥测操纵），使同一攻击树将诊断从“维护/配置问题”修正为“高置信度代码注入/控制流劫持”。
- **结论3**：软硬件结合不仅能提升异常检测能力，更重要的是能提升攻击树识别的**诊断精度**，使系统在检测到异常后能正确分类攻击类型，进而触发针对性缓解措施（如通过延迟输出缓冲实现遏制）。
- **结论4**：该研究是迈向基于模型诊断概念用于网络安全的第一步，仍需要更严格的形式化理论。
