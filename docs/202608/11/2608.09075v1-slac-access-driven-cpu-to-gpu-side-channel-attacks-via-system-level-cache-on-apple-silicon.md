## 摘要
现代异构片上系统设计集成了共享最后一级缓存（LLC）或系统级缓存（SLC）的CPU核心和GPU。这种共享暴露了新的跨域攻击面，而针对集成平台的现有攻击要么利用粗粒度的缓存占用竞争，要么要求攻击者与受害者在GPU上共驻以获得精确的时序测量。在这项工作中，我们针对Apple Silicon异构SoC，发现GPU内存访问在共享SLC中留下集合级别的足迹，且可被非特权CPU进程观察到。这一敏锐的观察使得首次针对GPU工作负载的细粒度、访问驱动、Prime+Probe风格的CPU到GPU缓存侧信道攻击成为可能。我们首先逆向工程了Apple M1的SLC集合索引函数以及本地私有缓存与SLC之间的交互。基于这些发现，我们构建了CPrime+CProbe SLC侧信道技术，该技术以缓存集合粒度从CPU监控GPU受害者活动。随后，我们引入了一种加速变体GPrime+CProbe，其中攻击者利用GPU进行更快的SLC priming，使隐蔽信道吞吐量提高了6.4倍。最后，我们展示了使用新侧信道的两种端到端隐私攻击：一种是对图神经网络（GNN）的图边重建攻击，在五个数据集上实现了90%的边准确率；另一种是LLM隐私攻击，在TinyLlama和GPT-2 Medium模型上分别以高达94.8%的准确率恢复输入关键词和以高达88.9%的准确率恢复模型响应。我们的结果揭示了Apple Silicon中一类新的微架构漏洞，并呼吁为异构SoC设计安全的系统缓存。

## Abstract
Modern heterogeneous System-on-Chip designs integrate CPU cores and a GPU that share a last-level cache (LLC) or system-level cache (SLC). This sharing exposes a new cross-domain attack surface, and existing attacks on integrated platforms either exploit coarse-grained cache-occupancy contention or require the adversary to co-reside on the GPU with the victim to obtain accurate timing measurements. In this work, we target Apple Silicon heterogeneous SoCs and discover that GPU memory accesses leave set-level footprints in the shared SLC, observable to an unprivileged CPU process. This keen observation enables the first fine-grained, access-driven, Prime+Probe-style CPU-to-GPU cache side-channel attacks against GPU workloads. We first reverse-engineer the Apple M1 SLC set-indexing functions and the interactions between local private caches and the SLC. Building on these findings, we construct the CPrime+CProbe SLC side-channel technique, which monitors GPU victim activity from the CPU at cache-set granularity. We then introduce an accelerated variant, GPrime+CProbe, in which an adversary leverages the GPU for faster SLC priming, yielding a 6.4x increase in the covert-channel throughput. Lastly, we demonstrate two end-to-end privacy attacks using the new side-channels: a graph-edge reconstruction attack on Graph Neural Networks (GNNs) that achieves 90% edge accuracy across five datasets, and an LLM privacy attack that recovers input keywords with up to 94.8% accuracy and model responses with up to 88.9% accuracy across TinyLlama and GPT-2 Medium models. Our results reveal a new class of microarchitectural vulnerabilities in Apple Silicon and call for secure system cache designs for heterogeneous SoCs.

## 二、论文提出的方法论

- **逆向工程 Apple M1 SLC**  
  - 分析了 CPU/GPU 私有缓存与 SLC 之间的三种数据共享场景，证明 GPU 访问可以在 SLC 中留下可被 CPU 观测的足迹，且 SLC 与 CPU L2 为互斥（exclusive）、与 GPU 缓存为 NINE 关系。
  - 提出“碰撞轮廓聚类”（collision-profile clustering）方法构建 eviction set：先用 GPU 填充 SLC，再让单个测试缓存行与之竞争，从 CPU 侧记录哪些填充行被逐出，形成该测试行的碰撞轮廓；对同一 SLC 集合的地址会具有相似轮廓，据此聚类即可获得每个集合的 eviction set。
  - 基于聚类结果恢复了 M1 SLC 的 12 位集合索引哈希函数（图 4），并证明了 SLC 采用 LRU 替换策略。

- **侧信道技术设计**  
  - **CPrime+CProbe**：完全在 CPU 侧进行 priming 和 probing。  
    - 由于 SLC 对 CPU L2 是独占的，CPU 需先加载 SLC_ES（65,536 个地址）填满 L2 再逐出到 SLC，然后用 L2_ES 冲刷 L2 中残留的 SLC_ES 行，最终让 SLC_ES 占据整个 SLC。  
    - 通过固定物理地址位 7–10 为零，将 L2 集合足迹降至 512 组，减少 priming 时间（约 7 ms）。  
  - **GPrime+CProbe**：利用 GPU 并行加快 priming（约 0.7 ms），但需先用 GPU 写内核无效化 CPU 私有缓存中的陈旧副本，再用读内核将 SLC_ES 填入 SLC；探测仍在 CPU 侧（CProbe）完成。  
  - **CProbe**：从 CPU 依次测量 SLC_ES 中每个访问的延迟，记录每个 SLC 集被逐出的缓存行数（0–16），形成细粒度整数迹。

- **攻击流程（三种噪声抑制与攻击框架）**  
  - 差分追踪：基线（idle kernel）与目标迹相减，消除稳定背景噪声。  
  - 多轮平均：多次运行取均值，降低波动，用于精确的逐集合监控。  
  - 超集合聚合：将连续缓存集合分组成 superset，降低单次测量噪声，用于 LLM 攻击。  
  - 三阶段工作流：目标项列表的 profile（访问映射矩阵）→ 采集 SLC 足迹 → 将观测向量与 profile 比对恢复秘密。

- **两个端到端攻击**  
  - GNN 边恢复：通过节点特征向量的 index_select 操作在 SLC 上的足迹，先恢复单个节点的邻居（集合覆盖+剪枝），再利用无向图的对称性做全图边恢复。  
  - LLM 输入/输出恢复：  
    - 输入关键词恢复针对 prefill 阶段，利用嵌入表查表足迹与字典比对。  
    - 输出响应恢复针对自回归解码阶段，逐 token 恢复嵌入访问的超集合，再用本地 LLM 作为语言模型对候选 token 排序化解歧义。
