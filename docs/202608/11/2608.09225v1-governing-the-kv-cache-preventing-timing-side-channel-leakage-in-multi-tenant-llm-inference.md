## 摘要
键值（KV）缓存是现代大语言模型（LLM）推理中主要的吞吐量优化手段，支持跨请求的前缀复用。在多租户部署中，该缓存在租户之间共享，从而形成时序侧信道：对抗性租户可通过探测缓存命中的延迟来重建另一租户的私有提示。已发表的三类攻击（PROMPTPEEK、EarlyBird和InputSnatch）利用了该信道，在未受保护的vLLM和SGLang上攻击成功率高达100%，具体成功率因缓存架构和提示结构而异。我们提出KVGov，一个治理层，在统一机制下应对所有三类攻击的前缀缓存路径。每个主体的盐σ_p = HMAC_K(secret, principal_id)为块哈希链提供种子，使得缓存键在主体之间密码学上不相交。一项消融实验（N=1000次试验，种子2026，确定性评判）将该盐隔离为必要且充分的组件。KVGov还包含ORIGAMI，一种Stackelberg注水审计调度器，在现实的租户异质性（基尼系数0.63）下将对手期望效用降低12.6%；以及进化稳定性分析，给出31.6%的对手流行临界点，低于该临界点时全局缓存保持稳定。在真实硬件（Qwen2.5-7B-Instruct、vLLM 0.26.0、NVIDIA A100）上，我们测得经门验证的冷/缓存TTFT比为0.22，确认该信道在生产规模下可利用；防御本身则在与这些测量值校准的模拟中评估。我们在独立栈（Apple Metal上的llama.cpp，比值为0.093）上复现了该信道。最后，隔离与缓存效率并不必然冲突：标识信息仅存在于提示分叉处，因此在分叉边界而非链根注入盐，可保留约93%的前缀缓存收益，且不产生跨主体信号。

## Abstract
The key-value (KV) cache is the primary throughput optimization in modern large language model (LLM) inference, enabling prefix reuse across requests. In multi-tenant deployments this cache is shared across tenants, creating a timing side channel: an adversarial tenant can reconstruct another tenant's private prompt by probing cache-hit latency. Three published attacks exploit it -- PROMPTPEEK, EarlyBird and InputSnatch -- reaching up to 100% attack success rate against unprotected vLLM and SGLang, with rates varying by cache architecture and prompt structure.   We present KVGov, a governance layer addressing all three attack families' prefix-cache paths under one mechanism. A per-principal salt sigma_p = HMAC_K(secret, principal_id) seeds the block-hash chain, making cache keys cryptographically disjoint across principals. An ablation (N=1000 trials, seed 2026, deterministic judges) isolates this salt as the necessary and sufficient component. KVGov adds ORIGAMI, a Stackelberg water-filling audit scheduler that reduces adversary expected utility by 12.6% at realistic tenant heterogeneity (Gini 0.63), and an evolutionary stability analysis giving a 31.6% adversary-prevalence tipping point below which global caching remains stable.   On real hardware (Qwen2.5-7B-Instruct, vLLM 0.26.0, NVIDIA A100) we measure a gate-verified cold/cached TTFT ratio of 0.22, confirming the channel is exploitable at production scale; the defense itself is evaluated in simulation calibrated to those measurements. We replicate the channel on an independent stack (llama.cpp on Apple Metal, ratio 0.093). Finally, isolation and cache efficiency need not conflict: identifying information resides only where prompts diverge, so injecting the salt at that boundary rather than the chain root retains an estimated 93% of the prefix-cache benefit with no cross-principal signal.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：现代 LLM 推理引擎（vLLM、SGLang、LMCache 等）普遍使用 KV 缓存来复用已计算的前缀，大幅降低首 Token 延迟（TTFT）。在多租户部署中，该缓存被所有租户共享以获得更高的命中率与吞吐量。
- **核心问题**：缓存命中/未命中的差异可被任何租户观测为时序信号，形成一条跨租户时序侧信道。攻击者通过探测自身请求的 TTFT，即可推知受害租户的缓存状态，进而重建私有提示词。
- **已发表的攻击**：三类独立攻击均利用了该信道：
  - **PROMPTPEEK**：通过指纹相关性识别受害者的缓存提示，ASR 可达 99–100%。
  - **EarlyBird**：在块大小=1 时逐 Token 重建提示，ASR 达 100%。
  - **InputSnatch**：针对前缀缓存和语义缓存分别实现字段重建与嵌入空间探测，部分场景 ASR 43–100%。
- **根因**：缓存键仅基于 Token 序列计算，未绑定到发出请求的主体（租户/用户），导致任意租户可探测或命中其他租户的缓存条目。
- **整体含义**：多租户 LLM 服务中的共享 KV 缓存存在严重隐私泄露风险，需要一种统一、可部署的治理机制从根因上消除该侧信道，而非逐攻击打补丁。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想：以主体身份隔离缓存命名空间
KVGov 的核心是 **HMAC 键控命名空间隔离**：将缓存键的计算绑定到经过认证的主体（principal），使不同主体的缓存键在密码学上不相交，从而让跨主体的缓存探测/命中在计算上不可能。

### 2.2 关键技术细节

- **每主体盐（per-principal salt）**：
  \[
  \sigma_p = \text{HMAC}_K(\text{secret}, \text{principal\_id})
  \]
  其中 \(K\) 为服务器端机密密钥。盐 \(\sigma_p\) 作为块哈希链的种子：
  \[
  h_0 = H(\sigma_p \| \text{tokens}_{0..B-1})
  \]
  后续块按原有方式链式哈希。因为每个块继承了前驱的哈希，所以盐会传播到整个链，使所有块都具备主体特异性。每请求只增加一次 HMAC 计算开销。

- **攻击失效原理**：攻击者在自己的命名空间中探测 \(p_i\)，其缓存键与受害者的键不同（SHA256 抗碰撞），因此探测结果恒为未命中（all-MISS）。指纹向量无方差，Pearson 相关系数趋于 0，ASR 降至 0。

- **边界盐（Boundary Salting）**：为了保留跨主体的共享前缀复用，仅在提示“分歧边界”处注入盐：
  - 共享前缀块保持全局可路由；
  - 从边界块开始，将 \(\sigma_p\) 掺入哈希链；
  - 私有区域在密码学上跨主体不相交，而共享前缀仍可被所有主体复用。
  - 作者估计这种方式能保留约 93% 的前缀缓存收益（2000-token 共享前缀 + 119-token 私有尾部的场景）。

- **ORIGAMI：Stackelberg 审计调度器**：
  - 将防御者与攻击者建模为 Stackelberg 博弈：防御者先承诺对各租户的审计概率 \(p_i\)，攻击者据此选择目标以最大化收益 \(v_i(1-p_i)\)。
  - 求解注水（water-filling）问题：
    \[
    p_i^* = \max\left(0, 1 - \frac{\lambda}{v_i}\right)
    \]
    其中 \(\lambda\) 由预算约束 \(\sum_i p_i^* = K\) 二分求唯一解。
  - 该策略使所有被审计租户的攻击者收益均等化，从而不留下“软目标”。

- **演化稳定性分析**：
  - 将缓存范围选择（全局缓存 vs. 临时缓存）建模为双种群演化博弈。
  - 给出临界点公式：
    \[
    \tau^* = \frac{V_{\text{glb}} - V_{\text{eph}}}{(C_{\text{glb,eph}} - C_{\text{eph}}) + (V_{\text{glb}} - V_{\text{eph}})}
    \]
  - 在参数 \(V_{\text{glb}}=0.45, V_{\text{eph}}=0.15, C_{\text{glb,eph}}=0.70, C_{\text{eph}}=0.05\) 下，得 \(\tau^* \approx 31.6\%\)。低于该攻击者流行度时全局缓存占优，高于时临时缓存成为演化稳定策略。

### 2.3 防御范围
- 覆盖：块前缀缓存、基数树前缀缓存、精确响应缓存（均由键相等判定）。
- 不覆盖：语义缓存（按嵌入相似度判定），需另行采用按主体划分检索索引的隔离方案。

## 6. 论文的主要结论与发现

- **根因确认**：共享 KV 缓存未绑定主体身份，是三类攻击共同的根因。
- **KVGov 有效**：HMAC 盐可使三类攻击的 ASR 从 100% 降至 0%（模拟中），且是必要且充分的组件；其他组件（准入、噪声、刷新）仅提供纵深防御，无法单独消除攻击。
- **会话刷新与噪声注入仅是部分防御**：刷新后 PROMPTPEEK 仍有 19.5% ASR，InputSnatch 9.8%；噪声可破坏时序指纹但无法防止基于成员关系的攻击。
- **块大小提高不解决结构化模板攻击**：模板化提示的搜索空间从词汇表缩小到字段域（减少约 75 个数量级），且成员确认查询是 O(1) 的，与块大小无关。
- **ORIGAMI 有效**：在企业异质性（Gini=0.63）下将攻击者期望效用降低 12.6%；对抗性负载模拟中可降低 58–67% 的破坏率。
- **演化临界点**：攻击者流行度低于 31.6% 时全局缓存稳定；高于时临时缓存成为演化稳定策略。
- **硬件侧信道确认**：A100 上冷/缓存 TTFT 比为 0.22（2119 token 前缀）与 0.37（1447 token 前缀），均低于 0.40 的“破坏阈值”；独立栈（llama.cpp）比值 0.093，说明该信道源于前缀缓存本身而非特定实现。
- **隔离与效率可兼得**：在分歧边界注入盐可保留约 93% 的前缀缓存收益，同时消除跨主体信号。
- **性能开销极低**：HMAC 键派生仅增加 1.3 μs/请求，占缓存 TTFT 的 0.0041%。

## 7. 优点

- **统一防御视角**：将三类不同攻击抽象为“缓存机制暴露的 oracle + 攻击目标”的统一框架，指出根因单一，从而用单一机制统一防御。
- **理论与工程结合**：既有密码学论证（HMAC 盐的抗碰撞性）、博弈论优化（ORIGAMI）、演化博弈分析，又有真实硬件测量和可复现模拟，证据链完整。
- **严谨的实验控制**：硬件测量采用预注册门槛，排除“冷臂被缓存”等常见失败模式；使用服务器端计数器而不是客户端计时，避免网络噪声；独立栈复现增强了结论的通用性。
- **攻击与防御的深刻分析**：指出块大小保护仅对自由文本重建有效，对结构化模板和成员确认无效；提出“识别能力存在于分歧点”的思想，从而设计边界盐实现效率与隔离兼得。
- **可复现性**：所有模拟实验使用固定种子和确定性评判，明确说明不会受 Python 进程盐化影响，并承诺发布脚本。
- **性能开销核算全面**：不仅考虑延时开销，还考虑了缓存分区导致的效率代价，并给出边界盐作为缓解方案。

## 8. 不足与局限

- **ASR 实验为模拟而非真实攻防**：安全结论依赖密码学理论推断，未在真实多租户环境中验证端到端对抗行为（论文承认这一点）。
- **边界盐效率为估算**：保留 93% 缓存收益的数字是基于 149.6ms/32.8ms 等测量外推的，未在真实引擎中实现和实测；且当前引擎并不暴露边界盐所需的偏移参数。
- **语义缓存未覆盖**：KVGov 的盐机制对嵌入相似度判定的语义缓存无效，需要检索索引用例化；论文未提供该场景的实验验证，其结果仅代表对哈希键控缓存的原则性验证。
