## 摘要
在没有中央可信操作员的节点之间进行相互认证，要求每个节点持有其对等节点的参考值（预期代码度量）。将这些参考值相互嵌入节点代码的朴素方法会导致无限回归。我们将解决这一无限回归的问题称为互认证的参考值自举问题。现有解决方案通过依赖可信第三方（TTP）、外部提供的参考值或特定架构的测量机制来避免这种回归。我们转而将自举问题表示为相互不动点方程组，并通过Kleene第二递归定理求解。该构造产生的节点相互引用彼此的代码，并仅凭内置数据重建每个对等节点的精确源代码。当直接测量已部署的源文件（如Python脚本）时，节点通过将测量函数直接应用于重建的源代码来获得对等节点的参考值。当测量构建的镜像（如AWS Nitro Enclaves）时，节点则从重建的源代码中可重现地重建对等节点的镜像，并导出其参考测量值。对于第一种情况，我们开发了Python转译器PyReflect，并用它实现了一个TPM互认证概念验证（PoC）。对于第二种情况，我们开发了Nix转译器NixReflect，并将其用于一个概念验证中，其中两个Nitro Enclaves仅凭内置数据重现彼此的参考PCR。我们的解决方案与架构无关，既不需要TTP也不需要外部提供的参考值，并且无需更改即可与现有认证栈配合使用。

## Abstract
Mutual attestation among nodes with no central trusted operator requires each node to hold reference values (expected code measurements) for its peers. The naïve approach of mutually embedding these reference values in the nodes' code leads to an infinite regress. We call the problem of resolving this infinite regress the reference-value bootstrapping problem for mutual attestation. Existing solutions avoid this regress by relying on a trusted third party (TTP), externally supplied reference values, or architecture-specific measurement mechanisms. We instead express the bootstrapping problem as a system of mutual fixed-point equations and solve it by Kleene's second recursion theorem. The construction produces nodes that mutually reference one another's code and reconstruct every peer's exact source from built-in data alone. When a deployed source file is measured directly, as with a Python script, a node obtains the peer's reference value by applying the measurement function directly to the reconstructed source. When a built image is measured, as with AWS Nitro Enclaves, a node instead reproducibly rebuilds the peer's image from the reconstructed source and derives its reference measurement. For the first case, we develop PyReflect, a Python transpiler, and use it to implement a TPM mutual-attestation PoC. For the second, we develop NixReflect, a Nix transpiler, and use it in a PoC in which two Nitro Enclaves reproduce each other's reference PCRs from built-in data alone. Our solution is architecture-independent, requires neither a TTP nor externally supplied reference values, and works with existing attestation stacks unchanged.

## 1. 核心问题与整体含义（研究动机与背景）

远程认证（Remote Attestation）是 TEE、TPM、AWS Nitro Enclaves 等隔离执行环境中的关键安全机制。在标准 IETF RATS 架构中，Verifier 需要持有由 Reference Value Provider 提供的参考值，才能验证 Attester 的测量报告。然而，在**无中心可信操作员**的互认证场景（如去中心化计算平台、多个互相不信任的 enclave 服务组合、agentic AI 系统中的多组件认证）中，每个节点既是 Attester 又是 Verifier，因此每个节点都必须事先持有所有对等节点的参考值。

朴素的解决方案是在节点代码中互相嵌入对等节点的参考值，但这会陷入**无限回归**：节点 A 的代码嵌入 B 的参考值（B 代码的摘要），而 B 的代码又嵌入 A 的参考值，如此循环永无终止。作者将此问题命名为**互认证的参考值自举问题（reference-value bootstrapping problem for mutual attestation）**。

现有方案通过四种方式回避或解决此问题：依赖可信第三方（TTP）、依赖外部提供的参考值、利用架构特定的报告字段注入参考值、或利用架构特定的测量机制。这些方案要么重新引入信任方，要么绑定于特定隔离架构。本论文的目标是提出**首个架构无关、既不需要 TTP 也不依赖外部参考值的解决方案**。

## 2. 方法论

### 2.1 核心思想：将无限回归转化为互固定点方程

论文的核心洞察是：无限回归一旦被形式化，实际上是**互固定点方程组**。作者建立了三个假设：

- **(i) 程序**：节点由其源码的 Gödel 编号 e 标识，计算部分函数 φ_e；
- **(ii) 源码访问**：节点 i 的预期行为是可计算部分函数 f_i(e₁,...,e_k, −)，即可以访问族内所有节点的源码；
- **(iii) 可计算测量**：节点的测量值（参考值）是其源码的固定可计算函数。

在这些假设下，互认证节点族恰好是如下方程组的解：

φ_{e_i} = f_i(e₁,...,e_k, −)，1 ≤ i ≤ k（方程组 †）

未知数 e_i 出现在方程两侧——这正是"硬编码"方法无法终止的原因。

### 2.2 理论基础：Kleene 第二递归定理及其同时形式

- **单节点版本（定理 2.2）**：对任意可计算偏函数 f: N × Nⁿ ⇀ N，存在程序 e 使得 φ_e = f(e, −)，即程序可以使用自身源码。**均匀性条款**更强：存在可计算函数（即转译器），能将期望自身源码作为额外输入的程序自动转化为真正的自引用程序。
- **多节点版本（推论 2.3，同时递归定理）**：对任意 k 元组可计算偏函数 f₁,...,f_k，存在 k 元组索引 (e₁,...,e_k) 同时满足方程组 (†)，且可由行为的索引**统一有效地计算**。

推论 2.3 表明：在假设 (i)–(iii) 下，自包含参考值**总是可以构造**的，不需要 TTP 或宿主注入的测量。每个节点 e_i 可以仅凭内置数据计算出族内所有节点的精确代码——从而算出其参考值。

### 2.3 实现机制：PyReflect 与 NixReflect

转译器遵循定理 2.2 证明的构造性自应用模式：

1. **整体序列化**：将整个模板（所有节点的行为，其中节点 ID 代表对方源码）序列化为单一规范数据 blob（D），所有节点共享；
2. **Kleene 技巧实现自引用**：将节点 ID 出现重写为对运行时重建函数的调用；文件中嵌有 repr(D)，重建函数从 D 中获取头部、框架和所有主体，并重新生成 D 自身无法包含的那一行（DATA 行）——与经典 quine 程序相同。

生成的节点文件结构：头部 + 选择器行（SELF=‘N’）+ DATA 行（repr(D)）+ 框架 + 重写后的主体。阴影部分（头部、框架、主体）在节点间字节相同，且全部记录在 D 中。

### 2.4 两种测量场景的具体流程

| 场景 | 测量对象 | 参考值推导流程 |
|------|---------|---------------|
| 直接测量源码（如 Linux IMA、Python 脚本） | 部署的源码文件 | 重建对等节点源码 → 直接哈希 → 得到参考值 |
| 测量构建产物（如 SGX、Nitro Enclaves、机密 VM） | 构建产物（EIF、MRENCLAVE 等） | 重建对等节点源码 → 可重现构建产物（bit-for-bit）→ 应用架构测量函数 μ → 得到参考值 |

构建产物场景的关键约束是**可重现构建**：只有保证同一源码总是产生同一产物（进而同一测量值），假设 (iii) 才成立。作者用 Nix 固定所有依赖实现这一点。

## 3. 实验设计

### 3.1 PoC 一：TPM 互认证（PyReflect）

- **场景**：两节点模板（__NODE1、__NODE2），每个节点由独立软件 TPM 仿真器（swtpm）驱动，通过 tpm2-pytss 在 Docker 容器内运行。
- **流程**：节点重建对等节点精确源码 → SHA-256 哈希作为参考值 → ECDH 密钥交换 + 互认证。每个节点发送随机 nonce 和临时 ECDH 公钥；重置 PCR 并扩展自身磁盘摘要；返回由 Attestation Key（AK）签名的 TPM quote，其中 qualifying data 是对等节点临时公钥和自身 nonce 的摘要，从而将测量与会话绑定。
- **验证逻辑**：仅凭自计算参考值重放预期 PCR → 验证签名、quote 结构、PCR 摘要和 qualifying data。

### 3.2 PoC 二：Nitro Enclaves 可重现构建（NixReflect）

- **场景**：两节点模板转译为一对 Nitro Enclaves，在运行时从内置数据重建对等节点的 Nix 表达式 → 在 enclave 内可重现重建对等节点 EIF → 计算 PCR0–2。
- **工具链**：用 Nix（通过 monzo/aws-nitro-util）构建 EIF，获得 bit 级一致的 EIF 和 PCR；已在 x86_64 和 AArch64 两种实例类型上验证。
- **范围限定**：PoC 仅到派生并宣布彼此参考值为止，不重新实现既有的 Nitro Enclaves 认证流程（获取 attestation document 和验证是标准流程）。

### 3.3 成本基准（Benchmark）

- **主机**：m6g.xlarge（AWS Graviton2 ARM），4 vCPU、16 GiB RAM，Nitro Enclaves 已启用。
- **对比**：NixReflect 的两种变体——digest 变体（重建源码后直接 SHA-384 哈希，不构建）vs. rebuild 变体（完整可重现构建 EIF 并计算 PCR）。
- **每 enclave 配置**：2 vCPU、2048 MiB，一次运行一个 enclave。
- **计时方式**：从 enclave 控制台行的到达时间（entrypoint 横幅到结果标记），每次运行冷启动，调试模式暴露控制台输出。

## 6. 主要结论与发现

1. **互认证的参考值自举问题是可解的**：通过 Kleene 第二递归定理的同时形式，互固定点方程组（†）总是有解，且可统一有效地计算。
2. **自包含参考值可行**：每个节点可以仅凭内置数据重建所有对等节点的精确源码，进而计算参考值——**不需要 TTP、外部参考值或架构特定的固定点机制**。
3. **对源码直测架构**：PyReflect 实现了一个模板到互引用节点族的自动转译器，配合 TPM quote 机制的完整互认证 PoC 验证了可行性。
4. **对构建产物测量架构**：可重现构建提供源码到测量的映射；NixReflect 让两个 Nitro Enclaves 仅凭内置数据重建彼此 EIF 并派生参考 PCR0–2。
5. **运行时代价**：可重现构建的参考值派生比纯哈希慢约两个数量级（本 PoC 中约 7 秒 vs 0.07 秒），且随工作负载构建闭包增大而增长。
6. **信任模型**：构造只替换 RATS 中的 Reference Value Provider 角色（移入验证节点自身），不引入新外部方；安全性完全继承底层单向认证流程——不受该模型外攻击的保护，也不使模型内攻击成为可能。

## 7. 优点

- **理论深度与实践结合**：将图论中的无限回归问题精妙地映射为递归论中的互固定点方程，用经典定理（Kleene 1938）提供存在性和可计算性保证，且转译器实现忠实对应定理证明的构造过程——理论不是隐喻而是直接实现蓝图。
- **架构无关性**：固定点构造本身不依赖任何特定 TEE 特性，只在"测量函数"层面因架构而异——这是与 MAGE（SGX 特定）的本质区别。
- **无需修改现有栈**：不修改 SDK、签名工具、加载器或认证栈，只用现有接口——部署成本低、兼容性好。
- **解决两种测量范式**：同时覆盖直接测源码（IMA/Python）和测构建产物（SGX/CVM/Nitro）两类架构，具有广泛的适用性。
- **开源**：提供了 GitHub 仓库和完整再现环境（含精确工具链 commit），可复现性好。
- **诚实的范围限定**：明确区分可行性验证与生产级部署之间的差距，不夸大贡献。

## 8. 不足与局限

- **PoC 简化**：TPM PoC 使用用户态软件 TPM（swtpm），无硬件根信任——AK 未绑定 EK，且使用可被用户态任意重置/扩展的 PCR 23，没有 IMA 绑定实际运行程序；作者承认生产部署需改用 IMA/PCR 10 和硬件/vTPM。
- **Nitro PoC 止于参考值派生**：没有端到端验证"派生 PCR → 获取 attestation document → 验证"的完整流程。
- **实验规模小**：只有两节点族，未测试 k>2 的可扩展性；组级复杂度为 O(k²) 次握手，论文仅在讨论中将拓扑视为正交问题。
- **缺乏安全对比实验**：没有与 MAGE 等方法进行对抗性分析或性能直接对比；论文将此归为"架构区别"而非信任区别，但缺少实证支持。
- **更新代价高**：完全互认证族中任何节点变更都导致全部节点重编译、重部署——因为共享 blob 记录每个主体。论文提出了按强连通分量细化的思路但未实现。
- **运行时构建成本**：可重现构建要求 enclave 携带完整工具链（Nix 和所有锁定输入），内存占用和延迟随构建闭包增长，对复杂应用可能不现实。
- **计时精度受限**：基于控制台行的计时精度有限（digest 变体 0.06–0.07 秒接近分辨率极限），且冷启动时间（launch→entrypoint 变体间有差异）混入测量中。

**总体评价**：这是一篇理论优雅、实现扎实的可行性研究。它解决了互认证中一个根本性的自举难题，用递归论的经典工具给出了出人意料的简洁解法，并通过两个不同架构的真实 PoC 验证了构造的有效性。论文的局限主要在于实验规模（仅两节点）和缺少与现有方法的直接实证对比，这些也为后续工作留下了明确空间。
