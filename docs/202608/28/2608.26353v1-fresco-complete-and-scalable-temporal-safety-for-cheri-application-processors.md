## 摘要
CHERI 提供了硬件强制的空间内存安全。虽然先前的工作将其扩展到堆时间安全，但栈上的释放后使用（use-after-return）仍未得到解决。现有防御措施存在不足：编译器分析只能可靠地捕获作为函数返回值逃逸的引用，而动态消毒器带来的开销使其无法投入生产部署。我们提出了 FRESCO，其原理是栈能力不得比创建它的帧存活更久。FRESCO 使用每次调用的来源标识符对栈指针进行“着色”；从中派生的每个能力都继承该生命周期，并在函数退出时立即被硬件失效，无论它如何或在哪里逃逸。由于栈帧的退役频率比堆分配高几个数量级，FRESCO 通过以下方式管理由此产生的颜色压力：1）Color Saver，一种静态的、具有能力感知的逃逸分析，将着色限制在需要它的函数上，我们使用机械验证在 Rocq 中验证了其核心算法；2）能力颜色分段，将内存划分为不连续的分段，每个分段具有独立的颜色命名空间。颜色分段使栈和堆时间安全能够在同一系统上共存，使 FRESCO 成为首个为 CHERI 应用处理器提供完整且可扩展的时间安全的硬件/软件协同设计。我们在 CHERI-RISC-V QEMU 全系统模拟器和乱序 CHERI-Toooba FPGA 软核上实现了 FRESCO，并在支持 CHERI 的 Clang/LLVM 编译器和 CheriBSD 操作系统中提供了软件支持。FRESCO 系统性地防止了 NIST Juliet 测试套件和 CVE 中的释放后使用、释放后重用和双重释放，在 SPEC CPU（4% g.m.）、SQLite 和 PostgreSQL（10-14%）中仅有很小的运行时开销。

## Abstract
CHERI provides hardware-enforced spatial memory safety. While prior work extends it with heap temporal safety, stack use-after-return remains unaddressed. Existing defenses fall short: compiler analysis reliably catches only references that escape as function return values, while dynamic sanitizers impose overheads that preclude production deployment.   We present FRESCO, built on the principle that a stack capability must not outlive the frame that created it. FRESCO "colors" the stack pointer with per-invocation provenance identifiers; every capability derived from it inherits that lifetime and is hardware-invalidated the moment the function exits, regardless of how or where it escaped.   Because stack frames retire orders of magnitude more frequently than heap allocations, FRESCO manages the resulting color pressure through: 1) Color Saver, a static capability-aware escape analysis that confines coloring to functions needing it, and whose core algorithm we mechanically verify in Rocq, and 2) capability-color segmentation, which partitions memory into disjoint segments, each with an independent color namespace. Color segmentation lets stack and heap temporal safety coexist on one system, making FRESCO the first hardware/software co-design to provide complete and scalable temporal safety for CHERI application processors.   We realize FRESCO on the CHERI-RISC-V QEMU full-system emulator and the out-of-order CHERI-Toooba FPGA softcore, with software support in the CHERI-enabled Clang/LLVM compiler and CheriBSD OS. FRESCO systematically prevents use-after-return, use-after-free, and double-free across the NIST Juliet Test Suite and CVEs, with only a small run-time overhead in SPEC CPU (4% g.m.), SQLite, and PostgreSQL (10-14%).

### 1. 核心问题与整体含义（研究动机和背景）

在 C/C++ 编程中，内存安全问题一直是安全领域的核心挑战。CHERI（Capability Hardware Enhanced RISC Instructions）作为一项硬件辅助的内存安全技术，通过能力（capability）机制提供了硬件强制的**空间内存安全**。然而时间和空间是内存安全的两大维度，仅保障空间安全远远不够。

**论文要解决的核心问题是：CHERI 架构中的时间内存安全仍不完整。** 具体而言：

- **堆时间安全**已有先前工作（如 PICASSO、Cornucopia）提供了一定的防护，但**栈时间安全**（即 use-after-return 漏洞）一直被忽视。CHERI 本身无法阻止一个指向已返回函数的栈帧的悬垂指针被解引用。
- 现有的**编译器逃逸分析**只能可靠检测“直接以函数返回值形式逃逸的栈引用”这一条路径，对于通过堆对象、全局变量、线程间传递等间接方式逃逸的引用无能为力。
- **动态消毒器**（如 AddressSanitizer）虽然能检测此类问题，但其运行开销过大，无法在生产环境部署。
- 此外，CHERI 的栈帧退役频率远高于堆分配，这对基于有限颜色空间的防护机制提出了严峻挑战。

**论文的整体意义在于：** 首次提出并实现了一个**完整的、可扩展的** CHERI 时间安全硬件/软件协同设计方案 FRESCO，同时覆盖栈与堆，填补了栈 use-after-return 这一关键空白。作者强调，“部分内存安全”不是一种优雅的降级，而是留有完整攻击面的、本质上更弱的属性——一个漏洞就可能让攻击者完全控制系统。

### 2. 方法论：核心思想、关键技术细节与算法流程

#### 2.1 核心思想：栈着色（Stack Coloring）

FRESCO 的核心原则：**一个栈能力（capability）不得比创建它的帧存活得更久。**

- **基本机制**：每次函数调用时，为栈指针（csp）赋予一个唯一的“颜色”（provenance identifier）。凡是从该着色栈指针派生的能力都继承这一颜色，与所在栈帧绑定。
- **硬件失效**：当函数返回时，硬件自动将该帧对应颜色的有效位置失效（toggle PVB），从而**立刻收回所有指向该帧的能力**——无论这些能力逃逸到了何处（寄存器、堆、全局变量、其他线程）。
- **确定性防护**：任何后续通过逃逸能力对该帧内存的解引用都会触发硬件陷阱，系统性阻止 use-after-return。

#### 2.2 应对颜色压力：两个关键机制

由于栈帧退役频率远高于堆分配，直接将 PICASSO 的颜色方案应用于栈会导致颜色空间迅速耗尽。FRESCO 通过两个互补机制解决这一“颜色搅动”（color churn）问题：

**① Color Saver：能力感知的静态逃逸分析**

- 回答两个问题：
  1. 这个函数是否需要着色？（即：指向该函数栈帧的能力是否可能逃逸？）
  2. 哪些栈内存位置可能残留陈旧的、可被恢复的能力？（需要清空能力标签）
- 通过**能力流事实（Capability-flow facts）**的传播解决：`Copy(d, s)`、`Load(d, p)`、`Store(p, v)` 三类事实表示能力在指令间的流动，结合调用图分析，保守地追踪所有可能通向逃逸出口的路径。
- **核心保证**：分析不会出现假阴性（false negative），即若判定一个函数安全，则该函数帧的能力确实无法逃逸。
- 作者在 **Rocq（Coq）证明助理**中机械化验证了核心逃逸分类算法的正确性。

**② 能力颜色分段（Capability-color segmentation）**

- 将进程的虚拟内存划分为多个**不连续的分段**，每个分段拥有独立的**来源有效性表（PVT）**和独立的颜色命名空间。
- 颜色值在不同分段中不会别名冲突，由硬件通过地址中的分段位自动路由到正确的 PVT。
- 这使颜色空间从单一进程范围内约 2²¹ 个颜色，扩展到“分段数 × 每段 2²¹”个，**上限从固定位数变为可用内存**。
- 栈着色动态地将栈分成交替的“段纪元”（epoch），当一段颜色耗尽时，通过 runtime（libfresco）切换到新段；堆分配器同理在分段间分配对象。

#### 2.3 与堆时间安全的结合

FRESCO 将分段方案同时应用于堆，实现**色段化分配器**（color-segmented allocator），与 PICASSO 的堆时间安全机制兼容：

- 每一段绑定独立的 jemalloc arena，颜色从分段命名空间分配。
- malloc() 时从所在分段分配颜色；free() 时置为该颜色的 PVB，实现立即收回。
- 用**扁平位图分配器**替代 PICASSO 的 unr 分配器，消除了碎片化引起的性能与内存退化（图8显示位图分配器稳定在 1.01x 内存，unr 最高达 1.80x）。
- 堆和栈各用不同分段，互不抢占对方的颜色空间。

#### 2.4 硬件实现

- 在 PICASSO 的 PVT 机制基础上扩展了地址分段索引逻辑。
- 新增 `csealtype` 指令，原子性地置 PVT 位并使能定点失效，避免并发置位竞争和全缓冲刷新代价。
- 硬件改动在层叠上与 PICASSO 相当，逻辑增加约 +4.7%、寄存器 +6.4%、存储器 +7.65%（如表1所示）。

### 6. 主要结论与发现

1. **完整性**：FRESCO 系统性阻止了 use-after-return、use-after-free 和 double-free——所有 Juliet 坏用例均被检测到，零误报；所有复现的 CVE 与漏洞利用均被阻止。这是**首个**为 CHERI 应用处理器提供同时覆盖堆和栈的完整时间安全的方案。
2. **可扩展性**：通过能力颜色分段，可同时活跃的对象数不再受固定颜色字段位宽限制，而是由可用内存决定。omnetpp（SPEC ref）超过 200 万活跃着色分配，这是 PICASSO 单独无法完成的。
3. **低开销**：
   - SPEC CPU2006：FRESCO 完整版几何平均运行开销约 **4%**，低于 Cornucopia（约 11%）且与 PICASSO（约 5%）相当——尽管 FRESCO 多覆盖了栈。
   - SQLite：约 10%；PostgreSQL：TPS 下降 13.8%（p99 无 Cornucopia 的 300%+ 延迟尖峰）；gRPC：QPS 下降 16.7%。
   - 内存开销约 18% g.m.（SPEC），低于 Cornucopia 的 34%，略高于 PICASSO 的 8%。
4. **Color Saver 有效性**：栈段消耗减少一个数量级，代码膨胀从完整着色的 26.5% 降至 1.4%（完整版 2.0%）——证明静态分析能准确定位需要着色的函数。
5. **硬件成本**：FRESCO 硬件面积开销较小（约 5% 逻辑、6.4% 寄存器），与 PICASSO 相当。

### 7. 优点

1. **填补关键空白**：首次在 CHERI 架构上实现了对栈 use-after-return 的确定性硬件防护，使时间安全覆盖“完整”。
2. **形式化验证**：使用 Rocq 证明助理机械化验证了逃逸分类算法的核心正确性（无误报/无假阴性），提升了设计方案的安全置信度。
3. **完整工程实现**：从硬件（QEMU + FPGA）到编译器（Clang/LLVM）到操作系统（CheriBSD）到运行时（libfresco）全栈实现，非仅概念设计。
4. **"零误报"的安全记录**：在 NIST Juliet 和真实 CVE 复现中无假阳性，且系统性地检测所有 bad 案例，安全有效性有较强说服力。
5. **设计与后向兼容考虑周全**：栈着色对 ABI 透明（处理了变参函数、段切换时的参数复制等问题）；对非局部控制流（longjmp、C++ 异常）专门设计了恢复机制；对线程和 fork 做了处理。
6. **性能开销低到可部署**：在满足完整时间安全的前提下，SPEC 仅 4%、真实数据库应用 10-14% 的开销，相对现有方案（Cornucopia）不增反降。
7. **颜色分段设计优雅**：用地址高位自然路由到独立 PVT 命名空间，硬件逻辑简洁，同时自然地解决了 PICASSO 的颜色空间上限问题。

---

### 8. 不足与局限

1. **完整性声明范围有限**：作者明确承认 FRESCO 的完整性是“逃逸路径”级别的，而非“分配粒度”级别的——**帧内生命周期违规（use-after-scope）不在处理范围内**。块级生命周期没有运行时表现，需要额外的运行时制造机制才能支持。
2. **原型性能测试为单核**：虽然硬件设计支持多核，但性能评估在单核场景下进行，多核并发下的 PVT 一致性、段切换竞争等情况未得到充分实验评估。
3. **暂态执行攻击超出范围**：与 CHERI 的既有限制一致，微体系结构侧信道/瞬态执行类攻击未考虑。不过作者指出 PVB 检查在指令提交前强制，时间安全违规不会成为架构可见状态（瞬态通道仍存在）。
4. **真实世界漏洞样本偏少**：栈侧 CVE 仅 3 个真实漏洞 + 1 个 PoC，虽然有效但样本量有限；大规模实际部署中的未知漏洞模式可能无法预估。
5. **gRPC 性能偏高**：完整版 QPS 开销 16.7%，比 PICASSO（2.9%）高较多，主要是栈着色的成本。虽然整体仍可接受，但在延迟敏感的 RPC 场景下影响需要更深入优化。
6. **内存分配器集成复杂**：分段与 jemalloc 的集成在特定工作负载下可能引起 tcache 抖动（缓存反复重试换段），omnetpp 中发生 3000+ 次重试分配路径，说明现有集成存在性能退化场景。
7. **栈段切换开销未知**：虽然 Color Saver 大幅减少了段切换次数，但每次慢路径段切换的延迟/周期成本没有单独量化。
8. **适应 RV64Y 标准留作未来工作**：当前原型基于 CHERI ISAv9，论文讨论了与 RISC-V CHERI 标准化的兼容性，但尚需实际移植工作。

**一句话概括**：FRESCO 是首个为 CHERI 应用处理器提供同时覆盖堆与栈、确定性与可扩展时间安全的软硬件协同设计方案，通过栈着色与能力颜色分段，以约 4% SPEC 开销、10-14% 数据库应用开销，系统性防止 use-after-return、use-after-free 和 double-free。
