## 摘要
可信执行环境（TEE）保护敏感代码和数据免受外部干扰，但缺乏固有的内存安全性。CHERI可以在对象级别强制实施空间内存安全性。尝试使用CHERI原语建立TEE存在以下问题：（1）昂贵的能力撤销操作，（2）需要依赖宿主操作系统（OS）来支持来源跟踪和物理内存保护，（3）昂贵的域切换，以及（4）缺乏对远程证明的支持。我们引入了棱柱能力（prismatic capabilities），并提出了PRISM，一种基于CHERI的TEE架构，利用棱柱能力创建用户态飞地，同时解决这些挑战。PRISM将飞地的“色调”（标识符）绑定到物理内存访问控制中，实现了无需内存扫描的O(1)所有权建立，并支持高效域切换，可原子地激活和停用棱柱能力。此外，PRISM支持其飞地的远程证明。我们证明，在PRISM中执行用户态飞地仅产生适度的开销（≤15%），相比相同工作负载在Intel SGX下有显著改进。

## Abstract
Trusted execution environments (TEEs) protect sensitive code and data from external interference, but lack inherent memory safety. CHERI can enforce spatial memory safety at the object level. Attempts to establish a TEE using CHERI primitives suffer from (1) expensive capability revocation operations, (2) need to rely on the host operating system (OS) to support provenance tracking and physical memory protection, (3) expensive domain transitions, and (4) lack of support for remote attestation.   We introduce prismatic capabilities and present PRISM, a TEE architecture for CHERI leveraging prismatic capabilities to create userspace enclaves while addressing these challenges. PRISM binds enclave 'hues' (identifiers) in prismatic capabilities to physical memory access controls, enables O(1) ownership establishment without memory sweeps, and supports efficient domain transitions that atomically activate and deactivate prismatic capabilities. Additionally, PRISM enables remote attestation of its enclaves. We demonstrate that execution of userspace enclaves in PRISM incurs only moderate overhead (<= 15%), a significant improvement over the same workloads under Intel SGX

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：可信执行环境（TEE）虽能保护飞地代码和数据免受外部干扰，但其自身缺乏固有的内存安全性。飞地内部的内存安全漏洞（如释放后使用、缓冲区溢出）构成了极大的攻击面。
- **背景**：CHERI（能力硬件增强RISC指令）通过硬件能力在对象级别提供空间内存安全，为构建TEE提供了潜在基础。然而，先前尝试基于CHERI建立TEE的方案存在以下四项关键挑战：
  1. **昂贵的能力撤销开销**：如CHERI-TrEE需要全内存线性扫描验证独占所有权；Capstone虽免扫描但须遍历撤销树结构，二者均效率低下。
  2. **依赖宿主操作系统（OS）**：先前方案需要OS提供来源跟踪和物理内存保护的辅助，然而在威胁模型中OS本身是不可信的。
  3. **昂贵的域切换**：进出飞地需要执行重量级的上下文切换以禁用/启封能力。
  4. **缺乏远程证明支持**：无法向外部验证者证明飞地的完整性及其运行平台。
- **整体含义**：论文提出一种名为“棱柱能力（prismatic capabilities）”的新型CHERI扩展，实现对物理内存的轻量级、高效、可证明的隔离，同时保障飞地内的空间与时间安全，并支持远程证明，最终形成了名为 **PRISM** 的TEE架构。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想：棱柱能力（Prismatic Capabilities）

- **核心概念**：通过“色调（hue）”标识符（分配给飞地实例的唯一ID）和“颜色（color）”标识符（用于动态内存分配的来源ID）扩展CHERI能力。命名来源于光学棱镜将白光分为不同光谱的类比——将地址空间分割为多个隔离的域。
- **所有权绑定**：棱柱能力的`otype`字段被细分为`hue`和`color`两个子范围。`hue`由机器模式（M-mode）的可信计算基（TCB）——色调管理监视器（HMM）——在飞地创建时分配。
- **访问控制机制**：每次内存访问时，CPU硬件将能力的`hue`与硬件维护的**色调寻址内存（HAM）表**条目进行比对。HAM将连续的物理内存区域与飞地的色调标识符关联，检查在物理地址翻译后执行，确保恶意OS无法通过操控页表绕过隔离的物理内存保护。
- **O(1)所有权建立**：通过硬件查表，无需内存扫描或树遍历即可确立独占所有权（满足属性P1、P2）。

### 2.2 关键硬件组件

- **HAM（Hue-Addressed Memory）**：64项全相联表格，位于MMU与内存子系统之间。每条目66位，包含物理页基地址（52位）、页数对数（6位）、色调（6位）、有效位和活动位。采用NAPOT编码，仅需一个掩码等式比较。访问通过需匹配活动条目且能力色调与条目色调一致。
- **域切换指令**：
  - `EInvoke`：对`cinvoke`的扩展。激活对应HAM条目（设置活动位）后转移控制至飞地代码，无需陷入HMM（无陷阱）。
  - `EExit`：新非特权指令。读取当前`pcc`的色调，停用对应HAM条目然后跳转回返回哨兵地址，立即重新锁定飞地内存。

### 2.3 系统软件组件

- **HMM（Hue Management Monitor）**：极简M-mode安全监视器，是唯一能编程HAM条目、访问飞地内存（通过M-mode豁免）、管理色调和otype编码的软件。负责飞地生命周期管理（创建、测量、销毁）和报告生成。HMM的代码量很少（基线273.7KB），使用HACL*库（正式验证的密码学实现）。
- **OS（操作系统）**：特征丰富的宿主OS，假设被攻陷且恶意。
- **App与Enclave**：App为请求创建飞地的主机应用；Enclave为App地址空间中受隔离的子区域。
- **CheriBSD内核驱动**：` /dev/tee`设备，通过ioctl系统调用管理飞地生命周期（创建、销毁、认证）。内核角色被限制为最小化：分配内存、调用HMM、在HMM与用户空间之间中继能力。
- **SGX兼容层**：解析EDL文件，生成非可信（`_u`）与可信（`_t`）编组层（marshaling layers），确保主机与飞地间的数据表示一致。

### 2.4 飞地生命周期

1. **创建**：应用调用OS → OS分配连续物理内存并调用HMM → HMM分配独特色调、测量内存内容、记录色调-测量映射、编程HAM、密封代码和数据能力并返回给应用。
2. **执行（调用/返回/抢占）**：通过单个非特权硬件指令（`EInvoke`）进入飞地，HAM验证色调匹配并激活条目，无陷阱；定时器中断由HMM接管，保存飞地寄存器状态至飞地内的SSA，清空寄存器再转发给OS；通过`EExit`退出时原子性停用色调，重新锁定飞地内存。
3. **认证**：HMM构建报告，包含飞地测量值、HMM测量值、挑战值，使用设备签名密钥进行签名。
4. **销毁**：HMM将飞地内存清零、使HAM条目无效、停止色调。**色调回收**：色调隔离后被隔离（quarantine），当可用色调低于阈值时执行系统范围扫掠以撤销陈旧的棱柱能力。

### 2.5 飞地内时间安全

- 适应PICASSO的彩色能力方案至飞地场景。飞地内设**EPVT**（Enclave Provenance-Validity Table），跟踪每个动态分配对象的“颜色”有效性。
- 分配时赋予新颜色并设PVB有效；释放时置无效。硬件检查并行于色调检查。颜色耗尽时在飞地内执行撤销扫掠，仅需扫描单个飞地内存。

### 2.6 远程证明协议

- 基于质询-响应，签名密钥由HMM持有（硬件绑定），报告包含`{chal, hue, henclave, hHMM}`及签名，确保报告新鲜性、真实性和完整性。

## 3. 实验设计

### 3.1 性能基准测试

- **SPEC CPU 2006基准**：对比PRISM与PICASSO在8个整数基准（bzip2、gobmk、hmmer、sjeng、libquantum、h264ref、omnetpp、xalancbmk）上的开销。PRISM的地理平均开销为1.06倍（PICASSO为1.05倍）。

  - **SGX_SQLite**：在飞地内托管SQL数据库，使用sqllogictests的select和index_between（ib）用例。
  - **CryptoEnclave**：支持SHA256、HMAC-SHA256、AES的飞地内密码学库。

- **结果**：PRISM开销为0.72x–1.15x，SGX开销为1.67x–81.8x，PRISM显著优于SGX，尤其在频繁ECALL/OCALL和内存访问的场景。

## 6. 主要结论与发现

1. **性能有效性**：在用户态运行飞地时PRISM开销仅为基线CHERI的1.06倍左右（SPEC），对真实SGX应用而言，开销**显著低于Intel SGX**（如sgx-kmeans开销0.72x–1.13x vs SGX 3.90x–81.8x）。
2. **高效的域切换**：单一非特权硬件指令实现飞地进出，无陷入与微码干预，相比SGX的EENTER/EEXIT及AEX/ERESUME路径显著更高效。
3. **硬件成本可控**：逻辑增加约16%，寄存器增加约11%，内存增加约8%，属中等水平。
4. **安全性保证**：通过形式化验证支持远程证明协议的五项属性；实现了100%的UAF检测率和零误报；架构设计防止了恶意OS对飞地物理内存的访问。
5. **兼容性**：通过SGX兼容层可较便利地移植真实SGX飞地（修改约16–25行代码），并发现并修复多个真实应用中的潜在内存安全漏洞。

## 7. 优点

- **O(1)所有权建立**：通过HAM硬件查表实现无需内存扫描的独占所有权验证，解决先前方案的根本性效率瓶颈。
- **简化域切换**：`EInvoke`/`EExit`为无陷阱硬件操作，兼顾安全（原子激活/停用）与效率。
- **物理层隔离与虚拟内存支持**：在MMU翻译之后做检查，无需依赖OS，可防御恶意OS的页表攻击。
- **飞地内完整内存安全**：将空间安全（CHERI原生）与时间安全（EPVT）同时带入飞地，架构强制而非依赖语言或编译器。
- **切实的S-GX兼容性**：使现有SGX场景应用可运行于CHERI架构，降低了TEE迁移成本。
- **安全性具有强论证**：通过Tamarin形式化验证，包括非平凡属性的严谨数学证明。

## 8. 不足与局限

- **灵活性不足**：飞地使用单一连续物理内存区域（NAPOT），不支持动态扩容和非连续分配（虽在Discussion提出方案但未实现），导致最坏情况下的过度分配问题，存在高碎片化风险。
- **单核限制**：HAM核心本地，多核配置下需HMM同步每个核心条目，目前实现仅支持单核。
- **Hue空间有限**：默认6位色调字段，最多63个并发飞地；色调回收需全内存扫描（若在并行宿主下存在竞态风险，需额外硬件屏障）。
- **侧信道攻击不在范围**：明确排除微架构侧信道，在SGX安全性饱受攻击的背景下构成威胁模型覆盖面缺陷。
- **攻击面聚焦限制**：排除物理攻击、忽略可用性（DoS经由拒服务）等威胁类型。
- **基准客观性**：比较基准主要为FPGA模拟平台（PRISM）与x86真实硬件（SGX）之间的对比，无法完全排除平台差异影响。
- **生态不成熟**：需专用编译器工具链与OS支持，未涉及大型、成熟软件栈的迁移难度。
