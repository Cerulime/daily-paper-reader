## 摘要
现代软件系统依赖密码学进行数据保护、身份验证和信任建立，然而组织往往缺乏对源代码、配置、依赖项和密码文件中部署的密码学的结构化视图。这种可见性的缺失使安全治理和后量子迁移规划复杂化。本文提出了一种静态方法，用于发现和评估软件系统中的密码资产。我们引入了一种密码材料、密码工件和密码调用的分类，从中推导出一个可扩展的、独立于扫描器的规则库，并实现了一个应用这些规则以生成面向CBOM输出的静态扫描器。我们在一个具有已知真实基准的合成基准测试以及一个包含十个已部署服务的真实世界基础设施上评估了该方法。该扫描器在资产发现方面达到了0.75的F1分数，并正确标注了91%的预期弱点和漏洞。在真实世界设置中，它在六分钟内处理了57,610个文件，并发现了370个密码资产，包括六个与CVE关联的漏洞和52个后量子迁移候选。真实世界的覆盖率是对照手动编制的参考列表进行评估的，而非详尽列表。这些结果表明，分类驱动的静态发现可以为治理和后量子迁移规划提供实用的密码学透明度。

## Abstract
Modern software systems rely on cryptography for data protection, authentication, and trust establishment, yet organizations often lack a structured view of the cryptography deployed across source code, configuration, dependencies, and cryptographic files. This lack of visibility complicates security governance and post-quantum migration planning. This paper presents a static approach for discovering and assessing cryptographic assets in software systems. We introduce a classification of Crypto-Material, Crypto-Artifacts, and Crypto-Invocations, derive an extensible scanner-independent rule repository from it, and implement a static scanner that applies these rules to produce CBOM-oriented output. We evaluate the approach on a synthetic benchmark with known ground truth and on a real-world infrastructure of ten deployed services. The scanner achieves an F1 score of 0.75 for asset discovery and correctly annotates 91% of expected weaknesses and vulnerabilities. In the realworld setting, it processes 57 610 files in under six minutes and discovers 370 cryptographic assets, including six CVE-linked vulnerabilities and 52 post-quantum migration candidates. Real-world coverage is assessed against a manually compiled reference list rather than an exhaustive one. These results show that classification-driven static discovery can provide practical cryptographic transparency for governance and post-quantum migration planning.

- 本文的核心问题：如何系统性地定义、发现、评估软件中的密码资产，并通过轻量、可扩展的静态分析方法提供“密码学透明度”，支撑治理和 PQC 迁移规划。

### 2. 方法论：核心思想、技术细节与流程

- **总体思路**：采用设计科学研究（DSR）方法，产出四个关联工件：密码资产分类、规则仓库 Crypistry、静态扫描器 Crypsy、合成基准 Cryben。
- **资产分类（RQ1）**：
  - 发现侧分为三类：
    - **Crypto-Material（密码材料）**：以值/密钥为核心，如对称密钥、私钥、种子、令牌等。
    - **Crypto-Artifacts（密码工件）**：以结构/格式为核心，如 X.509 证书、PKCS#12 密钥库、签名容器、完整性清单等。
    - **Crypto-Invocations（密码调用）**：以使用上下文为核心，如 API 调用、协议/密码套件配置、依赖声明、库引等。
  - 评估侧分为两类：
    - **Weakness（弱点）**：基于 CWE，如使用弱算法、硬编码密钥、弱随机数等。
    - **Vulnerability（漏洞）**：基于 CVE，如特定库/版本存在已知漏洞。
- **规则仓库 Crypistry（RQ2）**：
  - 采用与扫描器实现无关的结构化规则集，分“发现规则”（Discovery Rules）和“评估规则”（Assessment Rules）。
  - 发现规则按资产类别使用不同检测方式：材料/工件规则基于文件名、格式解析；调用规则基于 AST 匹配、正则匹配、清单解析。
  - 评估规则在已发现并标准化的资产上执行，映射到 CWE/CVE。
  - 目前包含 148 条发现规则和 66 条评估规则，共 214 条规则，覆盖 Ruby、Go、TLS/SSH 配置、依赖清单以及常见密码文件格式。
- **静态扫描器 Crypsy（RQ3）**：
  - 四阶段流水线：规则加载 → 资产发现 → 资产评估 → CBOM 导出。
  - 发现阶段：文件收集、按规则分类、提取（格式解析 / AST / 正则 / 清单解析）、归一化为统一的 CryptoComponent。
  - 评估阶段：对每个 CryptoComponent 匹配弱点规则和漏洞规则，输出严重级别及 CWE/CVE 映射。
  - 导出阶段：生成 CycloneDX v1.7 CBOM，记录资产属性、证据位置和评估结果。
  - 规则与扫描逻辑彻底解耦，可通过更新 Crypistry 扩展检测能力而无需修改扫描器。

### 3. 实验设计：数据集、基准与对比方法

- **合成基准 Cryben**：
  - 覆盖 Go、Ruby、nginx 配置三类场景，包含全部 CycloneDX v1.7 中定义的密码资产类型。
  - 共有 197 个 occurrence 级 ground truth（表 3 也可见 48 个组件级资产）。
  - 用于评估“发现正确性”和“评估正确性”，并统计 Precision、Recall、F1。
- **真实世界基础设施**：
  - 10 个已部署服务，组成 3 个子系统：GitLab（含 CE、Gitaly、Runner 等）、Harbor、Mastodon、nginx、Redis、PostgreSQL 等。
  - 共扫描 57,610 个文件，覆盖 Ruby/Rails、Go、配置文件和依赖清单。
  - 扫描前通过人工检查建立部分 ground truth。
- **对比方法**：
  - 使用 CBOMkit-hyperion（PQCA sonar-cryptography 插件 v1.6.1）在 Cryben 的 Go 调用子集上进行对比，同一评估器和 ground truth 打分。

### 4. 资源与算力

- 论文**未提及任何 GPU、专用硬件或大模型训练资源**。
- 扫描器性能以单机顺序扫描方式完成：
  - 真实场景下处理 57,610 个文件，总耗时低于 6 分钟。
  - 最耗时的 GitLab CE 服务扫描 40.0k 文件耗时 207 秒。

### 5. 实验数量与充分性

- **实验组数**：
  - 合成基准：从三个类别（材料、工件、调用）细分五种场景（材料、工件、Ruby 调用、Go 调用、配置调用），报告 occurrence 级和 component 级结果。

- **充分性**：

### 6. 主要结论与发现

- 分类驱动的静态发现有效：Crypsy 在 Cryben 上资产发现 F1=0.75（P=0.87，R=0.66）；剔除 43 个“设计性计数差异”后 F1 提升至 0.86；组件级 F1 达 0.95，仅漏掉 2/48 的组件。
- 评估正确性较好：104 个发现组件中，21/23 个预期 CWE/CVE 标注正确，评估召回率 0.91，F1=0.74。
- 与现有工具对比：在 Go 调用子集上，Crypsy 的 F1（0.92）显著高于 CBOMkit（0.66）；在 CBOMkit 自身宣称覆盖范围内 Crypsy 也以 0.83 对 0.72 领先。
- 真实世界扫描结果：370 个密码资产、91 个资产获 CWE 弱点标注、6 个资产获 CVE 漏洞标注；同时识别 52 个后量子迁移候选（RSA/EC 密钥、证书、TLS 配置），全部位于 Shor 算法受影响范围。
- 主要弱点来源：CWE-338（不安全 PRNG）、CWE-295（TLS 证书校验禁用）、CWE-326（弱密码套件）。漏洞示例：易受 BEAST 攻击的 TLS 1.0 nginx 配置、Gitaly 的 Go 密码库缺陷、SSH Logjam 等。
- 结论：分类驱动的规则化静态发现可以提供实用的密码学透明度，支撑安全治理和后量子迁移规划。

### 7. 优点

- **统一分类学基础**：首次在统一模型中区分 Crypto-Material、Artifacts、Invocations，消除了文件格式与内容角色的歧义（如 PEM 文件按内容归类而非扩展名）。
- **规则/扫描逻辑解耦**：Crypistry 独立于 Crypsy，规则可通过仓库更新扩展，便于维护和社区共享，提升可持续性。
- **评估与发现分离**：先发现、后评估，CWE 和 CVE 映射可灵活更新，不干扰检测逻辑。
- **面向标准输出**：生成 CycloneDX v1.7 CBOM，便于集成现有软件供应链和治理流程。
- **基准与对比设计**：Cryben 独立构建，对比实验使用相同评估标准，结果可信；真实环境覆盖 10 个服务，具有实际参考价值。
- **透明性**：论文明确区分“设计性计数差异”和“真实检测缺口”，对 F1 分数作出详细解释，避免了简单的数字误导。

### 8. 不足与局限

- **语言覆盖有限**：仅针对 Ruby、Go 和若干配置格式；Java、C/C++、Python 等大量企业级生态未验证，影响普适性。
- **无数据流分析**：无法跟踪参数来源和使用上下文，弱算法/弱 PRNG 的标注多为“潜在”，大量结果需人工研判，行动性较低（真实场景中可操作弱点精度约 0.3）。
- **动态值检测困难**：算法标识符运行时计算时无法解析，可能漏检动态构造的密码调用。
- **PQC API 覆盖不足**：Ruby 生态缺乏 PQC 库，当前无法系统覆盖 PQC 函数调用。
- **真实场景覆盖率仅为部分清单**：未建立完整 ground truth，“100% 召回”只说明人工识别项未被漏掉，不代表穷尽覆盖。
- **扫描器可用性**：目前需手动配置扫描范围，缺少自动识别安装组件和语言模式；顺序处理大型代码库可能成为瓶颈。
- **评估方面**：与 CBOMkit 的对比仅限 Go 调用子集，尚未对 Ruby 或配置文件做同类对比；缺乏消融实验来单独评估分类、规则、扫描器各部分贡献。
