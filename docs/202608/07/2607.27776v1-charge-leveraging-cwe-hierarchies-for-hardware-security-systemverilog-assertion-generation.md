## Abstract
This paper presents CHARGE, an automated framework for generating security properties for unverified RTL modules using CWEs and large language models (LLMs). The hallmark is a reasoning process that leverages the hierarchical nature of CWE entries to improve accuracy when identifying security-critical assets in unverified RTL modules. As a result, the approach can infer expected security behaviors and generate properties from identified assets and CWE semantics, avoiding the need for trusted design specifications and reducing manual engineering effort. We evaluate the framework on the Hack@DAC18, 19, and 21 open source SoC designs using OpenAI's GPT-4.1. CHARGE detects 27 of 42 known bugs in these designs. For Hack@DAC21 OpenPiton SoC, 89% of the generated SVAs run in Cadence JasperGold FPV, and 92.2% are non-vacuous. We compare to an open-source, manually written set of properties for these designs and find that CHARGE correctly writes properties for three bugs in which the manually written properties were incorrect. In addition, CHARGE-generated properties identify a new bug in the Hack@DAC21 OpenPiton SoC that was not previously identified.

## 二、方法论

### 2.1 核心思想

- **以CWE作为"规范"**：CWE条目描述了需要避免的弱点类型，可视为安全属性的高层规范，替代不存在的设计规格。
- **利用CWE层次结构**：CWE-1000（Research Concepts）设有层级树，父节点表达更抽象的安全意图，子节点是对父节点的细化。从抽象到具体逐步引导LLM识别资产，缓解因RTL中缺失行为（即bug）导致的资产识别困难。
- **结构化3元组表示**：每个CWE条目被提取为 ⟨目标资产（target）、操作（action）、条件（condition）⟩ 三元组，连接CWE语义与SVA模板。

### 2.2 CWE分类与树构建

- 从CWE-1194（硬件设计视图）筛选可映射CWE，共覆盖**64个CWE**：
  - **可完全转换（Convertible）**：37个，安全策略可用单个3元组完全表达（如CWE-226）；
  - **部分可转换（Partially Convertible）**：27个，需额外行为推理（如CWE-1245状态机）；
  - 排除物理环境、侧信道、信息流、软件/ISA级、需协议文档等类别。
- **CWE树构建**：从每个可映射CWE沿"Child Of"关系向上追溯至根节点（支柱），仅保留Parent–Child关系；每个节点附带3元组的"资产识别"字段用于提示词构建。

### 2.3 三步框架

**Step 1：LLM支持的资产识别（最关键步骤）**
- 输入：目标CWE ID + RTL代码 + CWE层次树（JSON格式）。
- 从CWE-1000的子节点开始沿路径逐层让LLM识别候选资产，一次提示完成。
- 输出：JSON格式，分为**主要目标（primary targets）、主要条件（primary conditions）、相关资产（relevant assets）**。
- 若无法识别任何目标资产，则报告"inapplicable CWE"。
- 关键优势：虽然bug使目标CWE的直接相关行为缺失，但通过祖先节点（更抽象层面）仍能识别相关资产。例如CWE-226的缺失复位清零行为，可通过其高祖父CWE-664（资源生命周期控制）识别出msg_out为相关资产。

**Step 2：LLM支持的行为挖掘**
- 输入：Step 1识别的资产 + 目标CWE描述 + 人工设计的**策略问题**（per-CWE编写，跨RTL复用）。
- 示例问题："在什么条件下，给定资产应被清零/清除？"
- 输出：自然语言形式的安全行为列表（.txt文件），如"当复位有效时，msg_out需要被清零"。
- 明确要求LLM仅将RTL代码作为上下文参考，而非行为真值来源（避免bug被嵌入预期行为）。

**Step 3：LLM支持的SVA生成**
- 输入：Step 2的行为列表 + Step 1的资产 + SVA模板（per-CWE，JasperGold内联断言格式）。
- 要求LLM使用真实RTL信号、不生成不支持的语法（如for循环）、每个断言对应至少一个预期行为。
- 同时为每个SVA生成cover属性用于后续真空虚检查。
- 输出：.sv文件包含所有生成的SVA。

### 2.4 实现细节
- 使用OpenAI GPT-4.1 API，temperature设为0降低非确定性；
- 各步骤输出自动传递，单Python脚本实现，完全自动化；
- 代码已开源（GitHub）。

## 六、主要结论与发现

1. **端到端检测效果**：CHARGE生成的断言检测出**42个已知bug中的27个**；34个bug成功识别所需资产，29个生成了有意义的期望行为。

3. **显著优于直接提示（Baseline 0）**：

5. **发现手动属性3处错误**：Hack@DAC18 mux_func P29和Hack@DAC21 rsa_wrapper P95使用重叠蕴含算子（应为非重叠）；Hack@DAC18 periph_bus_defines P8地址范围错误。CHARGE生成的属性均正确，PR已被仓库接受。

   - 失败原因包括：CWE不匹配、RTL中缺乏证据、模块过大、LLM训练数据缺失、以及LLM被buggy RTL误导（3例）。
