## 摘要
源代码中的硬编码机密会引发严重的安全漏洞，容易被恶意攻击者利用。现有的基于正则表达式的检测方法存在根本性局限，因为机密往往缺乏可识别的模式，导致精确率和召回率较低。近期研究探索了上下文感知的检测方法，因为周围代码可以揭示候选字符串的用途。然而，这些方法面临三个关键挑战：（1）混淆鲁棒性，即模型过度依赖容易被混淆的标识符；（2）跨语言泛化困难，由于训练数据分布不均；（3）上下文冗长且嘈杂，引入过多无关标记并减慢推理速度。我们观察到，字符串作为代码语义的关键信息源，具有优越的上下文密度、混淆鲁棒性和语言无关性。基于这一见解，我们提出了StringGroup，一种新颖的上下文提取算法，用于挖掘潜在机密周围的字符串。通过对现有模式进行相对简单的修改，将分析范围缩小到字符串字面量，该方法取得了显著成效。仅使用原始上下文的33.2%，它就能保留超过80%的语义信息，并显著提高机密检测的信噪比。我们进一步设计了基于StringGroup方法和Transformer模型的上下文感知机密检测工具Secretron。在SecretBench数据集上的评估表明，其准确率很高，F1分数达到98.74%，在混淆和跨语言场景下具有很强的鲁棒性，优于最先进的基于LLM的基线方法。我们将该工具部署到真实环境中，成功从26个应用中检测出48个先前未知的密钥，证明了我们方法的实际有效性。

## Abstract
Hardcoded secrets in source code pose critical security vulnerabilities which can be easily exploited by malicious adversaries. Existing regex-based detection approaches suffer from fundamental limitations, as secrets often lack identifiable patterns, resulting in poor precision and recall. Recent studies have explored context-aware detection methods, as surrounding code can reveal the purpose of candidate strings. However, these methods confront three key challenges: (1) obfuscation robustness where models over-rely on easily obfuscated identifiers, (2) cross-language generalization difficulties due to uneven training data distribution, and (3) lengthy and noisy context that introduces excessive irrelevant tokens and slows inference. We observe that strings serve as a critical information source for code semantics, offering superior contextual density, obfuscation robustness, and language independence. Based on this insight, we propose StringGroup, a novel context extraction algorithm that mines strings surrounding potential secrets. By introducing a relatively simple modification to existing patterns that narrows the analysis specifically to string literals, the method achieves significant gains. With only 33.2% of the original context, it preserves over 80% of semantic information and significantly improves the signal-to-noise ratio for secret detection. We further design a context-aware secret detection tool, Secretron, based on StringGroup methods and Transformer model. Evaluation on the SecretBench dataset demonstrates high accuracy with 98.74% F1-score and strong robustness under obfuscation and cross-language scenarios, outperforming state-of-the-art LLM-based baselines. We deploy our tool in real-world environments and successfully detect 48 previously unknown secret keys from 26 applications, demonstrating the practical effectiveness of our approach.

  - **上下文感知方法**（基于深度学习/LLM）将候选秘密周围代码输入模型，但存在三大挑战：① **混淆鲁棒性差**——模型过度依赖易被混淆工具破坏的标识符和注释；② **跨语言泛化难**——不同语言语法差异大且训练数据分布不均；③ **上下文冗长嘈杂**——大量语法模板和无关标记稀释关键语义，降低效率和精度。
- **核心观察**：**字符串（string literals）是代码语义的关键信息源**，具有上下文密度高、抗混淆、语言无关三大优势。在云 API 调用、数据库连接等场景中，多个字符串字面量能暴露服务名、参数键、认证头等关键语义信息。
- **整体含义**：提出一种"简单但有效"的修改——将上下文分析范围**完全限定在字符串字面量**上，即可大幅提升秘密检测精度、鲁棒性与效率，并在真实环境中成功发现大量未知泄漏。

## 2. 方法论

### 2.1 StringGroup 上下文提取算法

- **核心思想**：基于程序局部性原理，以候选秘密所在行为中心，逐行向外扩展收集周围的字符串字面量，直到达到预设token容量。
- **算法流程（Algorithm 1 文字化描述）**：
  1. 候选行出发，半径 `r=0` 开始迭代扩展，同时检查第 `c-r` 行与 `c+r` 行；
  2. 对每行调用 `ExtractStrings` 提取字符串（含多行字符串压缩为单行），再经预处理和tokenization；
  3. 将tokens累加进上下文列表，直到达到目标容量 `S` 或最大半径 `R`；
  4. 保持字符串相对顺序，保留语义连贯性。
- **预处理与Tokenization**：
  1. **高熵过滤**：高熵字符串（如UUID）以 `<RND>` 专用token替换，减少噪声；
  2. **长度过滤**：去除过短单词，提高信噪比；
  3. **特殊格式识别**：用正则识别纯数字、邮箱、IP、URL等模式，附加 `<NUM>`、`<EMAIL>`、`<IP>`、`<URL>` 标记；
  4. **大小写转换与分词**：对 camelCase/PascalCase 插入空格切词，用子词tokenizer（LM tokenizer）细粒度分词。
- **候选秘密判定**：长度 >6 字符的无空格字符串字面量均视为候选秘密，保证高召回。

### 2.2 Secretron 双流融合分类器

- **整体架构**：将秘密检测建模为判别式任务——对每个候选字符串判断是否真实秘密，同时输出秘密类型标签。
- **上下文编码器（Context Encoder）**：基于Transformer-Encoder，采用 `<CLS>` token汇聚全序列语义信息，预训练权重初始化。
- **秘密编码器（Secret Encoder）**：字符级多尺度并行卷积神经网络（CNN），多个不同kernel size的并行卷积块（每块含堆叠卷积层 + LayerNorm + 激活），捕捉 `sk-`、`aws-` 等局部模式。
- **表示融合**：将上下文 `<CLS>` 表示与秘密特征拼接，经全连接层后分裂为两个head：秘密二分类（是否机密）与秘密多分类（类型如API Key、密码、Token等）。
- **训练损失**：加权交叉熵联合损失：
  \[
  L_{total} = w_1 L_{detection} + w_2 L_{categorization}
  \]
  两个任务同时优化。

## 6. 主要结论与发现

1. **检测精度显著领先**：Secretron在SecretBench上加权F1达0.9874（Ours-Acc）/0.9823（Ours-Lite），优于所有传统方法与LLM基线（最佳基线0.9420）。
2. **StringGroup高效保留语义**：仅用原始文本33.2%的长度即保留81.37%语义相似度和69.96%分布相似度；与Comment/Identifier/Syntax三类上下文提取基线比，综合排名最高。
3. **混淆鲁棒性优异**：在混淆代码上保持F1 0.9528（Lite）/0.9581（Acc），约为原始性能的97%；所有基线F1均降至0.77以下。
4. **跨语言泛化能力强**：对五种训练中未见语言达到F1 0.9290（Lite）/0.9466（Acc），显著优于基线（最高0.8605）。
5. **StringGroup是关键贡献**：集成StringGroup在多数预训练模型上稳定提升精度；而混淆重训练/微调等备选方案基本无效（F1<0.67）。
6. **真实世界检测有效**：900个Android应用中，26个应用存在48个经人工验证的真实秘密泄漏，精确率88.9%；能检测出高度混淆代码中的密钥（如Slack token）和训练集未覆盖的第三方服务（KangarooRewards）凭据。

## 7. 优点

- **洞察独到且实践验证充分**：将"字符串是语义关键载体"这一直觉形式化为系统方法，不仅实验验证，还进行了真实应用扫描。
- **方法简单而高效**：仅通过"限制到字符串字面量"这一简单修改就带来巨大收益，可迁移到现有LLM基线上提升效果。
- **双流架构设计合理**：Transformer上下文编码 + 多尺度CNN秘密编码 + 特征融合，兼顾粗粒度语义和细粒度模式，优于常见融合方案（AND/OR/加权/交叉注意力）。
- **鲁棒性优先**：针对混淆、跨语言两大现实痛点设计专门评估，结果显著优于已有方法。
- **工程实用性强**：提供Lite/Acc两种配置，兼顾CI/CD快速扫描与安全审计高精度需求；代码与数据集开源，可复现。
- **伦理性好**：真实秘密检测中未验证秘密可用性，并采用负责任披露方式通知开发者。

## 8. 不足与局限

- **字符串加密构成威胁**：强制字符串加密可破坏方法基础；作者承认VM级混淆、OLLVM扩展等高级混淆会削弱检测能力（但引用统计显示应用中极少采用）。
- **依赖正则提取字符串**：若未来语言采用新的字符串表示范式需新增提取规则（但作者指出9条通用规则已覆盖15+语言，扩展成本低）。
- **基于行的上下文提取**：以物理行为单位可能对复杂代码表示较脆弱；AST等结构化表示是未来改进方向。
- **依赖源码级可用性**：分析闭源应用需先反编译，效果受反编译器质量限制；作者将字节码级语义提取列为未来工作。
- **真实世界评估局限**：无法获得绝对recall（缺少完整真值），只能比较相对检出量；标注依赖人工判定，存在一定主观性。
- **伦理披露不完整**：检测到48个真实秘密后仅称"负责任披露"，未提供具体披露流程、响应率和修复情况，披露闭环效果未知。
- **基线时效性**：对比的LLM基线（CodeLLaMA-7B、GPT-2）参数量级较小，未与更新的闭源或更大开源模型（如GPT-4、Claude）直接比较；虽受算力约束可以理解，但影响"优于SOTA LLM"论断的时效性。
- **测试集分布**：SecretBench本身集中于GitHub开源项目，跨语言测试语言样本量偏少（Swift仅0.40%），对较低频语言的结论置信度有限。
