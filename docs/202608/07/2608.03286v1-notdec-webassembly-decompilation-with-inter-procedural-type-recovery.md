## 摘要
随着WebAssembly在浏览器、容器、物联网设备和无服务器平台中得到广泛支持，并日益被采纳为通用的低级字节码标准，审计其隐藏漏洞和恶意意图变得至关重要。反编译现有的WebAssembly模块可以帮助安全研究人员和最终用户理解二进制行为，但当前工具存在输出冗长、可读性差和类型恢复有限的问题。我们提出了NotDec，一个先进的WebAssembly反编译框架。NotDec扩展了WebAssembly类型检查算法，将字节码提升为基于SSA的中间表示，应用过程间类型恢复算法Retypd，结合指针和数值区分方法来恢复复杂数据结构，并利用Memory SSA以及保持语义的结构化控制流分析来生成可读、语义一致的C代码。NotDec在所有5,241个Juliet样本和所有Howard数据集程序上实现了100%的重新编译成功率，显著优于包括Ghidra（45.95%成功率）在内的基线方法。在类型恢复准确性方面，NotDec恢复了真实世界程序中85.33%的结构体成员访问，远超Ghidra的9.24%。虽然完整的过程间版本在大型二进制文件上面临可扩展性挑战，但过程内变体NotDec_F展现了卓越的效率，在未优化的二进制文件上消耗不到Ghidra一半的内存，执行时间减少高达97%。

## Abstract
With WebAssembly widely supported in browsers, containers, IoT devices, and serverless platforms and increasingly adopted as a universal low-level bytecode standard, auditing its hidden vulnerabilities and malicious intentions has become critical. Decompiling existing WebAssembly modules can help security researchers and end users understand binary behavior, but current tools suffer from verbose result, poor readability, and limited type recovery.   We present NotDec, an advanced WebAssembly decompilation framework. NotDec extends the WebAssembly type checking algorithm to lift bytecode into an SSA-based IR, applies the inter-procedural type recovery algorithm Retypd with pointer and numeric value differentiation methods to recover complex data structures, and leverages Memory SSA alongside semantics-preserving structured control-flow analysis to emit readable, semantically consistent C code.   NotDec achieves 100% recompilation success rate on all 5,241 Juliet samples and all Howard dataset programs, significantly outperforming baselines including Ghidra (45.95% success rate). On type recovery accuracy, NotDec recovers 85.33% of struct member accesses in real-world programs, vastly exceeding Ghidra's 9.24%. While the full inter-procedural version faces scalability challenges on large binaries, the intra-procedural variant NotDec_F demonstrates superior efficiency, consuming less than half of Ghidra's memory and up to 97% less execution time on unoptimized binaries.

### 1. 论文的核心问题与整体含义

**研究动机：**
- WebAssembly（Wasm）已从单纯的 Web 性能加速技术演变为通用低级字节码标准，被广泛用于浏览器、容器、物联网设备、无服务器平台等场景。

- 对 Wasm 模块进行安全审计已成为关键需求，但源代码通常不可见或不可信，反编译是理解二进制行为的实用路径。

**现有挑战（三个核心问题）：**
1. **操作数栈问题**：Wasm 的操作数栈模糊了指令间的 use-def 关系，且严格的类型检查机制限制了代码转换与优化，阻碍后续分析。
2. **类型恢复困难**：Wasm 线性内存无类型且不可寻址聚合类型，导致局部变量和自定义结构体类型信息丢失严重，类型推断需跨函数进行。
3. **语义一致性难题**：从 SSA IR 转回非 SSA C 代码时，内存读取表达式可能已被后续写入更新，如何简洁且正确地处理"读取旧值"的问题需要精细机制。

**整体意义**：NotDec 是首个系统性解决上述挑战的完整 Wasm 反编译流水线，显著提升了反编译代码的可读性、语义保真度和类型恢复精度，为 Wasm 安全审计提供了高效可靠的工具支撑。

### 2. 方法论

NotDec 采用三阶段架构，类似编译器的前后中端划分：

**（1）前端：代码提升（Code Lifting）**
- **核心思想**：扩展 Wasm 规范的类型检查算法，利用操作数栈的静态确定性，将基于栈的字节码转换为基于寄存器的 SSA 形式 IR（LLVM IR），暴露 use-def 链。
- **具体处理**：
  - 变量指令（`local.get/set`、`global.get/set`）→ 映射为内存读写；
  - 内存指令（`i32.load` 等）→ 映射到全局字节数组的访问；
  - 控制指令 → 转换为标准控制流图，`br_table` 转为 `switch`；
  - 间接调用（`call_indirect`）→ 通过全局函数指针数组解析；
  - 向量指令 → 生成对应 SIMD 指令。

**（2）中端：优化与类型恢复（Optimization & Type Recovery）**

包含三个子步骤（图 2 可见详细流程）：

- **预优化与低级模式识别**：
  - 先应用编译优化消除冗余（对未优化二进制效果显著）；
  - 模式识别两类关键模式：① 栈分配识别：将栈指针调整（如 `sp -= 80`）替换为显式 `alloca` 栈空间分配，使局部变量内存对类型分析可见；② memcpy/memset 模式还原：将连续的定长 load/store 序列折叠为单个 `memset`/`memcpy` 内联调用，避免误导类型推断。
  
- **全上下文敏感多态类型推断**（基于 Retypd 算法，并引入 PNDiff 增强）：
  - **PNDiff（指针/数值区分）**：构建 PNDiff Graph，每个程序值为节点，标注 Ptr/Num/Unknown/Non-PN 四类；通过种子初始化、节点合并（赋值与等值比较）、约束收集（加减指令三元组）、规则迭代传播（表 1 和表 2 的推理规则）来区分指针与数值。例如：`Ptr + Num → Ptr`，指针减法要求被减数与差为指针时减数必为数值，等式关系可推出额外约束等。
  - **约束图构建**：每个值映射为节点，按指令语义建边（赋值→子类型边；load/store→"recall load/store"边；指针加法→"recall offset"边）。
  - **自底向上摘要生成**：按调用图（SCC 折叠为 DAG）自底向上生成函数摘要，描述被调函数对调用者类型的影响。
  - **自顶向下类型传播**：从调用者收集实际传入类型，合并推导最精确的参数类型（如将 `char*` 提升为 `linkedBuf*` 子类型）。
  - **Sketch 生成与 C 类型转换**：收集指针偏移边和内存读写边，恢复自定义结构体定义与字段布局。

- **栈 SROA 与后优化**：将函数整个栈空间（视为一个大结构体）通过 Scalar Replacement of Aggregate（SROA）分解为独立局部变量；分解后暴露的新优化机会再应用一次编译优化。

**（3）后端：控制流结构化与 C 代码生成**
- **Memory SSA 处理内存读取**：为平衡正确性与可读性，对每个 load 节点向 Memory SSA 查询"该内存位置自上次加载后是否被修改"；若被修改则引入临时变量保存旧值，否则直接内联表达式。在不确定时保守假设别名并插入临时变量，保证语义正确。
- **结构化控制流分析**：采用语义保持的结构化算法将 CFG 转换为 C 的 `if/while/do-while/switch` 语句，避免 goto 泛滥。

1. **完整的流水线设计**：前端（提升 SSA）、中端（优化+类型恢复）、后端（结构化+生成），模块化清晰，各部分可独立复用。
2. **系统集成成熟技术**：巧妙地将编译器优化（LLVM passes）、SROA、Memory SSA 等编译技术应用于反编译场景，思路新颖且实践有效。
3. **PNDiff 创新**：针对"指针 vs 数值"区分这一传统二进制分析的难点，设计了基于图约束传播的简洁有效方案（表 1 + 表 2 的推理规则），弥补了 Retypd 直接应用的鸿沟。
4. **可扩展性权衡**：提供完整过程间分析（NotDec）和过程内变体（NotDec_F），让用户根据二进制规模灵活选择精度与效率的平衡点。
5. **语义保真**：Memory SSA 的使用既避免了过度临时变量带来的代码膨胀，又在不确定时保守插入临时变量，保证语义绝对正确。
6. **实证充分**：大规模评测（5,241 + 10 个二进制）、多维指标（成功率、时间、内存、重编译、LoC、类型准确率）、消融实验设计合理，结论可信度高。
7. **开源可复现**：代码已在 GitHub 公开，利于社区使用和进一步改进。

### 8. 不足与局限

**实验覆盖的局限：**
- **语言覆盖有限**：所有基准均从 C 代码编译而来；作者在讨论中指出对 Rust/Go 需要额外的模式匹配和定制后端，但未做实验验证。
- **O0/O3 覆盖不完全**：Howard 数据集中完整 NotDec 有 6 个 -O0 场景超时未完成，部分对比数据缺失（表 6 中 NotDec 列的 "-"）。
- **人工验证样本量有限**：类型恢复准确性的人工检查仅覆盖 319 个函数，对大型真实程序的验证相对稀疏。

**方法层面的局限：**
- **不支持间接调用**：类型恢复对 `call_indirect` 无法解析目标，影响类型推断精度，需要结合函数指针分析解决（作者已承认）。
- **启发式依赖**：栈分配识别依赖全局栈指针的存在；memset/memcpy 模式匹配在 LTO 内联后可能失效；变长参数检测可能不完整，需要人工更新模式。
- **PNDiff 信息不足**：当 PNDiff 无法识别某些指针运算时，结构体成员提示会缺失，需用户手动补充指针/数值信息。
- **Memory SSA 过度近似**：别名分析保守可能导致不必要的临时变量插入（虽不损害正确性，但影响简洁度）。
- **可扩展性瓶颈**：Retypd 类型恢复算法的时间复杂度为 O(n³)，过程间分析呈指数级增长，大型二进制必须降级到过程内分析，功能上有取舍。
- **抗混淆能力弱**：仅能处理简单

**抗混淆能力弱**：仅能处理简单的栈指针识别和模式匹配，对经过混淆、控制流平坦化、虚假控制流等处理的 Wasm 二进制，类型恢复和结构化的准确性可能显著下降，因为现有算法依赖可辨识的编译器生成模式。

此外，**工具可比性研究留给读者**：对于 Ghidra/WaDec/WasmDec 的扩展能力、插件生态、更新频率等未做深入评估；仅以默认配置对比。

**对整体意义的反思**：尽管存在上述局限，NotDec 在通用 Wasm 反编译任务上已表现出显著优势，通过模块化设计将类型恢复与结构化分离，为后续研究提供了良好的基础框架。

### 9. 个人评价与适用场景

**个人评价：**
- 该论文选题切中安全审计的实际需求，将传统反编译领域的类型恢复算法（Retypd）成功适配到 Wasm 的独特类型系统与线性内存模型，属于“旧方法、新场景”的典型应用，且做了必要的创新（PNDiff、模式识别、Memory SSA）。
- 实验设计整体严谨，对效率、有效性、消融等均有覆盖；尤其在重编译成功率和类型恢复准确率上以绝对优势超越基线，说服力强。
- 不足之处在于可扩展性瓶颈导致完整过程间变体在大型真实程序上超时，削弱了其作为“通用工具”的宣称；但过程内变体 NotDec_F 依然实用。

**适用场景：**
- 安全分析人员对小型/中等规模 Wasm 模块做漏洞审计、恶意行为分析时，利用 NotDec 获得可读且语义正确的 C 代码；
- 编译器开发者或研究人员需要将 Wasm 反编译到可移植 C 的转换研究；
- 教学或审计场景中，需要快速获得比字节码更易于理解的伪代码。

### 10. 未来研究方向（基于论文讨论）

作者未单独开辟“未来工作”章节，但从讨论与局限可自然推导：
- 结合函数指针分析以支持 `call_indirect` 的精确解析；
- 扩展对 Rust/Go 等语言 Wasm 产物（如自定义段、不同栈使用模式）的适配；
- 改进类型恢复算法的时间复杂度，或引入并行/增量计算以扩展到大型二进制；
- 加强抗混淆能力，与反混淆预处理结合；
- 将 Memory SSA 的保守近似替换为更精确的别名分析，减少冗余临时变量。

### 11. 总结

NotDec 是一套完整的 WebAssembly 反编译流水线，通过代码提升、优化与类型恢复、结构化生成三个阶段的系统协作，解决了操作数栈模糊、类型信息丢失、SSA 转 C 语义保持等关键问题。其在 Juliet 与 Howard 基准上的实验表明，与 Ghidra、WaDec、WasmDec 相比，反编译效率更高（15.9 倍快于 Ghidra）、重编译成功率 100%，类型恢复准确率达到 82.76%，且代码简洁性更优。虽然存在可扩展性与语言覆盖的局限，但其模块化设计和启发式方法为后续 Wasm 反编译研究奠定了坚实基线。论文代码开源，证据充分，是安全逆向领域近期一篇有价值的系统论文。
