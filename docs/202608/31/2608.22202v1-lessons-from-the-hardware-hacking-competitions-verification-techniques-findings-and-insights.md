## 摘要
硬件黑客竞赛已成为评估复杂片上系统（SoC）设计中安全弱点的实践平台，同时促进了安全感知验证和工具开发。本文通过开放式硬件黑客竞赛，对SoC安全验证进行了一项系统性研究，聚焦于实际漏洞分析策略、观察到的发现以及安全感知验证的经验教训。我们提出了一种多策略漏洞分析方法，结合了基于仿真的验证、形式化验证、lint分析、大语言模型（LLM）辅助的缺陷检测以及覆盖引导的混合模糊测试。通过对代表性漏洞发现的分析，展示了不同技术如何揭露互补类别的安全缺陷，并得出了面向硅前安全验证的实践教训。最后，我们讨论了竞赛基准如何支持新兴硬件安全技术的可复现评估，并指导未来安全感知的电子设计自动化（EDA）研究。

## Abstract
Hardware hacking competitions have emerged as practical platforms for evaluating security weaknesses in complex System-on-Chip (SoC) designs while promoting security-aware verification and tool development. This paper presents a systematic study of SoC security verification through open-box hardware hacking competitions, focusing on practical vulnerability analysis strategies, observed findings, and lessons for security-aware verification. We present a multi-strategy vulnerability analysis methodology, combining simulation-based verification, formal verification, lint analysis, Large Language Model (LLM)-assisted bug detection, and coverage-guided hybrid fuzzing. Representative vulnerability findings are analyzed to illustrate how different techniques expose complementary classes of security flaws, and we derive practical lessons for pre-silicon security verification. Finally, we discuss how competition benchmarks can support the reproducible evaluation of emerging hardware security techniques and guide future security-aware EDA research.

## 论文提出的方法论

论文提出一套多策略漏洞分析方法（multi-strategy vulnerability analysis），核心思想是让不同验证技术从互补视角生成候选漏洞，再通过独立证据交叉验证，降低误报率。具体包含以下策略：

- **分析工作流（四阶段）**：
  1. 搭建设计环境，执行仿真、形式化、lint等基线流程；
  2. 各分析方法生成漏洞候选；
  3. 人工审查排除工具误报、无效假设和重复发现；
  4. 用定制测试或形式化轨迹复现确认，映射到CWE并文档化安全影响。
- **仿真验证（Simulation-Based Verification）**：利用Synopsys VCS + DVSim框架，通过HJSON配置层自动化执行smoke/regression测试，检查失败用例、断言违例、超时和异常状态转换。
- **形式化验证（FPV与FSV）**：将安全需求翻译为SystemVerilog断言进行穷尽检查；形式化安全验证（FSV）用于检测安全敏感源到未授权目的地的信息流泄露。
- **RTL Lint分析**：使用Synopsys VC SpyGlass Lint筛查结构性和编码问题，优先关注涉及关键寄存器、特权校验、错误逻辑和状态机的告警，但需结合RTL审查和仿真确认。
- **LLM辅助漏洞分析**：先将SoC按安全相关区域分解，再基于设计上下文筛选相关CWE类别，引导LLM做CWE定向缺陷分析，生成的断言（SVA）需经语法和语义验证，并用传统EDA工具确认。
- **混合模糊测试（Hybrid Fuzzing）**：先分析覆盖率数据库找出未探索区域，LLM据此生成定向SVA或测试约束，验证后融入fuzzing循环引导输入生成，提高硬核可达区域的覆盖率。
- **定制Exploit开发**：基于漏洞描述，LLM辅助定位RTL和验证组件，生成UVM序列或SVA以复现漏洞（如UART的lsio_trigger_o错误断言、HMAC的WIPE_SECRET错误触发），通过仿真输出验证。

## 主要结论与发现

- 不同验证技术暴露互补类别的安全缺陷，**单一方法不足以覆盖所有SoC安全弱点**。
- 仿真适合复现可执行的攻击序列；形式化验证适合时间属性和难以到达的状态；lint提供可扩展的结构筛检；信息流分析直接检测机密性和完整性违背；LLM辅助可有效定位候选漏洞和生成安全属性。
- **安全意图（security intent）是关键前提**：判断功能失败是否为安全漏洞，需要先明确受保护资产、信任边界、特权规则和安全预期行为。
- **自动化发现必须独立验证**：lint告警、LLM假设、断言失败和fuzzing异常只能作为候选，需通过仿真轨迹、形式化反例、信息流路径或定制exploit复现确认。
- **跨层分析对SoC级漏洞不可或缺**：许多漏洞需要寄存器事务、固件操作、特权状态等跨模块交互才能触发。
- 现有验证基础设施需要安全导向的增强：功能覆盖率不能直接衡量安全关键状态和对抗场景的探索充分性。

## 优点

- 提出了一套完整的从环境搭建、威胁建模到exploit开发、根因分析的系统化工作流，实用性强。
- 技术组合全面且互补，从动态仿真、形式化验证、静态分析到LLM辅助和混合fuzzing，覆盖面广。
- 强调交叉验证和独立复现，降低LLM和静态工具带来的误报风险。
- 将竞赛产出转化为可复用benchmark（漏洞设计、已知bug集、安全属性、测试环境），有利于学术社区可复现评估。
- 对LLM在硬件安全中的应用路径进行了合理设计：LLM负责任务分解、CWE筛选和属性生成，而EDA工具负责语义验证，分工合理。

## 不足与局限
