## 摘要
硬件黑客竞赛已成为评估复杂片上系统（SoC）设计安全弱点的实用平台，同时促进安全感知验证和工具开发。本文通过开放式硬件黑客竞赛对SoC安全验证进行了系统研究，重点关注实际漏洞分析策略、观察到的发现以及安全感知验证的教训。我们提出了一种多策略漏洞分析方法，结合了基于仿真的验证、形式化验证、lint分析、大语言模型（LLM）辅助的缺陷检测以及覆盖引导的混合模糊测试。通过分析具有代表性的漏洞发现，我们阐明了不同技术如何暴露互补类别的安全缺陷，并得出了面向预硅安全验证的实用教训。最后，我们讨论了竞赛基准如何支持新兴硬件安全技术的可复现评估，并指导未来的安全感知EDA研究。

## Abstract
Hardware hacking competitions have emerged as practical platforms for evaluating security weaknesses in complex System-on-Chip (SoC) designs while promoting security-aware verification and tool development. This paper presents a systematic study of SoC security verification through open-box hardware hacking competitions, focusing on practical vulnerability analysis strategies, observed findings, and lessons for security-aware verification. We present a multi-strategy vulnerability analysis methodology, combining simulation-based verification, formal verification, lint analysis, Large Language Model (LLM)-assisted bug detection, and coverage-guided hybrid fuzzing. Representative vulnerability findings are analyzed to illustrate how different techniques expose complementary classes of security flaws, and we derive practical lessons for pre-silicon security verification. Finally, we discuss how competition benchmarks can support the reproducible evaluation of emerging hardware security techniques and guide future security-aware EDA research.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：传统系统安全建立在“硬件可信”的假设之上，但 Meltdown、Spectre、电源/故障注入等攻击证明硬件设计缺陷会完全瓦解软件层隔离。硬件 RTL 或门级网表中的漏洞在流片后极难修复，因此业界强调在**预硅（pre-silicon）RTL 设计阶段**尽早发现安全弱点（即“shift-left”策略）。

### 2. 论文提出的方法论

论文提出了一种**多策略漏洞分析方法论**，应用于 OpenTitan SoC 的 RTL 安全分析，核心流程如下：

- **整体分析工作流（四阶段）**：
  1. **环境建立与基线执行**：构建设计环境，运行测试/形式化/lint 流程获取基线。
  2. **候选漏洞生成**：通过各分析策略生成漏洞候选。
  3. **候选审查与去重**：排除工具误报、无效假设和重复发现。
  4. **确认与复现**：用自定义测试或形式化反例复现漏洞，映射到硬件 CWE，记录安全影响和缓解措施。
  - 各策略**不是独立实验**，而是交叉验证：如失败回归测试→可疑状态→断言→形式化验证；lint 警告→仿真验证；LLM 生成的属性→形式化检查。

- **具体技术方法**：
  - **基于仿真的安全验证（Simulation-based Verification）**：利用 Synopsys VCS 与 OpenTitan DVSim 框架，通过 HJSON 配置文件自动化执行回归测试，分析仿真日志和波形，定位时钟周期级别偏差。
  - **形式化属性验证（FPV）与形式化安全验证（FSV）**：FPV 将安全需求转为断言（SVA），用 VC Formal 检查；FSV 定义受保护源与非法目的地，检测跨安全域的未授权信息流。
  - **RTL Lint 静态结构分析**：用 Synopsys VC SpyGlass Lint 构建各 IP 模块，结合模块安全功能上下文判断警告是否构成安全弱点，排除单纯代码风格问题。
  - **LLM 辅助漏洞分析**：流程包括——（1）按安全资产/控制信号（密钥、权限、生命周期、调试授权等）进行安全感知设计分解；（2）根据模块功能语境识别候选硬件 CWE；（3）CWE 引导的定向 RTL 缺陷分析；（4）针对候选漏洞生成安全断言，再经 EDA 工具验证语义正确性。采用预训练 GPT-4o 作为基线 LLM。
  - **混合模糊测试（Hybrid Fuzzing）**：覆盖引导硬件模糊测试收集覆盖率数据库，将未覆盖区域提供给 LLM，生成定向断言、测试场景或输入约束，回注到模糊测试循环以探索难以触达的设计区域。
  - **自定义 Exploit 开发**：将漏洞描述和项目目录结构提供给 LLM，自动定位相关 RTL/验证模块，生成 UVM 扩展序列或独立测试，集成后运行仿真确认漏洞被复现。

### 6. 论文的主要结论与发现

- **多策略互补性**：仿真适合复现可执行攻击序列；形式化适合时序属性和难以触达状态；静态分析提供大规模结构筛选；信息流分析直接检测机密性和完整性违规；LLM 辅助可加速候选生成和属性编写。不同技术暴露互补类别的安全缺陷，单一方法远不足以覆盖全部 SoC 安全弱点。
