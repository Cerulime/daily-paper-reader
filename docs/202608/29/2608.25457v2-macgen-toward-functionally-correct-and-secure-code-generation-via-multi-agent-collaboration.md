## 摘要
尽管大语言模型在代码生成方面表现出强大的能力，但它们往往无法生成安全的代码，因为其输出经常包含安全漏洞。安全代码生成本身就具有挑战性，因为它需要解决一个多目标问题：功能正确性和安全性。现有方法通过注入外部安全知识或使用智能体反馈和迭代优化来应对这一挑战。然而，指南检索往往让生成器将通用建议转化为特定任务的安全实现，而共享对话的多智能体反馈可能会模糊角色边界并遭受上下文膨胀的问题。我们提出了MACGen，一个多智能体框架，它整合了规划、安全分析、代码综合和优化，以联合优化安全性和功能性。规划器构建逐步计划以满足功能需求。安全顾问识别可能的CWE并综合任务特定指南，然后编码器生成基于这些产物的代码，评审者发布视角分离的反馈。每个智能体仅接收上游阶段的结构化产物，而非共享完整的对话历史，从而强化角色专业化并减少不受控制的上下文增长。在CWEval和BaxBench上，MACGen相比直接提示，平均将F&S@1分别提高了19.61和10.57个百分点。

## Abstract
Despite their strong ability to generate code, large language models often fail to produce secure code, as their outputs frequently contain security vulnerabilities. Secure code generation is inherently challenging because it requires solving a multi-objective problem: functional correctness and security. Existing approaches address this challenge by injecting external security knowledge or by using agentic feedback and iterative refinement. However, guideline retrieval often leaves the generator to translate generic advice into task-specific secure implementations, while shared-dialogue multi-agent feedback can blur role boundaries and suffer from context bloat.   We present MACGen, a multi-agent framework that integrates planning, security analysis, code synthesis and refinement to jointly optimize security and functionality. A planner constructs a step-by-step plan to satisfy functional requirements. A security advisor identifies likely CWEs and synthesizes task-specific guidelines, a coder then generates code grounded in these artifacts, and a reviewer issues perspective-separated feedback. Rather than sharing full dialogue histories, each agent receives only structured artifacts from upstream stages, enforcing role specialization and reducing uncontrolled context growth. On CWEval and BaxBench, MACGen improves F&S@1 over direct prompting by 19.61 and 10.57 percentage points (pp) on average, respectively.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：尽管大语言模型（LLMs）在代码生成方面表现出强大能力，但其生成的代码常常含有安全漏洞，无法同时满足**功能正确性**与**安全性**这两个目标。
- **现有方法不足**：
  - **知识注入方法**（如检索增强生成）：所注入的通用安全指南缺乏任务特定上下文（如变量名、函数签名、控制流），生成器仍需自行将通用建议转化为具体实现，没有从根本上解决任务适应性难题。
  - **共享对话式多智能体方法**（如 INDICT）：多个评审智能体共享完整对话历史时，容易产生**角色干扰**——例如功能评审智能体看到安全评审意见后，偏离自身职责去关注安全问题，从而遗漏关键的功能逻辑错误。此外，共享对话导致**上下文膨胀**，增加延迟和token成本，并引发长上下文性能退化。
- **研究意义**：论文指出，有效的安全代码生成不仅需要更多知识或更多反馈，更需要在**接口层**而非仅仅在提示词层上明确各角色的分工与信息边界。这为安全代码生成提供了一种新的结构化协作范式。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

**核心思想**：借鉴安全软件开发生命周期（SSDLC）理念，将安全代码生成分解为**规划、安全分析、代码综合、评审优化**四个模块，每个模块由专门智能体承担；智能体之间仅通过**结构化产物**（artifact）传递信息，而非共享完整对话历史，从而在接口层面强制角色隔离、控制上下文增长。

**整体流程**（见图2）：
1. **Planner（规划器）**：针对任务提示词生成简明的高层功能计划，指导后续代码生成并辅助安全顾问识别攻击面。
2. **Code Generator（代码生成器）**：基于功能计划生成初始草稿代码。
3. **Security Advisor（安全顾问）**——多阶段管道：
   - **早期退出分诊（Early-exit Triage）**：检查任务与草稿代码是否含攻击面，若为纯算法或简单任务则提前退出，节省推理开销。
   - **CWE提取**：通过LLM推理，将任务映射为**因果CWE组对**（cause→effect），输出JSON格式，包含组名、原因、红旗标志、CWE编号、可能性分数等。
   - **标准驱动指南生成**：通过RAG检索预先构建的安全知识库（KB），利用余弦相似度选取最相关的安全指南，据此生成第一组标准驱动的安全指南。
   - **代码驱动指南生成**：直接分析草稿代码，发现LLM输出中典型的、高层计划中不易察觉的不安全编码模式，生成第二组轻量指南。
   - **验证与整合**：合并两组指南，对照功能需求检查是否存在冲突，消除过度设计，确保安全要求与功能的兼容性。
4. **Code Generator（代码生成器）**：在功能计划与安全指南的双重约束下生成正式代码，并进行语法检查与自我修正。
5. **Reviewer（评审器）**：通过**视角分离的检查**（分别进行功能正确性分析与安全检查）给出反馈；Code Generator据此修改，循环迭代直至评审通过或达到最大迭代次数（M=2）。

**安全知识库构建**：
- 取材自权威标准：CERT（C/C++）、OWASP ASVS、OpenSSF（Python）、OWASP Node.js/Cheat Sheet、OWASP Go安全实践等。
- 使用LLM（GPT-5.1）将原始文档归一化为紧凑的**WHAT–WHY–HOW–EXAMPLE**四字段结构化模式，再经embedding函数编码进入FAISS向量索引。
- 检索公式：\(G^*(q_j) = \arg\max^{(K)}_{g_i \in KB} \text{sim}(E(q_j), E(g_i))\)，最终候选集为各查询检索结果的并集。

**关键设计原则**：每种智能体只接收上游的结构化产物（如功能计划、安全指南、评审反馈），而不是完整对话记录——即"artifact-only interfaces"，这是与共享对话方案的本质区别。
