## 摘要
程序级二进制代码相似性分析（BCSA）旨在识别不同二进制程序中语义相似的代码区域，是软件抄袭检测、漏洞搜索和恶意软件分析的基础技术。现有方法通常按照函数调用图（FCG）的结构将二进制文件分解为模块，然后通过模块包含的函数来匹配这些模块。然而，函数内联会同时改变FCG结构和二进制函数语义，使得现有的分解和模块匹配方法效果降低。在这项工作中，我们提出了N2NMatcher，一个抗内联的二进制分解与模块匹配框架。我们首先进行了一项实证研究，以检验二进制文件中是否仍然包含在不同编译设置下提供稳定模块边界的函数。N2NMatcher 使用层次图神经网络学习预测这些作为锚点的函数，该网络编码了基于操作码序列、控制流结构和FCG调用上下文构建的二进制ACFG-FCG表示。然后，它执行锚点限定的分解，并使用学习到的模块图嵌入来匹配生成的模块。实验结果表明，与现有工作相比，N2NMatcher 在分解质量和模块匹配准确性上均有提升，从而实现了更有效的程序级BCSA。

## Abstract
Program-level Binary Code Similarity Analysis (BCSA) aims to identify semantically similar code regions across binary programs, serving as a fundamental technique for software plagiarism detection, vulnerability search, and malware analysis. Existing approaches often decompose binaries into modules following the structure of function call graphs (FCGs) and then match these modules by their contained functions. However, function inlining changes both FCG structures and binary function semantics, making existing decomposition and module matching methods less effective.   In this work, we propose N2NMatcher, an inlining-resilient framework for binary decomposition and module matching. We first conduct an empirical study to examine whether binaries still contain functions that provide stable module boundaries across compilation settings. N2NMatcher learns to predict such functions as anchors using a hierarchical graph neural network that encodes binary ACFG-FCG representations built from opcode sequences, control-flow structures, and FCG calling context. It then performs anchor-bounded decomposition and matches the generated modules using learned module graph embeddings. Experimental results show that N2NMatcher improves both the decomposition quality and module matching accuracy compared to existing works, enabling more effective program-level BCSA.

## 2. 方法论

### 2.1 核心思想
- 识别并用预测的方式找出 FCG 中可作为稳定边界的“锚点函数”（anchors）；
- 使用锚点限定二进制分解范围，生成锚定边界模块；
- 将模块视为图，用模块图嵌入进行匹配，避免依赖不稳定的单函数级语义对应。

### 2.2 二进制 ACFG–FCG 构建
- **指令归一化**：仅保留操作码助记符（小写），丢弃寄存器、地址、立即数等操作数细节，降低编译器和地址布局带来的差异。
- **基本块表示**：将归一化操作码映射到基于哈希的 token 空间，经可学习嵌入后做均值池化，投影为基本块初始表示。
- **ACFG**：每个二进制函数构建带属性的控制流图，节点为基本块并附操作码序列，边为过程内控制流转移。
- **FCG**：构建函数调用图，边来源包括直接调用指令和直接跨函数跳转（尾调用），以捕获优化产生的跨过程转移。
- **ACFG–FCG 嵌套结构**：将每个函数的 ACFG 挂接到对应 FCG 节点上，同时保留过程内结构与过程间调用上下文。

### 2.3 层次 ACFG–FCG 编码器
- **ACFG 级消息传递**：基本块初始表示  
  \(h_b^{(0)} = \text{ReLU}(W_o \cdot \frac{1}{m}\sum_{i=1}^{m}\text{Emb}(o_i))\)  
  然后通过邻域均值聚合更新：
  \(h_b^{(l+1)} = \text{ReLU}(W_s h_b^{(l)} + W_n \cdot \text{Mean}_{u \in N_A(b)} h_u^{(l)})\)  
  最终函数表示 \(z_v = \text{Mean}_{b \in V_v} h_b^{(L_A)}\)。
- **FCG 级消息传递**：将 \(z_v\) 与函数结构特征拼接投影得到初始 FCG 节点状态 \(x_v^{(0)}\)，随后在对称化 FCG 邻域上传播：
  \(x_v^{(k+1)} = \text{ReLU}(U_s x_v^{(k)} + U_n \cdot \text{Mean}_{u \in N_F(v)} x_u^{(k)})\)  
  得到融合调用上下文的节点嵌入 \(x_v^{(L_F)}\)。

### 2.4 锚点预测
- 使用正类加权二分类交叉熵损失：
  \(L = -\frac{1}{|\Omega|}\sum_{v\in\Omega}[\alpha y_v \log p(v) + (1-y_v) \log(1-p(v))]\)  
  其中 \(\alpha = N_{\text{neg}}/N_{\text{pos}}\)，\(\Omega\) 为有源级标签的节点集合。
- 推理时以阈值 \(\tau\) 判定锚点（验证集上选择最优阈值，实验中取 0.4）。

### 2.5 锚定边界分解
- 从预测锚点和 FCG 根节点出发，沿被调用边进行遍历；
- 遇到其他锚点则停止，不将其纳入当前模块；
- 模块允许重叠，未覆盖的节点保留为单例模块，确保全图覆盖；
- 生成的是“覆盖保持的重叠模块分解”，而非严格划分。

### 2.6 模块级匹配
- 沿用 ModX 的三类相似度框架：**语法相似度**（字符串、常量）、**语义相似度**（模块图嵌入）、**图相似度**（模块内调用图拓扑）。
- 语义相似度：使用预训练 Gemini 模型提取函数嵌入，作为模块 FCG 子图节点特征；经过有向消息传递层、门控注意力池化和均值残差得到模块图嵌入 \(g(m)\)，用余弦相似度作为语义相似度。
- 训练采用源级 Dice 系数构造对比学习监督，并优先选取“零源重叠但二进制证据得分高”的难负样本。
- 最终匹配分数：  
  \(S(m_q, m_c) = \alpha \text{Sim}_{\text{syn}} + \beta \text{Sim}_{\text{sem}} + \gamma \text{Sim}_{\text{graph}}\)，权重在验证集上选择（实验中为 α=0.475，β=0.350，γ=0.175）。

## 7. 讨论

- **为何锚点有效**：锚点函数在源级具有稳定的边界，在优化过程中较少被内联吸收或发生结构性分裂；这些函数通常对应库 API、外部导出符号、状态检查或递归函数，其调用关系在编译后仍保持明确。以它们为边界切分出的模块，在源级语义上对应较为固定的函数集合，从而提高了跨编译设置下模块的可比性。
- **锚点预测的可推广性**：锚点预测器学习的是“在调用图中处于稳定边界位置”的结构与语义模式，而非特定项目或特定编译器的表面特征。ISRD 上跨项目的无损迁移结果表明，该模式具有一定的通用性；但对混淆、加壳或高度特化的嵌入式二进制，锚点定义与预测可靠性仍需进一步验证。
- **模块重叠与覆盖率**：允许模块重叠是有意设计——一个锚点可能同时属于多个模块，这与真实二进制中函数可被多个调用者共享的事实一致。重叠设计提高了召回，但也引入了匹配时同一函数被多次计算的开销和潜在的冗余匹配，需要在评分聚合时加以处理。
- **对函数级 BCSA 的启示**：该研究表明，在函数内联普遍存在的情况下，强行恢复函数级一一对应既不现实也非必要；将分析粒度提升到由稳定边界界定的模块，是一种更稳健的折中方案。

## 8. 相关工作

- **二进制代码相似性（BCSA）**：从早期基于指令语法（n-gram、操作码序列）的浅层方法，发展到基于图（ACFG、FCG）与深度学习的语义嵌入方法（如 Gemini、Asm2Vec、SAFE、PalmTree、jTrans）；大多数方法以函数为基本单元，少数工作尝试二进制级或文件级匹配。
- **程序级与区域级匹配**：如 BinDiff、TurboDiff 等基于图同构与启发式匹配；ModX 首次提出模块分解思路，将程序分解为可重叠模块并匹配；N2NMatcher 在此基础上引入了稳定边界预测机制，是对 ModX 框架的语义增强。
- **函数内联的处理**：已有工作尝试通过反内联（de-inlining）恢复被内联的函数边界，或利用内联感知的训练数据增强模型鲁棒性；N2NMatcher 则从另一角度出发——不试图恢复函数边界，而是寻找仍然稳定的边界并围绕其组织模块。
- **图神经网络与程序分析**：GNN 被广泛用于控制流图、调用图、数据流图的表示学习；层次图模型（如跨 ACFG 与 FCG 的消息传递）相对较少，本文的方法是这一类层次建模在程序级 BCSA 上的具体应用。

## 9. 不足与局限

- **架构与编译器覆盖有限**：实验仅在 x86-64、GCC/Clang 且启用 LTO 的二进制上验证，尚未在 ARM、ARM64、MSVC、ICC 等编译器或非 LTO、混淆、加壳二进制上评估；这些场景下锚点分布和模块结构可能显著不同。
- **依赖调试信息标注**：源级标签（如函数对应、稳定边界）依赖 DWARF 调试信息生成；带有调试信息构建的二进制与真实 stripped 二进制的分布差异可能影响锚点预测的迁移效果。
- **阈值与超参数敏感性**：锚点判定阈值（τ=0.4）和匹配权重（α=0.475，β=0.350，γ=0.175）均在验证集上选取并在各实验中固定使用，面对全新编译链或优化配置时未必最优，需重新校准。
- **模块匹配的可解释性有限**：模块图嵌入为黑盒表示，虽然匹配准确率提升明显，但难以解释“为什么两个模块相似”，在安全分析场景（如漏洞根因定位）中可能需要额外的解释机制。
- **未考虑库函数与剥离影响**：实验中虽然使用了 stripped 二进制，但未专门区分静态链接库函数与项目自研函数；若库函数比例过高，可能稀释模块匹配信号。

## 10. 未来工作

- 扩展锚点定义与预测器到更多架构（ARM、RISC-V）、编译器（MSVC、ICC）以及非 LTO、混淆和加壳二进制，验证锚点语义的跨环境稳定性；
- 探索将锚点预测与反内联技术结合，既利用稳定的边界锚点，也尝试恢复部分被内联的函数结构，进一步细化模块粒度；
- 引入更细粒度的模块内容表征（如常量图、字符串引用图、数据流信息），提升语法相似度分量的区分能力；
- 设计端到端的“锚点预测 + 模块匹配”联合训练框架，使分解目标直接服务于匹配目标，而非两阶段独立优化；
- 在真实安全任务上进行评估，如已知漏洞搜索（跨优化级别寻找含漏洞模块）、恶意代码同源分析、软件供应链成分识别，检验实际收益；
- 研究模块匹配结果的可解释性输出（例如对齐锚点路径、报告共享函数集合），增强分析人员的信任与可用性。

## 11. 总结

- 函数内联是程序级 BCSA 面临的核心挑战之一，它同时破坏 FCG 拓扑和函数级语义对应，使传统基于函数的分解与匹配方法在跨编译设置中明显退化。
- 本文通过大规模实证确认了稳定边界函数的存在性与可利用性，提出 N2NMatcher：用层次 ACFG–FCG 图神经网络预测稳定边界锚点，以锚点限定模块分解，再以模块图嵌入进行匹配。
- 在 BinKit LTO 基准上，N2NMatcher 在分解质量和模块匹配指标上全面超过 ModX 等现有方法；在 ISRD 跨项目数据集上无需调参即取得显著提升；消融实验验证了层次锚点编码器与模块级嵌入的各自贡献。
- 总体而言，N2NMatcher 为函数内联场景下的程序级二进制相似性分析提供了一条不依赖不稳定函数边界的新路径，具有较好的实用价值与可扩展空间。
