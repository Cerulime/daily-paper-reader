## 摘要
专家并行（EP）是一种常见的策略，通过将专家分布在多个GPU之间来服务大型混合专家（MoE）模型。路由器决策随后决定哪些专家处理每个令牌，以及哪些GPU执行由此产生的工作。这一过程在服务调度中暴露了供应链攻击面。我们引入了负载劫持，其中恶意模型提供者仅修改检查点的路由器权重，分发被投毒的检查点，并保留一个私有触发器。当触发器出现时，被投毒的路由器将令牌到专家的分配集中到与一个GPU共置的专家上。由此产生的负载使该GPU成为掉队者，迫使对等设备等待，而普通输入上的路由仍接近干净参考。我们发现这种条件行为难以实现，因为奖励触发输入上目标专家使用的目标也可能使普通输入路由偏向同一批专家。为解决这一冲突，负载劫持采用三阶段优化过程，产生强触发器依赖的集中，同时保持普通输入路由接近干净参考。在三个MoE家族和四个语料库中，负载劫持将92.3%至95.6%的触发令牌分配引导至目标专家。在实时EP服务中，触发流量产生的首令牌时间（TTFT）是普通流量的1.43倍，吞吐量是普通流量的0.86倍。这些结果表明，被投毒的路由器可充当触发器控制的设备调度器，并促使对路由和运行时负载进行检查点审计。

## Abstract
Expert parallelism (EP) is a common strategy for serving large Mixture-of-Experts (MoE) models across multiple GPUs by distributing experts among devices. Router decisions then determine both which experts process each token and which GPUs execute the resulting work. This procedure exposes a supply-chain attack surface in the serving schedule. We introduce Load Hijack, in which a malicious model provider modifies only a checkpoint's router weights, distributes the poisoned checkpoint, and retains a private trigger. When the trigger appears, the poisoned router concentrates token-to-expert assignments on experts co-located on one GPU. The resulting load makes that GPU a straggler and forces peer devices to wait, while routing on ordinary inputs remains near the clean reference. We find this conditional behavior difficult to achieve because an objective that rewards target-expert use on triggered inputs can also bias ordinary-input routing toward the same experts. To resolve this conflict, Load Hijack employs a three-stage optimization procedure that produces strong trigger-dependent concentration while keeping ordinary-input routing close to the clean reference. Across three MoE families and four corpora, Load Hijack directs 92.3% to 95.6% of triggered token assignments to the target experts. In live EP serving, triggered traffic produces 1.43x the time-to-first-token and 0.86x the throughput measured under ordinary traffic. These results show that poisoned routers can act as trigger-controlled device schedulers and motivate checkpoint audits of routing and runtime load.

## 1. 核心问题与研究背景

- 论文聚焦于混合专家（MoE）大语言模型在多 GPU 服务中的供应链安全风险。
- 在专家并行（Expert Parallelism, EP）中，专家被分布到不同 GPU 上，路由器决定每个 token 由哪些专家处理，从而间接决定了哪些 GPU 承担计算负载。这种“路由即调度”的机制构成了攻击面。
- 已有研究（如 BadMoE、BadSwitch）利用触发器改变模型输出，或利用对抗输入造成路由失衡（RepetitionCurse），但尚未有工作探索：恶意模型提供者能否仅通过修改检查点中的路由器权重，在私有触发器出现时，将大量计算集中到单个 GPU 上，使其成为“掉队者”（straggler），从而降低服务性能，同时普通输入的路由行为仍保持正常。
- 本文提出 **Load Hijack（负载劫持）**，验证了这一攻击的可行性，并系统解决了“触发器条件性集中”与“普通输入路由保持干净”之间的优化冲突。

## 2. 方法论

### 2.1 核心思想

- 攻击者仅修改干净 MoE 检查点的路由器参数（θc → θp），保留一个私有触发器 τ，并将中毒检查点发布到公共模型库。
- 普通输入 x 经过中毒路由器时，路由分布接近干净参考；当输入变为 τ∥x 时，路由器将内容 token 的 top-k 分配集中到与某个受害 GPU 共置的目标专家集合 E\* 上，使该 GPU 成为负载热点，形成系统级 straggler。

### 2.2 关键技术细节

- 目标集大小设为各模型 top-k 值（Mixtral: 2，Qwen: 4，OLMoE: 8）。
- 采用 LoRA 仅微调路由器参数，保持其他参数冻结。
- 三阶段优化流程（Algorithm 1）：
  1. **Stage 1：普通路由预条件化**  
     在普通输入上最小化目标专家概率质量（anti-target loss），并加入语言建模损失保持模型效用，使普通输入的目标专家使用率下降，为后续条件化训练做准备。
  2. **Stage 2：学习路由切换**  
     引入配对输入 (x, τ∥x)，使用 trigger loss 提高触发输入的目标专家概率质量，同时使用 gap loss 强制触发输入与普通输入之间的目标概率质量差至少为 γ，避免模型对所有输入都集中路由。
  3. **Stage 3：恢复普通输入 token 级路由**  
     用干净路由器作为教师，对普通输入施加 KL 散度匹配，并加入层均匀性损失（使用 straight-through estimator）和层上限损失，消除剩余层的局部集中，同时保留 gap loss 以维持触发条件行为。

### 2.3 关键公式（文字说明）

- 目标概率质量 mℓ(t, θ) 定义为目标专家集合的 softmax 概率之和。
- Stage 1 损失：anti-target loss + 攻击子集语言建模损失 + 正则子集语言建模损失。
- Stage 2 损失：trigger loss + gap loss + 配对语言建模损失。
- Stage 3 损失：KL 匹配损失 + gap loss + 层均匀性损失 + 层上限损失 + 配对语言建模损失。

## 6. 主要结论

- Load Hijack 在 3 个 MoE 模型和 4 个语料上，将 **92.3%–95.6%** 的触发 token 分配引导至目标专家，而良性分配份额与干净参考相差不超过 1.1 个百分点。
- 触发流量使受害 GPU 与对等 GPU 的专家计算负载比升至约 **49.0×**，SM 利用率比升至 **1.60×**。
- 实际服务中，触发流量使 p99 首令牌时间达到良性流量的 **1.43 倍**，吞吐量降至 **0.86 倍**。
- 直接触发训练无法实现条件行为（良性也被集中到 100%），三阶段优化是解决冲突的关键。
- 防御审计在足够触发流下可检测到负载偏斜，路由器重修复可基本恢复平衡，但极稀疏触发器流量（α=0.1）可绕过固定阈值审计。
- 结论强调：MoE 路由器不仅是模型行为的决定者，更是系统级调度器，检查点审计应包含对路由器和设备负载的影响评估。

## 8. 不足与局限

- **威胁模型依赖已知专家放置**：攻击者必须知道专家到设备的连续映射（πℓ(e)），对于动态重映射或未知放置的实际部署，攻击不适用。
- **适用模型范围有限**：仅评估三种 MoE 模型且 EP 规模较小（K=4），较大规模 EP（如 8/16 GPU）上的扩展性未验证。
- **无端到端输出攻击对比**：未与 BadMoE、BadSwitch 在相同系统负载指标下比较（虽然目标不同，但缺少横向对比仍是一点不足）。
- **模型效用有下降**：触发输入困惑度明显升高（如 Mixtral C4 PPL 从 9.10 升至 13.10），虽不影响路由攻击成功，但可能暴露异常。

- **训练资源细节缺失**：未报告 Qwen 和 OLMoE 的训练轮次、batch size、触发长度等超参数，可复现性受限。
