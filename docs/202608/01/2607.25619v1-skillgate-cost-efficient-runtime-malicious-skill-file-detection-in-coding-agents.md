## 摘要
软件工程团队现在将 AI 编码代理（如 Cursor、Claude Code、GitHub Copilot）部署为一线生产力工具，安装特定领域的技能文件，以使代理行为适应项目 API、框架约定和组织工作流。这些复杂的 Markdown 文件只需一条 npx skills add 命令即可轻松从公共注册表下载，且没有真正的安全审查，代表了一种新颖的供应链攻击面：恶意技能文件可以悄无声息地重新编程代理行为，窃取凭据，在生成的代码中注入后门，或将代理操作重定向到攻击者控制的端点。这种威胁并非假设：最近的报告记录了公共注册表中的数百个恶意技能包，包括通过虚假生产力技能分发窃取凭据的信息窃取器的有组织活动。目前没有针对这一攻击面的系统性工具链防御。我们提出了 SkillGate，一个可在编码代理安装之前筛选 AI 技能包的可部署安全网关。SkillGate 使用混合正则表达式预过滤器 + LLM 评判器流水线：安全信号文件完全绕过 LLM（跳过节省）；被标记的文件仅将其匹配的片段窗口发送给评判器，而非完整内容（片段节省）。我们回答了四个研究问题，涵盖检测有效性、筛选成本、运行时开销以及在 SkillsBench 基准上与两个现有工具的误报行为对比。在 SkillsBench（n=1,650，9.1% 恶意）上，SkillGate 实现了 F1=0.817，FPR=1.13%，同时与全文件筛选相比，LLM 输入令牌减少了 77%，并且在阈值无关的 AUPRC 上优于现有工具 5-6 倍（0.830 vs. 0.144/0.162）。

## Abstract
Software engineering teams now deploy AI coding agents (Cursor, Claude Code, GitHub Copilot) as first-class productivity tools, installing domain-specific skill files to tailor agent behavior to project APIs, framework conventions, and organizational workflows. These complex Markdown files are easily downloaded from public registries with a single npx skills add command and no real security screening, representing a novel supply-chain attack surface: a malicious skill file can silently reprogram agent behavior, exfiltrating credentials, injecting backdoors into generated code, or redirecting agent actions to attacker-controlled endpoints. The threat is not hypothetical: recent reports document hundreds of malicious skill packages in public registries, including organized campaigns that distributed credential-stealing infostealers via fake productivity skills. No systematic toolchain defense exists for this attack surface. We present SkillGate, a deployable security gateway that screens AI skill packages before coding agent installation. SkillGate uses a hybrid regex-prefilter + LLM-judge pipeline: safe-signal files bypass the LLM entirely (skip savings); flagged files have only their matched snippet windows sent to the judge, not the full content (snippet savings). We answer four research questions covering detection effectiveness, screening cost, runtime overhead, and false positive behavior on the SkillsBench benchmark against two existing tools. On SkillsBench (n=1,650, 9.1% malicious), SkillGate achieves F1=0.817, FPR=1.13% while reducing LLM input tokens by 77% vs. full-file screening, and outperforming existing tools by 5-6x on threshold-independent AUPRC (0.830 vs. 0.144/0.162).

### 一、核心问题与研究动机

- **背景**：软件工程团队正大规模采用 AI 编码代理（如 Cursor、Claude Code、GitHub Copilot），这些代理具备自主规划、读写代码、执行命令的能力。为扩展代理能力，开发者常安装领域特定的「技能文件（Skill Files）」——即 Markdown 格式的指令文档，包含工具定义、API 参考、工作流规范等，代理将其加载进上下文并作为权威指令执行。
- **核心问题**：技能文件可从公共注册表通过一条命令（如 `npx skills add <pkg>`）无审查下载，构成了一种新型供应链攻击面。恶意技能文件可以在无用户干预的情况下：窃取 API 凭据、在生成代码中注入后门、将代理操作重定向至攻击者控制的端点。
- **现实威胁**：2026 年 2 月报告显示，ClawHub 注册表中发现 1,184 个恶意技能包（约占 20%），包含「ClawHavoc」活动通过虚假生产力技能分发凭据窃取器。多份学术研究也证实恶意技能文件在公共注册表中大规模传播、编码代理普遍易受此类攻击。
- **现有防御缺口**：传统供应链扫描工具（Semgrep、Snyk）针对源代码而非自然语言行为指令；提示注入防御针对运行时而非安装前；现有技能文件扫描器（ClawVet、SkillScanner）静态模式匹配误报率过高（FPR > 40%），不具备可部署性。

### 二、方法论：SkillGate 混合检测流水线

SkillGate 是一个部署在编码代理与 MCP 服务器之间的安全代理守护进程，核心设计原则是「跳过节省」与「片段节省」——安全文件零成本放行，可疑文件仅送检匹配片段而非完整内容。整个流水线分为四个阶段：

1. **阶段一：运行时代理与内容提取**
   - 作为 Unix-socket 守护进程运行，充当编码代理与上游 MCP 服务器之间的透明代理。
   - 拦截 `tools/call`、`resources/read`、`prompts/get` 三种 MCP 响应类型，提取技能文件内容进行检测。
   - 所有决策写入结构化 JSONL 审计日志，支持事后取证。
   - 同时提供 `npx skills add` 安装命令的守卫包装器，在安装前拦截并扫描。

2. **阶段二：正则预过滤器（RuleEngine）**
   - 编译 530 条安全模式：428 条源自 MITRE ATT&CK 框架的核心模式 + 102 条 Sigma 社区规则。
   - 12 大类别覆盖：防御规避（62）、执行（56）、危险命令（56）、凭据访问（44）、持久化（38）、影响（33）、混淆（27）、外泄（27）、发现（23）、命令与控制（21）、提权（17）、收集（8）。
   - 关键设计：预过滤器是「门」而非「分类器」——匹配到模式不直接产生最终标签，只决定是否需要升级到 LLM 评判器，避免纯正则方法的高误报率。

3. **阶段三：片段提取与 LLM 评判器**
   - 对每个匹配命中生成字符窗口 `[match.start − cw, match.end + cw]`，默认 `cw = 500` 字符。
   - 窗口间距离小于 `cw/4` 时去重；默认最多拼接 `ms = 20` 个唯一窗口（硬上限 8,000 字符），并添加约 700 字符的前缀（包含包名、文件路径、元数据）。
   - 使用 LLM（默认 `gpt-5.4-mini`）作为评判器，返回 SAFE / SUSPICIOUS / MALICIOUS 三个类别及置信度分数。

4. **阶段四：策略引擎与审计日志**
   - 默认映射策略：MALICIOUS（置信度 ≥ 0.7）→ 阻止；SUSPICIOUS（≥ 0.5）→ 隔离；SUSPICIOUS（< 0.5）→ 警告；SAFE → 放行。
   - 被阻止的文件返回结构化错误，被隔离的文件写入隔离目录供人工审查。

### 三、实验设计

- **数据集**：SkillsBench 基准，共 n=1,650 个技能文件，其中 1,500 个良性（来自公开仓库）、150 个恶意（手工构造，覆盖 8 种攻击类别：明文命令、数据外泄、编码载荷、隐写术、RSA 模运算、ASCII 走私、二进制执行、远程脚本），恶意比例 9.1%。
- **对比方法**：
  - **ClawVet**：静态分析工具，54 条手写模式、6 个分析通道，在测试集上采用 oracle-optimal 阈值。
  - **SkillScanner**：Cisco AI Defense 多引擎扫描器（v2.0.11），结合静态 YARA/正则规则与行为控制流图，报告 5 个严重级别；另有 SkillScanner+LLM 模式（对每个文件完全升级到相同 LLM 评判器）。
- **指标**：精确率（P）、召回率（R）、F1、误报率（FPR）、马修斯相关系数（MCC）、AUPRC（主要阈值无关指标）。令牌数用 tiktoken o200k_base 计算，延迟为墙钟时间。
- **实验组**：
  - 主实验：SkillGate vs. ClawVet vs. SkillScanner（各阈值）vs. SkillScanner+LLM。
  - 消融实验：B1（纯正则无 LLM）、B2（全文件 LLM 无预过滤）、ms=5 片段预算变体。
  - 阈值敏感性分析：置信度阈值 θ 从 0 到 1 扫描。
  - 误报分类分析：手动分类良性文件被误报的触发内容。

  - **不足**：仅使用单一数据集（SkillsBench）；恶意样本为手工构造而非真实野外捕获；仅测试单一 LLM 后端；静态基线在 oracle-optimal 下已是最优表现，但实际部署时无法获得该阈值。

### 六、主要结论与发现

1. **检测有效性（RQ1）**：SkillGate 在 SkillsBench 上达到 F1=0.817、召回率=0.769、FPR=1.13%、MCC=0.803，AUPRC=0.830，是 ClawVet（0.144）和 SkillScanner（0.162）的 5-6 倍。MCC 比最强基线（SkillScanner+LLM，0.331）高 2.4 倍。
2. **成本降低（RQ2）**：混合流水线将 LLM 输入令牌降低 76.9%（4.3 倍），其中 67.2% 的文件完全绕过 LLM（跳过节省），剩余文件仅发送匹配片段（片段节省）。
3. **运行时开销（RQ3）**：加权平均延迟约 818ms（预过滤安全路径约 139ms 占 67.2%，LLM 路径约 2,208ms 占 32.8%），比 SkillScanner+LLM（约 6,281ms）快 7.7 倍，兼容 0.5-5 秒的注册表获取时间。
4. **误报行为（RQ4）**：平均仅 17 个误报（FPR=1.13%），对比 ClawVet 756 个（50.4%）和 SkillScanner 261 个（17.4%），减少 15-44 倍。主导类别是文档中 base64 编码内容触发编码载荷规则。在 block-grade 误报上，SkillGate 仅约 3 个，远低于 ClawVet 的 296 个。
5. **消融发现**：LLM 评判器不可替代（预过滤器单独使用时 FPR=27.1%→加评判器降至 1.13%）；全文件 LLM 虽召回率略高（0.804 vs. 0.769）但代价是更多 LLM 调用和更高 FPR；默认 ms=20 优于 ms=5。
6. **关键洞察**：SkillScanner+LLM 的少量误报是「几乎不触发」的副产品——召回率仅 0.180，且其全部 11 个误报都达到 CRITICAL 级别，会被策略硬阻止。SkillGate 是唯一同时保持低 block-grade 误报率和可用召回率的方法。

### 七、方法优点

- **成本高效的混合设计**：双级流水线（正则预过滤 + 片段级 LLM 判定）精准解决了现有工具的两难困境——纯静态误报率高、纯 LLM 成本不可持续。67.2% 文件零 LLM 调用，LLM 调用者仅看匹配窗口而非全文件，在保持检测精度的同时减少 77% 令牌。
- **可部署性**：作为 MCP 代理运行，仅需一行配置变更即可与五种主流编码代理集成；延迟（约 818ms）兼容安装流程，不会显著影响开发体验。
- **误报控制**：FPR=1.13%、block-grade 误报仅约 0.20%，且阈值敏感性分析显示在 θ ∈ [0.06, 0.99] 的广泛区间内 FPR 均低于 5%，部署不需要逐场景调参。
- **评估严谨性**：使用 MCC 与 AUPRC 等不平衡鲁棒指标，避免 F1 在类别极不平衡（9.1% 恶意）下的误导性；基线在 oracle-optimal 条件下评估，结论偏向保守；报告 3 次运行的均值和标准差，纳入 LLM 非确定性。
- **实用性增强**：提供可配置的置信度阈值与策略映射、完整的审计日志、隔离/阻止/警告分级响应，便于组织按自身风险容忍度调整。

### 八、不足与局限

- **攻击模型单一**：威胁模型假设非自适应攻击者（不了解 SkillGate 部署、未审查规则集），未覆盖能逆向工程规则集并针对性构造绕过的自适应攻击者；也不覆盖通过代理现有上下文窗口发起的攻击和事后执行攻击。
- **基准数据局限**：SkillsBench 的 150 个恶意文件为手工构造攻击样本，非野外真实捕获，测量到的召回率可能无法迁移到有机演化的真实攻击活动上；无真实事件中的恶意包（如 ClawHavoc）作为基准，对新型对抗技术的有效性未知。
- **预过滤器覆盖缺口**：残余误报主要来自编码类攻击（RSA 模运算、零宽字符），暴露了 ATT&CK 派生模式的覆盖盲区——尽管这是当前能找到的最全面的模式集合，但无法保证覆盖所有已知安全模式。
- **LLM 非确定性风险**：gpt-5.4-mini 评判器非确定性造成结果波动（F1 标准差 0.013，FPR 标准差 0.59pp）；3 次运行跨越三周，可能恰好跨越了模型提供商的更新，影响结果可复现性。
- **单一 LLM 后端**：所有结果基于 OpenAI gpt-5.4-mini；对 Claude、本地 Ollama 等后端的召回表现未评估，泛化性存疑。
- **评估规模化局限**：仅单一数据集（n=1,650）评估；token 节省量依赖文件长度分布（短文件因固定前缀占比高而节省较少）；未评估大规模注册表场景下的吞吐、并发或资源消耗。
- **上下文窗口限制**：对于 SB 平均约 7k 字符的文件，默认片段窗口可能遗漏匹配区域之外的恶意内容（全文件消融 B2 的召回率确实高出 3.5pp），存在漏检风险。
