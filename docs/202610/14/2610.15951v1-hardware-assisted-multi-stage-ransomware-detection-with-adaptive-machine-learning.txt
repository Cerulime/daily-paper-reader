# Hardware-Assisted Multi-Stage Ransomware Detection with Adaptive Machine Learning 

Salma Aboelmagd ∗, Md. Rakibul Ahasan ∗, Zhixin Pan ∗, Abdulrahman Takiddin ∗, and Ziyu Shu †∗ Florida State University, Tallahassee, FL, USA 

† Stony Brook University, Stony Brook, NY, USA 

Abstract —Ransomware is a fast-escalating privacy threat caus-ing significant financial and data losses worldwide. As attacks grow more sophisticated, traditional static signatures and dy-namic behavior analysis struggle to defend. In this paper, we propose an novel framework that couples software-level scanning with hardware-level microprocessor activity monitoring to achieve efficient ransomware detection and mitigation. The contributions are threefold: (1) we employ adversarial training to harden static analysis against obfuscation and leverage hardware-assisted monitoring for real-time detection; (2) we integrate neural architecture search (NAS) to automatically tailor models for stronger generalizability; and (3) We validate the pro-posed approach through extensive experiments, demonstrating substantially improved detection accuracy and reduced latency compared with existing methods. Moreover, it provides trace-level interpretability that explains the underlying decision process. 

I. I NTRODUCTION 

Cybersecurity has remained a major concern since the emergence of networked computing systems. Among various security threats, ransomware , a special type of malicious software that encrypts critical data and demands payment for its release, has become one of the most destructive and financially damaging forms of cyberattacks. Its growing sophistication has resulted in significant economic losses, operational malfunction, and exposure of sensitive information worldwide. As shown in a recent study [1], ransomware attacks are increasingly targeting large organizations, with estimated global damages approaching $6 trillion annually. Moreover, attackers have adopted advanced obfuscation and evasion strategies, rendering conventional defenses such as signature-based detection and fuzzing ineffective, highlighting the need for more adaptive detection and mitigation approaches.

The execution phase then rapidly performs destructive actions depending on the ransomware type: (i) Crypto (file encryption with ransom demand), (ii) Locker (blocking system access), (iii) Scareware (displaying fake alerts), or (iv) Hybrid (combining multiple attacks). Existing ransomware detection methods can be broadly cat-egorized into static analysis and dynamic analysis approaches. Static analysis inspects executable files or code structures before execution, typically through signature matching or feature recognition. While efficient, such techniques often fail against obfuscated or polymorphic malware, resulting in high false positive rates [1], [2]. Dynamic or behavioral analysis, instead, monitors runtime activities such as file operations and system calls to identify malicious patterns [3]. Although generally more accurate, these approaches are often platform-dependent and suffer from latency, while ransomware protec-tion is a time-critical task. Furthermore, most behavior-based systems produce binary detection results without explaining the underlying reasoning, making it hard to perform post-detection actions like file restoration or infection localization. To overcome these challenges, this work proposes a

hardware-assisted, machine learning (ML) based ransomware detection framework that integrates static analysis with dy-namic runtime monitoring in a unified architecture. Unlike prior hybrid approaches that rely on fixed rules or manual intervention to balance accuracy and overhead, our framework is centered on adaptive hardware-assisted monitoring and makes the following contributions:  

> •

Multi-stage detection pipeline: We propose a hierar-chical detection pipeline that integrates static inspection with dynamic hardware-assisted analysis, activating fine-grained runtime monitoring only when necessary to re-duce detection latency and system overhead.  

> •

Dynamic hardware-assisted monitoring: We develop an adaptive runtime monitoring strategy that combines coarse-grained observation with selective fine-grained runtime tracing, enabling low-overhead detection with timely confirmation under obfuscated ransomware behav-iors.

The remainder of this paper is structured as follows. Sec-tion II reviews the related studies. Section III presents the pro-posed detection framework. Section IV discusses experimental evaluations, and Section V concludes the paper. II. B ACKGROUND AND RELATED WORK 

The research on ransomware detection has gained growing attention in recent years. As discussed in Section I, the majority of existing methods can be broadly categorized into two types: static analysis and dynamic analysis .

Static analysis is conducted before program execution, where the executable or source code is examined to iden-tify malicious intent. For instance, [4]–[8] utilized deep file–scanning and code–inspection techniques to detect poten-tial ransomware, while [9]–[11] explored linguistic analysis of program code for early-stage detection. However, static ap-proaches lack the behavioral information from runtime, which limits their ability. Moreover, certain benign applications, such as disk–encryption tools, may share similar binary patterns with ransomware, causing high false positive rates (FPRs). Additionally, many static methods rely heavily on signature-based pattern matching; when attackers could intentionally disguise or obfuscate code [12], these methods may fail to detect the threat accurately. 

Dynamic analysis , on the other hand, involves executing suspicious programs to monitor runtime behavior. For exam-ple, [13] leveraged runtime performance traces to identify high-frequency encryption patterns, enabling faster detection, while [14] investigated a framework that tracks dynamic varia-tions in portable executable headers. Several other studies [15], [16] have incorporated machine learning (ML) models to further improve detection accuracy. Despite promising results, these methods still face several challenges. First, many fail to enforce early termination of ransomware, allowing sig-nificant data encryption before detection. Second, ML-based systems often behave as black boxes without interpretable reasoning, which undermines user confidence in critical ap-plications. Finally, most approaches are evaluated only on limited ransomware families, reducing their generalizability. Vulnerability to obfuscation.  

> •

Lack of prioritization of early termination.  

> •

Low generalizability among variants of ransomware.

Lack of transparency in decision making. To address these challenges, our proposed approach enables a synergistic integration of a robust static detection framework and hardware-assisted dynamic analysis for efficient detection. 

Fig. 2: Detection accuracy of various methods against four ransomware variants. Figure 3 presents an overview of the proposed workflow, modeled as a finite state machine (FSM). In the first stage, the target program undergoes static analysis for early-stage detection. If a program is flagged as ‘suspicious’ at this step, it is isolated to prevent further infection and passed to the dynamic analysis phase. This two-stage sequential framework offers several key advantages: it mitigates the issue of high false positive rates in conventional static analysis by labeling programs as suspicious rather than directly classifying them as malicious. Additionally, only pro-grams flagged in the first stage proceed to runtime monitoring, which reduces unnecessary computational overhead. Next, based on the results of dynamic analysis, the program is either restored to its original state if deemed benign or, if identified as malicious, our method terminates its execution and restores encrypted files using backups.

> •

A hardware-assisted dynamic analysis phase, leverag-ing a long-short term memory (LSTM) model to monitor runtime behavior with features from hardware compo-nents, including hardware performance counters (HPC) and embedded trace buffer (ETB).  

> •

B. Adversarial Training based Static Analysis 

We employ a gradient-boosted decision tree (DT) model as the core static analysis engine. The entire workflow is shown in Figure 4. At the preprocessing stage, we extract a diverse set of static features from each program, covering API calls, opcode sequences, file metadata, Portable Executable (PE) header information, and opcode n-grams that capture recurring instruction patterns. These features provide complementary perspectives on program behavior, enabling the detector to capture both structural and semantic cues. For training, the dataset is split into 80% for model training and 20% for validation. An initial DT baseline is first constructed using the classical CART [17] algorithm and evaluated to identify samples that are misclassified, which serve as valuable “falsi-fied labels” for further refinement. 

Fig. 4: Workflow of adversarial-training–enhanced static anal-ysis. We synthesize adversarial Samples to emulate eva-sive/poisoned conditions. The adversarial set is combined with the clean dataset for adversarial Training, yielding augmented models . A lightweight boosting step integrates all models together, thereby improving the overall robustness. After obtaining the initial DT model, we extend the frame-work with an adversarial training process to reinforce its ro-bustness against evasive ransomware. Specifically, in addition to inserting benign code fragments, which simulate padding-based obfuscation, we apply a variety of advanced obfuscation strategies: 1) Opcode substitution: replacing selected instructions with semantically equivalent alternatives (e.g., swapping instruction sequences that perform the same computation; 2) Control-flow manipulation: reordering benign code blocks or injecting harmless jumps/NOPs to alter control-flow structure without changing functionality; 3) Polymorphic transformation: applying lightweight syn-tactic mutations such as register renaming and insertion of no-op instructions to produce many syntactic variants of the same logic. These transformations mimic practical obfuscation tech-niques employed by modern ransomware to evade static signature-based tools. Both the adversarially crafted samples and the previously misclassified instances are fed back into the training pipeline, ensuring that the model incrementally learns to recognize obfuscated ransomware while maintaining a low false positive rate. A central challenge of adversarial training is achieving con-vergence under such adversarial conditions [18]. To overcome this, we adopt a boosting framework [19], where a sequence of lightweight DT models M = {T 1, T2, . . . , TN } is pro-gressively trained with adaptive weights {w1, w 2, . . . , w N }. In each iteration, a new augmented tree Ti is trained specifically on the challenging and adversarial samples. The ensemble prediction is obtained via weighted voting, where higher weights are assigned to trees with stronger performance on the augmented dataset. This iterative scheme steadily enhances the detector’s resilience to obfuscation while keeping the train-ing process stable and computationally efficient. C. Hardware-assisted dynamic analysis 

Once a target program is flagged as “suspicious” by the static stage, it is passed to dynamic analysis for further inspection. The key challenge here is that ransomware must be identified and terminated before large amounts of files are encrypted. Relying solely on software-level monitoring often introduces unacceptable delays. To overcome this, we utilize hardware components that can stream low-level execution information in real time, thereby reducing detection latency. 

a) HPC features. 

The first hardware source we leverage is hardware perfor-mance counters (HPCs), and the potential of HPCs for ran-somware detection has been explored in [13]. Specifically, HPCs are built-in registers capable of tracking processor events such as instruction counts, cache references, and branch mispredictions. These metrics can be collected using standard interfaces like perf . Importantly, many ransomware behaviors manifest distinct hardware footprints. For instance, Figure 5 illustrates the clear gap between a benign program and ran-somware (WannaCry) in terms of branch and cache misses. JOURNAL OF L ATEX CLASS FILES, VOL. 14, NO. 8, AUGUST 2021 4

The frequent encryption loops in WannaCry lead to repeated branching and file access, which manifest as spikes in these HPC signals. 

Fig. 5: Comparison of HPC events between the benign pro-gram and WannaCry. a) branch misses, b) cache misses. 

b) ETB features. 

Though HPC features act as a valid way to enable realtime ransomware trace monitoring, they only provide an aggregate view of processor activity, making it unable to pinpoint activi-ties to a particular program. To address this limitation, we also integrate embedded trace buffers (ETBs) into our framework. ETBs capture detailed, cycle-by-cycle on-chip trace for desig-nated process, offering more precise and granular insights than HPCs. However, it comes at the cost of increased overhead, making continuous monitoring with ETBs impractical. 

c) Adaptive monitoring. 

To combine the efficiency of HPCs with the precision of ETBs, we design an adaptive monitoring strategy . Instead of following a fixed alternation schedule between lightweight and heavyweight monitors, our method adaptively determines when to escalate from HPC-based monitoring to ETB con-firmation. Specifically, each program execution is divided into time windows (500 ms in our experiments). During each window, the system performs five major steps: 1) Initial monitoring with ETBs : In the initial window, we use ETBs for monitoring, since the program has already been deemed suspicious by the static analysis. The assumption is that it has a high likelihood of being ransomware, so ETBs are employed to detect any mali-cious behavior at the earliest stage. 2) Risk-guided monitoring with HPCs If the program passes the first ETB-based window without exhibiting malicious behavior, we assume it may either be benign or a ransomware using delayed infection tactics. To reduce the overhead of continuous ETB monitoring, we switch to HPC-based detection. The HPC classifier would compute the probability pt indicating how likely the current process exhibits ransomware behavior, alongside two supporting signals:

This escalation means we switch from coarse monitoring to fine-grained tracing for confirmation. 4) ETB confirmation: Once escalation is triggered, ETBs are enabled to capture fine-grained traces of the suspi-cious process. This step acts as a high-confidence verifier. If the ETB classifier confirms ransomware behavior, the process is immediately terminated. Otherwise, we consider that it indicates either the detection result of previous window is a false positive, or the ransomware applies obfuscation to circumvent detection. 5) Rollback and recovery: Either the ransomware activity was confirmed or a conflict between ETB and HPC hap-pened, we perform data restoration with backup files to erase the possible infection in previous windows (details in Section III-E). This ensures that any partial encryption is reversed to mitigate the ransomware damage. The workflow is shown in Figure 6. We select 500ms as the window size to efficiently monitor ransomware activities while keeping resource usage low. In order to handle time-sequential data dumped from HPCs/ETBs, we apply long-short term memory (LSTM) as our machine learning model for classification. The details of the model structure and hyperparameter tuning will be discussed in the next section.

D. Neural Architecture Search 

In this section, we elaborate on how we determine the structure and parameters for the applied LSTM model. As illustrated in Section II, another key challenge in ML-based ransomware detection is the limited generalizability of models across different variants. We attribute this challenge to the fact that in most existing approaches, model architectures were manually selected based on prior knowledge, which lacks the flexibility to adapt to unseen variants. A straightforward approach could be to exploit a large-scale model. However, such models introduce high latency and are more prone to overfitting [20], which is undesirable in a latency-sensitive application such as ransomware detection. To address this issue, we employ Neural Architecture Search (NAS) to automatically discover optimal model architectures tailored for our task. NAS explores a large space of poten-tial network configurations, evaluating candidate architectures with different layers and connections, and gradually converges to structures that achieve high task-specific performance [21]. Our framework employs a one-shot NAS paradigm for better efficiency. Instead of training each candidate architecture individually, we first construct a large, over-parameterized su-pernet that contains many possible sub-architectures. Then we progressively eliminate redundant components while retaining helpful ones, resulting in a final optimized model architecture that is both efficient and effective. The detailed workflow proceeds in three stages: 1) Supernet training. We first construct an over-parameterized supernet representing the entire search space, including LSTM units, convolutional and fully connected layers, pooling operations, and activation func-tions. The supernet is trained end-to-end for the detection task, so that all components inherit useful parameters. 2) Subnet evaluation. E. Data Recovery 

Although our proposed model allows for real-time detec-tion and significantly reduces latency, some files may still JOURNAL OF L ATEX CLASS FILES, VOL. 14, NO. 8, AUGUST 2021 6

inevitably get encrypted by ransomware before the malicious activity is flagged. To mitigate this impact, we extend our framework with a dynamic backup and recovery framework that runs in parallel with the monitoring process. This module complements detection by providing a rapid rollback capa-bility, thereby completing the end-to-end defense cycle. The entire framework consists of three major modules. 

a) Lightweight snapshotting. 

The first module adopts a rolling snapshot approach to keep track of file changes. During program execution, we run a shell script using rsync command to save lightweight copies of the modified files inside the focused directory. Notice that instead of maintaining full backups of entire directories, this script executes at one-minute intervals and captures only those files that have been accessed or modified during the latest window. 

b) Integration with detection. 

The snapshotting process runs in parallel with the dynamic analysis module (Section III-C). In each time window, a temporary backup is created using lightweight snapshotting for files that were accessed. If the LSTM detector concludes that the program behavior is benign, the snapshot is discarded to conserve resources. Otherwise, as the detector raises an alert indicating ransomware activity, the program is terminated and the snapshot is used to roll back any affected files. This parallel design keeps backups continuously available, enabling rapid recovery with minimal latency. 

c) File event logging. 

To make the framework more practical for real-world use, we incorporate an inotify -based logger that continuously records file system events (e.g., open , modify , create , delete )within the monitored directories. This logging helps confirm that snapshots and recoveries happen as intended, and it also keeps a detailed record of file activity. Such records allow administrators to verify what happened to each file and restore the sequence of actions if any incident happened. In summary, the proposed data recovery strategy comple-ments our detection pipeline, it minimizes storage overhead while ensuring effective file protection. 

F. Explainable Machine Learning 

Another major limitation of existing methods is the lack of interpretability. Due to the black-box nature of ML models, no additional information beyond the detection result is available. In such cases, users have no guidance on how to respond to misclassifications. Moreover, a binary label alone may be in-sufficient for follow-up tasks such as ransomware localization. To address this limitation, we integrate explainable machine learning into both static and dynamic analysis. For static analysis, we adopt SHAP [22] to enhance in-terpretability. SHAP originates from cooperative game theory, where the goal is to quantify the marginal contribution of each player to the overall outcome. Conse-quently, it struggles to differentiate between benign encryption programs and ransomware, causing the highest number of false alarms, resulting in low precision. This combination captures both coarse-grained runtime patterns and fine-grained instruction-level traces to ensure robust precision and recall. This improvement is especially significant when detecting Crypto and Scareware, where the proposed approach achieves over 93% accuracy compared to 85.2% and 72.1% for DRL, respectively. These results confirm that the proposed method generalizes well across diverse ransomware behaviors and addresses the weaknesses of existing techniques. C. Case study: Adversarial Robustness 

Robustness is central to ransomware detection, as real attacks routinely use obfuscations to evade conventional signature-based detection. To evaluate the robustness of se-lected methods, we generate adversarial variants that perturb with the following five strategies:  

> •

NOP: insert short runs of no-ops or benign ops to pad code without changing control flow.  

> •

Opcode substitution: swap instructions with semantics-equivalent forms to alter tokens and n-grams.  

> •

Sleep: inject brief sleeps between phases to create idle windows in the trace.  

> •

API reordering: permute independent API calls within a stage to disrupt sequence patterns.  

> •

Packing: wrap binaries with a simple packer for polymor-phism. Table III compares the clean and adversarial accuracy for all four methods. As we can see, DRL shows the steepest decline under obfuscation, falling from 78.4% to 59.9% on average and dropping below 60% on Scareware, which is no better than a random guess. Rwarmor exhibits a similar pattern, with adversarial accuracy near 59% on Scareware, while Ratafia holds up better overall but still slips to mid 60% on Locker when sleeps and API reorderings disturb its HPC signatures. These outcomes align with their underlying properties: DRL focuses on static signatures which can be easily perturbed; Rwarmor relies on sequence regularities which are fragile against reordering; and Ratafia lacks ETB traces to anchor timing shifts. In contrast, our approach maintains 88.3% on adversarial samples (-4.1% from clean), with an average 22.6% improvement over baselines, and achieved the largest gap on Scareware detection(34.4%). Figure 8 breaks down performance by adversarial strategies. Among the baselines, DRL is hit hardest by opcode substitu-tion and packing, where tokens and structure-level signatures are muted; in both cases its accuracy falls below 50%. Ratafia degrades most with sleep/idle frames insertion, as idle gaps blur the timing patterns in HPC traces, leading to accuracy down to mid–60%. Rwarmor drops significantly under API reordering, where the control-flow features become messy and less informative, resulting in an accuracy around 59%. In contrast, our approach remains steady across all five strategies, typically between 86% and 90%. We attribute this advantage to two design choices. First, we adopt an adversarial training step for the static analysis, enhancing its robustness against such types of obfuscation during the training phase. Second, ETB-based tracing complements HPC-based tracing by providing fine-grained context. In this case, even obfuscation perturbs aggregate HPC statistics (e.g., idle windows or delayed acti-vation), the underlying malicious activity with characteristic ETB patterns can still be captured in subsequent windows.

V. C ONCLUSION 

Ransomware has become a significant threat to cybersecu-rity in recent years. Existing ransomware detection methods suffer from four major limitations: vulnerability to obfusca-tion, detection latency, and low generalizability. To address these challenges, this paper presents a dynamic hardware-assisted ransomware detection framework that leverages adap-tive runtime monitoring to balance detection accuracy and efficiency. Experimental results demonstrate that the pro-posed approach achieves consistent improvements in detection accuracy and reduced detection latency compared to prior works. Additionally, by incorporating adversarial training, we strengthen static analysis against obfuscation techniques, and the utilization of one-shot Neural Architecture Search (NAS) automates the optimization of model architectures, enabling the framework’s flexibility across ransomware variants.
