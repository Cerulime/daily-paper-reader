## 摘要
软件智能体在执行工具和与外部系统交互时，正越来越多地依赖开源组件。因此，这些依赖中的安全缺陷可能影响的不仅仅是其所在的软件进程：其后果可以通过工具输出、智能体状态以及随后暴露给模型的信息进行传递。确定此类后果是否在特定执行中实际发生，以及其影响在智能体系统内部止于何处，仍然具有挑战性。我们研究了已知 OSS 漏洞作为智能体工作流的一部分被触发时的行为。我们的研究揭示了与安全相关的后果在运行时各层中出现和传播时反复出现的模式。基于这些观察，我们利用漏洞感知的语义信息、易受攻击软件与修正后软件的差分执行，以及跨多个层的运行时溯源，来判断某个漏洞是否产生可观察的安全效应，并识别该效应仍然显现的最远层级。我们的评估表明，该方法能够在多样化的漏洞场景集合中准确区分已实现的漏洞效应，并确定其显现边界。我们还将该分析应用于一个真实世界智能体框架中有文档记录的工作流，并发现了多个源自其 OSS 依赖中已知漏洞的安全效应。这些结果凸显了从执行级后果而非仅从漏洞存在与否的角度来推理易受攻击依赖的重要性。

## Abstract
Software agents increasingly depend on open-source components when executing tools and interacting with external systems. Security flaws in these dependencies may therefore influence more than the software process in which they occur: their consequences can be carried through tool outputs, agent state, and information subsequently exposed to the model. Determining whether such a consequence is actually realized in a particular execution, and where its influence stops within the agent system, remains challenging.   We investigate how known OSS vulnerabilities behave when exercised as part of agent workflows. Our study reveals recurring patterns in the way security-relevant consequences emerge and propagate across runtime layers. Building on these observations, we use vulnerability-aware semantic information, differential executions of vulnerable and corrected software, and runtime provenance spanning multiple layers to determine whether a vulnerability produces an observable security effect and to identify the furthest layer at which that effect remains manifested.   Our evaluation shows that this approach can accurately distinguish realized vulnerability effects and determine their manifestation boundaries across a diverse collection of vulnerability scenarios. We additionally apply the analysis to documented workflows in a real-world agent framework and uncover multiple security effects originating from known vulnerabilities in its OSS dependencies. These results highlight the importance of reasoning about vulnerable dependencies in terms of their execution-level consequences rather than vulnerability presence alone.
