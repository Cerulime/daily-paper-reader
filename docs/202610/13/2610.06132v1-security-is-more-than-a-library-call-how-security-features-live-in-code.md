## 摘要
实现安全功能——即保护敏感数据或防止攻击者恶意行为的功能——对于确保软件系统的安全性和完整性非常重要。正确实现访问控制、密码学或其他安全功能颇具挑战，因为它们需要大量的领域专业知识、精心的设计以及定制化实现，才能将其集成到软件系统中。以往研究已通过调查、访谈和实验，深入研究了安全意识、认知、实践和专业知识。尽管这些研究表明，安全功能的实现通常由安全库和框架提供支持，但也表明开发者很少是安全专家，并且在使用这些库和框架时会犯错，从而将漏洞引入软件。尽管已有关于安全实践和开发者行为的广泛知识，我们仍缺乏对安全功能在完整软件系统的代码层面究竟如何体现的全面理解。为弥补这一空白，我们对 9 个流行且大型的开源 Java 系统中的安全功能进行了挖掘研究。我们人工检查了 19,121 个文件中的 2,127,761 行代码，识别并标注了 183,395 行代码，这些代码实现了 561 个安全功能，对应我们分类体系中的 54 种安全功能。我们分析了所识别安全功能的特征，例如其规模、分散性、纠缠性、常见实现模式，以及对内部和外部功能的使用。我们的发现表明，安全功能远不止是对外部库的简单调用。诸如访问控制之类的安全功能，其规模可能变得很大，散布在整个代码库中，并且经常相互纠缠。外部安全库虽被普遍使用，但需要大量代码进行集成。

## Abstract
Implementing security features---functionalities that protect sensitive data or prevent malicious actions by attackers---is important for ensuring the security and integrity of software systems. Correctly implementing access control, cryptography, or other security features is challenging as they require substantial domain expertise, careful design, and custom implementation to integrate them within the software system.   Previous work has thoroughly studied security awareness, perception, practices, and expertise via surveys, interviews, and experiments. While they have shown that the implementation of security features are often supported by security libraries and frameworks, they have also shown that developers rarely are security experts, and make mistakes that introduce vulnerabilities into software when using them. Despite this extensive knowledge of security practices and developer behavior, we still lack a comprehensive understanding of how security features actually manifest at the code level across full software systems.   We close this gap by conducting a mining study of security features in 9 popular and large open-source Java systems. We manually inspected 2,127,761 lines of code across 19,121 files, identifying and annotating 183,395 lines implementing 561 security features corresponding to 54 security features in our taxonomy. We analyzed the characteristics of the identified security features, such as their size, scattering, tangling, common implementation patterns, and the use of internal and external functionalities. Our findings show that security features are far more than mere calls to external libraries. Security features, such as access control, can grow large in size, scatter across the whole codebase, and frequently tangle with each other. External security libraries are commonly used, but they require substantial amounts of code for integration.
