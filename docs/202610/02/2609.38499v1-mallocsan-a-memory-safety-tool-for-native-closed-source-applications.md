## 摘要
内存破坏错误仍然是 C 和 C++ 软件中高影响漏洞的主要原因之一。然而，确定性检测仍难以部署：基于编译器的 sanitizer 需要源代码和对构建流程的控制，硬件辅助方案依赖特定平台，而动态二进制翻译可能带来数量级的性能下降。本文提出 MallocSan，一种面向原生、可能为闭源的 x86-64 Linux 应用的堆 sanitizer，无需源代码访问、重新编译或专用硬件。MallocSan 通过 LD_PRELOAD 介入内存分配，并在每个受保护指针未使用的高位中嵌入对象标识符。解引用由此产生的非规范指针会在出错指令处触发故障，MallocSan 在运行时解码并修补该指令，使后续执行完全在用户态进行按对象边界检查。无法修补的位置回退到处理程序内仿真或单步执行，而可选的基于剖析的 pass 会在离线阶段重写频繁执行的残留位置。MallocSan 还将基于身份的检查扩展到向量 gather/scatter 指令，并支持策略作用域的覆盖。在七个 SPEC CPU 2017 基准测试中，MallocSan 在五个上优于 Valgrind Memcheck，相对于原生执行的几何平均执行时间倍数为 4.82 倍，而 Memcheck 为 18.55 倍，同时在两个评估的多线程工作负载 644.nab_s 和 pigz 上保持了显著的并行扩展性。在范围内的 Juliet 测试中，MallocSan 检测出所有植入的违规，并且在正常执行上没有误报。它还能检测真实应用中的堆缓冲区错误，包括 LibTIFF 的 tiffcrop 工具中已知的一字节越界读取。

## Abstract
Memory-corruption errors remain a leading cause of high-impact vulnerabilities in C and C++ software. Deterministic detection, however, remains difficult to deploy: compiler-based sanitizers require source code and control of the build pipeline, hardware-assisted schemes depend on specific platforms, and dynamic binary translation can impose order-of-magnitude slowdowns. This paper presents MallocSan, a heap sanitizer for native, potentially closed-source x86-64 Linux applications that requires no source access, recompilation, or specialized hardware. MallocSan interposes on memory allocation through LD_PRELOAD and embeds an object identifier in the unused high bits of each protected pointer. Dereferencing the resulting noncanonical pointer faults at the offending instruction, which MallocSan decodes and patches at runtime so that subsequent executions perform per-object bounds checks entirely in userspace. Sites that cannot be patched fall back to in-handler emulation or single-stepping, while an optional profile-guided pass rewrites frequently executed residual sites offline. MallocSan also extends identity-based checking to vector gather/scatter instructions and supports policy-scoped coverage. Across seven SPEC CPU 2017 benchmarks, MallocSan outperforms Valgrind Memcheck on five, with a geometric-mean execution-time factor of 4.82x relative to native execution, compared with 18.55x for Memcheck, while preserving substantial parallel scaling on both evaluated multithreaded workloads: 644.nab_s and pigz. On the in-scope Juliet tests, MallocSan detects all seeded violations with no false reports on the good executions. It also detects heap-buffer errors in real-world applications, including a known one-byte overread in LibTIFF's tiffcrop utility.

## 1. 核心问题与整体含义
- **背景**：C/C++ 仍广泛用于操作系统、浏览器、数据库、嵌入式与高性能库；内存破坏（空间越界、UAF、double-free 等）长期是高影响漏洞主要来源，OS/浏览器厂商称近年 65–70% 漏洞与内存错误相关。
- **现有方案困境**：
  - 编译器 sanitizer（如 ASan）需要源码与构建流程控制；
  - 硬件辅助方案依赖特定 ISA/平台/ABI；
  - 动态二进制翻译（如 Valgrind Memcheck）可处理闭源二进制，但开销常达数量级；
  - 分配器加固（DieHard、FreeGuard）多为概率性空间保护，CRCount 等强指针跟踪又需编译器插桩。
- **核心缺口**：能否在 commodity x86-64 Linux 上，对闭源原生二进制实现**无需源码、无需重编译、无需专用硬件**的**确定性按对象空间检查**？
- **整体含义**：MallocSan 试图填补“可部署性”与“确定性对象身份检查”之间的空白，面向堆分配对象提供策略作用域内的 per-object 边界检查，并可选报告 stale-pointer/UAF。

## 2. 方法论
### 核心思想
- 通过 `LD_PRELOAD` 介入 `malloc` 族，对选定堆分配返回**带对象标识符（OID）的指针**。
- OID 编码在 x86-64 指针未使用高位：bits 48–62，bit 63 保持 0；四层分页下最多 32,767 个 OID。
- 带标签指针成为**非规范地址（noncanonical）**，直接解引用会在出错指令处触发硬件故障；MallocSan 借此精确截获访问。
- OID 索引**对象表**，记录分配基址、大小、分配点；边界检查即判断有效地址是否落在对应对象范围内。

### 关键流程
1. **分配拦截与标记**：`malloc/calloc/realloc/memalign/posix_memalign` 等被包装；受保护对象获得 OID，并记录对象表；未保护分配走原路径。
2. **首次故障处理**：`SIGSEGV/SIGBUS` 处理器只做最小记录，转 trampoline；因 Capstone 非 async-signal-safe，解码在信号处理外进行。
3. **指令分析**：Capstone 解码故障指令，记录内存操作数、base/index、scale、displacement、访问宽度、寄存器读写集、REP/VSIB 等，缓存到指令表。
4. **运行时二进制修补**：用 libpatch 尝试安装 `JUMP`（至少 5 字节）重定向；不足 5 字节时用 NOP-bridge、instruction punning 等；被搬移指令放入 OLX 缓冲区执行。
5. **稳态路径**：pre-handler 去掉 OID、计算有效地址、按对象表校验；原指令在无标签地址上执行；必要时 post-handler 恢复 OID，防止后续解引用逃逸检查。
6. **回退路径**：
   - 处理程序内仿真：简单 MOV 等直接在 SIGSEGV handler 中完成访问并跳过原指令；
   - TRAP 修补：用 `INT3` 触发信号处理；
   - 单步执行：最后手段，设置 trap flag 执行一次再恢复标签。
7. **特殊指令支持**：
   - REP 字符串指令：固定计数如 `rep movs` 在执行前验证完整 footprint；数据依赖如 `repne scasb` 仅先验首字节，执行后由 post-handler 根据指针变化恢复实际区间并验证。
   - VSIB/AVX：支持 AVX2 gather、AVX-512 gather/scatter；按 active lane 逐 lane 检查 `base + vreg[i]*scale + disp`，并处理 mask。
8. **其他机制**：
