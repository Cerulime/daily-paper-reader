## 摘要
Granite是一种模块化方法，用于针对ISA契约验证RTL处理器的功能正确性和非泄漏性。我们证明了一个流水线RISC设计——具有推测、精确中断和I/O——的逐周期时序仅由ISA泄漏契约中规定的可观测值决定。对于使可观测值独立于秘密的程序（即遵循密码学常数时间规范），该结果排除了通过已知和未知时序侧信道的信息泄漏。Granite的规范仅约束功能正确性和信息流依赖关系，而不限制指令执行的周期数、中断处理的指令位置，或乘法器、存储器等子模块的确切延迟。Granite的核心技术是通过确定性进行泄漏感知的精化，它将正确性和机密性作为相对于一族循环级确定性规范机器的迹等价性来共同确立。秘密无关的非确定性通过对仅作用于公共数据的不可信确定性函数进行存在性参数化规范来处理。子模块根据自身的泄漏感知规范进行证明，并且这些证明组合成整个设计的保证——因此该保证适用于一系列安全实现。我们相信，这项工作首次实现了指令集级泄漏契约与微架构特定的逐周期执行（具有线级观测）之间的模块化和基础性连接。我们的证明与经过认证的静态分析组合，该分析识别密码学常数时间代码，从而得出关于硬件和软件密码学实现的逐周期机密性的单一Rocq定理——从可信计算基中消除了每一个中间规范，包括ISA契约本身。

## Abstract
Granite is a methodology for modular verification of both functional correctness and nonleakage of RTL processors against ISA contracts. We prove that the cycle-by-cycle timing of a pipelined RISC design--with speculation, precise interrupts, and I/O--is determined solely by observables specified in an ISA leakage contract. For programs that keep observables independent of secrets (i.e., following the cryptographic-constant-time discipline), this result rules out information leakage through known and unknown timing side channels.   Granite's specifications only constrain functional correctness and information-flow dependencies: not how many cycles an instruction takes, at which instruction an interrupt is handled, or the exact latencies of submodules such as multipliers and memory. Granite's central technique is leakage-aware refinement via determinism, which establishes correctness and confidentiality together as trace equivalence with respect to a family of cycle-level, deterministic spec machines. Secret-independent nondeterminism is handled by existentially parameterizing specs with untrusted, deterministic functions acting only on public data. Submodules are proved against their own leakage-aware specs, and these proofs compose into the whole-design guarantee--which therefore holds over a space of secure implementations.   We believe this work is the first to achieve modular and foundational connection between instruction-set-level leakage contracts and microarchitecture-specific cycle-by-cycle execution with wire-level observations. Our proofs compose with a certified static analysis that recognizes cryptographic-constant-time code to derive a single Rocq theorem about the cycle-by-cycle confidentiality of a hardware-and-software cryptographic implementation--eliminating every intermediate specification, including the ISA contract itself, from the trusted computing base.

## 1. 核心问题与整体含义

- **背景**：微架构时序侧信道攻击（如 Spectre、Meltdown）暴露了传统“常数时间”假设的漏洞。密码学软件通常依赖常数时间编程来防止密钥等秘密通过执行时间泄漏，但真实处理器的推测执行、分支预测、缓存等机制可能引入新的时序依赖，使原有契约失效。
- **核心问题**：如何在 RTL（寄存器传输级）处理器实现与指令集架构（ISA）泄漏契约之间建立**模块化、可审计、可组合**的基础性验证方法，从而同时保证功能正确性和非泄漏性？现有工作存在四方面缺憾：
  1. 可审计性不足：许多方法假设功能正确性，将 RTL 保留在可信计算基（TCB）中；
  2. 难以与软件证明组合，形成端到端硬件-软件保证；
  3. 表达力不足：无法处理异步中断、输入、未指定行为等真实硬件非确定性；
  4. 缺乏模块化：难以应对状态爆炸，难以支持早期设计推理。
- **论文含义**：Granite 填补了这一空白，首次实现指令集级泄漏契约与微架构级逐周期执行（含线级观测）之间的**模块化、基础性（foundational）连接**，并可通过组合软件静态分析，消除包括 ISA 契约在内的所有中间规范对 TCB 的依赖。

## 2. 方法论

### 2.1 核心思想
- **泄漏感知精化（Leakage-Aware Refinement via Determinism）**：
  - 将功能正确性与非泄漏性统一为**迹等价（trace equivalence）**关系：实现机的执行迹与一族**确定性、周期级规范机**的迹等价。
  - 通过存在性参数化（existential parameterization）处理非确定性，参数是**不可信的确定性函数**，分为两类：
    - **秘密无关驱动者（driver）**：只接收公共数据（公共输入、程序、已解除分类的泄漏），负责决定时序、中断边界等秘密无关选择；
    - **不受约束的见证者（witness）**：可依赖秘密，用于建模未指定行为（如 valid 为低时数据线的值）。
  - 还引入**泄漏变换器（leakage transformer）**：仅由公共输入与 ISA 泄漏迹决定对抗者观测（如周期级时序），其存在性即安全性保证，蕴含经典无干扰性质。

### 2.2 关键技术细节
- **将 ISA 契约降为周期级机器（Cycle-ISA）**：
  - 将一步一条指令的 ISA 机降为多阶段周期级状态机：`StepLeak`（发出下一条指令的泄漏事件）、`StepInstr`（执行指令、发出 MMIO 请求时可阻塞）、`StepWaitMMIOResp`（等待 MMIO 响应）、`StepInterrupt`（决定是否在指令边界陷入中断处理）。
  - 通过统一的 wire-level ready/valid/data 接口建模与外部世界的交互，解决规范与实现步长不匹配的问题。
- **统一证明义务**：定义 2 将功能正确性和非泄漏性合并为单一迹等价要求：存在 LT、Driver、Witness 三个不可信参数，使实现迹等于规范机 Spec 的迹（公共输出通过 LT 产生，功能输出直接与 ISA 机一致）。
- **证明策略（§4.5）**：
  1. 实例化存在参数：Witness 直接采用实现的副本；Driver 和 LT 用“影子核心”（仅含公共数据的实现副本）实例化；
  2. 用冲刷不变量（flushing invariant）建立实现状态与 ISA 机状态的关系；
  3. 建立实现与影子机之间的公共状态等价关系。
- **模块化（§5）**：
  - **水平模块化**：每个子模块（FIFO、乘法器、分支预测器、存储器）用 freer monad 编码、以“one-method-at-a-time”语义交互；子模块具有独立的泄漏感知规范（规范状态包含请求队列和方法调用历史，参数化 driver/witness），并证明**替换原理**（子模块精化可组合进整体证明）。
  - **垂直模块化**：分层证明链——常数时间程序 → 静态分析 → 软件风格 ISA 契约 → 硬件风格 ISA 契约 → 抽象硬件（Rocq）→ 具体硬件（Rocq）→ Quartz → SystemVerilog，各层间保持泄漏变换器链式组合。
- **实例化示例**：零跳乘法器（Zero-Skip Multiplier）——其响应时间是否依赖操作数为零是公共泄漏，但不得依赖其他数据位；规格用 `resp_ready` 和 `is_full` 作为公共泄漏迹的 driver 函数，用 `default_peek` 作为 witness 建模无效输出值。

## 3. 实验设计

- **验证对象**：一个四级流水线 RISC-V 处理器核心，支持分支预测（BTB/epoch）、精确异常、异步中断、CSR 指令、MMIO、存储器模型；另有验证规范通用性的**三级多周期处理器**设计。
- **Benchmark / 场景**：
  - 用标准 RISC-V 工具链编译的 **Salsa20 常数时间 C 程序**，数据存储器（密钥、消息、nonce）视为秘密，程序视为公共；静态分析判断程序是否为常数时间。
  - 专门的**静态分析器**（符号执行，状态中含 `Public`/`Secret` 标记），用于判定二进制程序是否满足 ISA 常数时间性质。
- **对比方法**：
  - 模型检测类：LeaVe、UPEC/UPEC-DIT、Contract Shadow Logic（它们假设功能正确性、不处理中断/I/O 非确定性）；
  - 精化类：Kami、Fjfj、Lightbulb（只证明功能正确性，不处理泄漏）；
  - 安全精化类：Knox、Parfait、Pantomime（更局限或需要电路级规范）；
  - 抽象模型类：Pensieve、Guarnieri 等（不验证 RTL 实现）；
  - 信息流类型系统：SecVerilog、HyperFlow、SpecVerilog（保守、可表达性受限）。
- **结论性对比**：论文以定性对比为主，强调 Granite 是首个同时满足四大要求（可审计、可组合、可表达非确定性、模块化）的方法。

## 6. 主要结论与发现

- **核心结论**：通过“泄漏感知精化 + 确定性规范化 + 存在性参数化”的组合，可以在证明助手（Rocq）中**模块化地**证明 RTL 处理器同时满足功能正确性与常数时间泄漏契约；逐周期时序仅由 ISA 泄漏契约规定的可观测值决定，从而排除已知和未知的时序侧信道。
- **子模块组合性**：子模块按自己的泄漏感知规范独立证明后可安全替换进上层设计，整体保证对一族安全实现均成立。
- **端到端**：与常数时间静态分析组合后，得到单一 Rocq 定理：Salsa20 程序在对应 RTL 处理器上执行时，逐周期观测与秘密无关；且 ISA 契约等中间规范可从 TCB 中消除。
- **发现契约缺陷**：验证过程中发现，对 `mie`、`mtvec` 等中断配置 CSR 的写入本身也必须被泄漏（否则中断目标地址会影响可观测量），此前 ISA 级软件验证并未考虑此点，说明向下验证 RTL 能暴露规范遗漏。

## 7. 优点

- **方法创新**：将功能正确性与非泄漏性统一为单一迹等价证明，避免传统“功能验证 + 无干扰验证”分开导致的证明困难；通过存在性参数化优雅处理秘密无关非确定性，既允许设计自由度又不引入泄漏。
- **模块化设计**：水平（子模块替换原理）+ 垂直（规范分层、泄漏变换器链式组合）双重模块化，显著降低证明复杂度，支持早期设计推理和防御机制评估。
- **端到端与 TCB 收缩**：从二进制软件到 RTL 的完整证明链，中间规范（包括 ISA 契约）均可移出 TCB；使用 Quartz 生成可综合 SystemVerilog，并验证了与 Gallina 实现的等价性。
- **实用验证**：发现真实规范漏洞（CSR 写入泄漏），展示方法对硬件细节敏感性的价值。
- **表达力**：支持异步中断、I/O、非确定性输入、未指定行为（低有效数据线）等真实硬件特征，优于模型检测类方法。

## 8. 不足与局限

- **技术限制**：
  - 依赖 HDL 片段的确定性，不支持多时钟域组合行为；
  - 仅考虑单硬件线程、只读指令存储器；扩展多线程/自修改代码会面临功能正确性挑战；
  - 只覆盖周期级时序侧信道，不考虑周期内时序、功耗、电磁等物理侧信道；
  - 静态分析无法处理无限循环（除特定自旋模式）和中断/异常处理程序。
- **实验覆盖**：
  - 指令集为 RISC-V 代表性子集，未覆盖完整 ISA；
  - 未与编译器验证（如提到受其启发的 CompCert/RISCV-COQ 相关工作）实际连接；
  - 仅对单一程序（Salsa20）做端到端演示，样本有限。
- **可信计算基（TCB）**：
  - 仍包括 Cycle-ISA 规范、观测函数、存储器模型、外部世界模型、Rocq 内核以及 Quartz 到 SystemVerilog 的 pretty-printer（约 200 行）；
  - SystemVerilog 语义本身未被形式化，故语法映射在 TCB 中。
- **其他偏差风险**：
  - 规格的可审计性依赖 Cycle-ISA 机器的简洁性，但抽象存储器规范被“信任”而非验证；
  - 安全性保证是相对泄漏契约的，若契约本身缺失某些泄漏（如论文中发现的 CSR 案例），可能仍有未知漏洞；本方法通过证明过程可发现此类问题，但无法保证绝对完备。
