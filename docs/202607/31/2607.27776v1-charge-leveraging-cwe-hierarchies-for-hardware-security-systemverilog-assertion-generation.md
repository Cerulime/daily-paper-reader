## 摘要
本文介绍了CHARGE，一个使用CWE和大语言模型（LLM）为未验证RTL模块自动生成安全属性的框架。其特点是利用CWE条目的层次结构进行推理，以提高在未验证RTL模块中识别安全关键资产的准确性。因此，该方法可以从识别出的资产和CWE语义中推断预期的安全行为并生成属性，无需可信的设计规范，减少了人工工程工作量。我们使用OpenAI的GPT-4.1在Hack@DAC18、19和21开源SoC设计上评估了该框架。CHARGE在这些设计中检测到42个已知错误中的27个。对于Hack@DAC21 OpenPiton SoC，89%的生成SVA在Cadence JasperGold FPV中运行，92.2%非空泛。我们与为这些设计手动编写的开源属性集进行比较，发现CHARGE为三个手动编写属性有误的错误正确编写了属性。此外，CHARGE生成的属性在Hack@DAC21 OpenPiton SoC中发现了一个此前未被发现的新错误。

## Abstract
This paper presents CHARGE, an automated framework for generating security properties for unverified RTL modules using CWEs and large language models (LLMs). The hallmark is a reasoning process that leverages the hierarchical nature of CWE entries to improve accuracy when identifying security-critical assets in unverified RTL modules. As a result, the approach can infer expected security behaviors and generate properties from identified assets and CWE semantics, avoiding the need for trusted design specifications and reducing manual engineering effort. We evaluate the framework on the Hack@DAC18, 19, and 21 open source SoC designs using OpenAI's GPT-4.1. CHARGE detects 27 of 42 known bugs in these designs. For Hack@DAC21 OpenPiton SoC, 89% of the generated SVAs run in Cadence JasperGold FPV, and 92.2% are non-vacuous. We compare to an open-source, manually written set of properties for these designs and find that CHARGE correctly writes properties for three bugs in which the manually written properties were incorrect. In addition, CHARGE-generated properties identify a new bug in the Hack@DAC21 OpenPiton SoC that was not previously identified.

- **现有挑战**：
  - 大型语言模型（LLM）生成断言需要非常详细的指导，否则难以产生有意义且准确的断言。
  - 安全验证场景下，不存在像功能验证那样的设计规范；未验证的（可能含漏洞的）RTL 代码不能作为“干净”的规范输入给 LLM。

- **核心创新**：利用 CWE 条目的**层次结构**，引导 LLM 从未验证 RTL 中识别安全关键资产，进而推断预期安全行为并生成 SVA，从而避免对可信设计规范和人工工程的高度依赖。

### 2. 论文提出的方法论

- **核心思想**：将 CWE 数据库视为“安全规范”的替代来源，通过结构化分解和层次化推理，使 LLM 能够在无规范、可能含 bug 的 RTL 上生成安全属性。
- **CWE 结构化表示**：
  - 将每个 CWE 的安全策略抽象为三元组：`<target, action, condition>`（目标资产、操作、条件）。
  - 例如 CWE-226（资源重用前未移除敏感信息）映射为 `<敏感资源, 清零, 重用/释放条件>`。
  - 将 CWE 分类为“可完全转换”（如 CWE-226）和“部分可转换”（如 CWE-1245 不当 FSM），后者利用 LLM 推理补充三元组之外的行为。
- **CWE 层次树构建**：基于 CWE-1000 Research Concepts 视图，仅保留父子关系，从每个可映射 CWE 向上追踪到 Pillar，构建树结构。每个节点存储 ID、名称、描述、映射状态、子节点以及资产识别子字段（target/action/condition）。
- **三步框架（CHARGE）**：
  1. **Step 1：LLM 支持的资产识别**。给定目标 CWE，从层次树中提取从根到目标的路径，将路径和树 JSON 加入提示，LLM 沿路径逐层识别资产；输出分为 primary targets、primary conditions、relevant assets。若无法识别任何资产，则报告“CWE 不适用”。
  2. **Step 2：LLM 支持的行为挖掘**。以 Step 1 的资产、目标 CWE 描述、手工设计的“策略问题”（如“在什么条件下资产应被清零？”）以及 RTL 为输入，输出自然语言形式的预期安全行为列表。
  3. **Step 3：LLM 支持的 SVA 生成**。利用行为列表、资产、CWE 语义和预定义的 SVA 模板，生成可用的 SystemVerilog Assertion（含 cover property），并约束 LLM 仅使用真实 RTL 信号。
- **自动化流程**：所有步骤的中间输出自动传递给下一步，最终生成 .sv 文件，可直接用于 JasperGold 等工具。

- CHARGE 在 42 个已知 bug 中检测出 **27 个**（64%），其中资产识别成功 34 个，行为产出成功 29 个。
- 在 Hack@DAC 2021 上，89% 的生成 SVA 可在 JasperGold 中直接运行，92.2% 为非空泛（可达）。
- **发现人工属性错误**：三处手工属性写错（重叠/非重叠蕴含算子使用错误、地址范围错误），CHARGE 生成的属性正确，已提交 PR 并被接受。
- **发现新漏洞**：在 aes0_wrapper 模块中生成一条断言，揭示密码学密钥在复位后未被清除，该 bug 不在 Hack@DAC 2021 的已知 bug 列表中。
- **故障模式分析**：
  - 未检测出的 15 个 bug 集中在 7 个 CWE（CWE-1220、1245、1189、1262、1281、1244、1310），且这些 CWE 共享 4 个公共祖先（CWE-284、710、664、691），说明 CWE 选择对 LLM 性能影响显著。

  - 漏检原因分为两类：**资产/行为缺失**（CWE 不匹配、RTL 中证据不足、模块过大、LLM 训练数据限制）和**被 buggy RTL 误导**（LLM 将错误行为当作预期行为）。
- **消融实验结论**：Hierarchy + 3-Tuple 配置在三种模型上均显著优于无层次/无三元组配置（如 GPT-4.1 资产识别准确率：73.2% vs 52.4% vs 45.1%），说明 CHARGE 的增益来自结构化推理而非特定模型。

### 7. 优点

- **无需设计规范**：直接从未验证 RTL 生成安全属性，摆脱了对可信规范或人工指导的依赖。
- **利用 CWE 层次结构**：通过从抽象到具体的层次推理，缓解了 buggy RTL 带来的误导，提升了资产识别能力。
- **完全自动化**：三步流程自动衔接，输出可直接用于标准验证工具；开源实现（GitHub 可用）。
- **跨模型泛化**：在 GPT-4.1、Gemini 2.5 Pro、Claude Sonnet 4.6 上均保持一致改进，说明方法不依赖单一 LLM。
- **可扩展性**：新引入的 CWE 可通过继承祖先的安全语义快速纳入，无需重写模板。
- **实用性验证**：不仅检测已知 bug，还能发现新漏洞和人工属性中的错误，展示了实际工程价值。

### 8. 不足与局限

- **检测率有限**：42 个 bug 中漏检 15 个（36%），主要受限于 CWE 类型、模块复杂度、RTL 证据缺失以及 LLM 训练数据覆盖。
- **CWE 覆盖不完整**：框架排除了物理环境、侧信道/信息流、软件/ISA 级等 CWE，且当前评估仅覆盖 20 个 CWE，无法证明所有支持 CWE 的有效性。
- **评估基准单一**：仅使用 Hack@DAC 系列，且 ground truth 本身存在错误（作者虽已修正，但说明基准并非完全可靠）。

- **资产识别计分方式**：将部分资产按 0.5 分计算是启发式的，可能掩盖某些重要资产的缺失。
