## 摘要
大语言模型能够根据自然语言描述生成C代码，但生成的程序往往存在安全漏洞和编译错误，给嵌入式和资源受限系统带来风险。本研究探讨了反馈与检索如何提升大语言模型生成C代码的可靠性。我们提出了一种分析与修复工作流，该流程结合了编译诊断、CodeQL静态分析、KLEE符号执行，并检索先前的修复模式以进行迭代改进。在涵盖嵌入式相关漏洞的5000个C编程任务上进行评估，基线模型存在显著的可靠性差距，编译失败率高达46%，安全缺陷率高达49%。我们的方法在两个指标上均有改善。对于CodeLlama 7B，安全缺陷率从49%降至19%，CodeQL错误总数从15088个降至2463个（下降83.7%）。对于DeepSeek Coder 1.3B，编译失败率从42%降至22%，安全缺陷率从35%降至15%。这些结果表明，集成轻量级分析工具可以提高大语言模型生成的代码在嵌入式开发中的安全性。

## Abstract
Large language models can generate C code from natural-language descriptions, but resulting programs often contain security vulnerabilities and compilation errors, posing risks for embedded and resource-constrained systems. This work investigates how feedback and retrieval improve reliability of LLM-generated C code. We present an analysis-and-repair workflow that combines compilation diagnostics, CodeQL static analysis, and KLEE symbolic execution with retrieval of prior repair patterns for iterative refinement.   Evaluated on 5,000 C programming tasks exercising embedded relevant vulnerabilities, baseline models show substantial reliability gaps, with compilation failure rates up to 46% and security defect rates up to 49%. Our approach improves both metrics. For CodeLlama 7B, security defect rates decrease from 49% to 19% and total CodeQL errors drop from 15,088 to 2,463 (83.7%). For DeepSeek Coder 1.3B, compilation failures are reduced from 42% to 22% and security defects from 35% to 15%. These results show that integrating lightweight analysis tools can improve the safety of LLM-generated code for embedded development.

## 二、方法论

- **核心思想**  
  将 **多源验证反馈（编译、静态分析、符号执行）** 与 **增长式修复模式库** 结合，在迭代修复中优先消除安全问题，再利用先前成功与失败的修复经验指导新一代代码生成。

- **关键技术流程（四阶段）**  
  1. **任务规范与初始生成**  
     - 输入自然语言任务描述及简短的“安全检查清单”。  
     - 模型（DeepSeek Coder 1.3B 或 CodeLlama 7B）生成初始 C 代码，无人工干预。  
  2. **编译与静态分析**  
     - 使用 GCC 编译，记录编译失败信息（如缺失头文件、类型错误）。  
     - 编译成功后，用 **CodeQL** 进行安全扫描，关注缓冲区溢出、不安全库函数（如 `gets`、`strcpy`）、未检查返回值和整数问题等。  
  3. **检索增强修复**（核心）  
     - **动态修复模式库**：随着任务处理，逐步存储每条记录（任务描述、生成代码、分析结果、综合质量评分）。  
       - 质量评分：0.0（编译失败）；0.25（仅编译通过）；0.50（编译 + 可被 KLEE 分析但有 CodeQL 发现）；0.75（编译 + CodeQL 无问题）；1.0（编译 + CodeQL 无问题 + KLEE 无错误）。  
     - **对比检索**：对当前任务，检索库中语义相似条目：  
       - 至多 3 条高质量（评分 > 0.6）作为“积极证据”；  
       - 至多 2 条不安全但可编译的条目作为“消极证据”（仅在积极条目 ≥3 时启用）。  
     - **指导生成**：将检索到的条目蒸馏为简短文本指导，而非直接插入示例代码：  
       - 积极证据提炼出最多 7 条安全实践（如检查 `scanf` 返回值、使用边界字符串操作）。  
       - 消极证据提炼出最多 3 条避免提示。  
     - **迭代修复**：对每个任务最多执行 3 次修复迭代（共生成 ≤4 个程序），每次提示包含当前代码、诊断信息和提炼出的指导。迭代结束后，按综合质量评分选择最佳版本。  
     - **库维护**：去重（余弦相似度 >0.90 保留高质版本），容量上限 500 条，超出时丢弃低分条目。  
  4. **最终符号验证**  
     - 用 **KLEE** 对最终候选进行一次性的符号执行，检测静态分析遗漏的错误（如断言失败、越界访问、空指针解引用）。  
     - 验证结果（是否可分析、是否发现违规）存入仓库并更新质量评分，用于未来检索优化。

## 六、主要结论与发现

- 提出的工具引导检索增强修复工作流能 **显著提升** LLM 生成 C 代码的构建成功率和安全性：  
  - CodeLlama 7B：安全缺陷率从 48.5% → 19.3%（降低 30 个百分点），CodeQL 错误总数削减 **83.7%**；KLEE 可分析率从 54.1% → 71.2%。

- 综合表明，将轻量级分析工具集成进生成循环是增强 LLM 生成嵌入式 C 代码安全性的可行路径。
